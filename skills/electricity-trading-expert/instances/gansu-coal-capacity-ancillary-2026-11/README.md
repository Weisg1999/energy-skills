# 甘肃煤电容量电价与辅助服务 · 2027 样板实例

> 本目录是 `skills/electricity-trading-expert/instances/` 的煤电收益叠加切片：**一省（甘肃）+ 一主体（2×660 MW 公用煤电）+ 一个规则版本（甘发改价格规〔2025〕4号可靠容量补偿、现货 V3.2、1656 号中长期规则）**。配置改 `instance.json`，换 `data/market_demo.csv` 即可复算，不改代码。
>
> 所有煤价、煤耗、辅助服务限价、调用比例、容量供需系数与考核情景均为 **D 级合成数据**，不对应任何真实电厂；规则文号仅用于演示计算链，不构成报价、投资或结算建议。

## 1. 一条命令

```bash
# 配置校验 + 来源表
python skills/electricity-trading-expert/instances/gansu-coal-capacity-ancillary-2026-11/run.py --check-config

# 合成数据全流程：四模式对比 → 电能量/容量/辅助服务 → 考核扣减 → 敏感性 → 临界值
python skills/electricity-trading-expert/instances/gansu-coal-capacity-ancillary-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/electricity-trading-expert/instances/gansu-coal-capacity-ancillary-2026-11/run.py \
  --market /path/to/market.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/electricity-trading-expert/instances/gansu-coal-capacity-ancillary-2026-11/make_demo.py
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；四个规则块都有 `grade` + `source`；申报容量在铭牌 50%–100%；模式出力不低于最低稳燃、不超过申报容量对应比例；煤耗曲线随负荷率单调不增。
2. **市场数据**：12 个月、月份升序、三段小时数之和为 24、价格落在现货出清限价内、合约电量非负。
3. **分模式出力**：每个模式给定谷/平/峰出力比例，出力 = 比例 × 铭牌，且不超过申报容量；按天数与小时数折算月电量。
4. **电能量**：三段分别按现货价结算；月度平曲线合约按 `(合约价 − 当月现货加权均价) × 合约电量` 做差价，收入 = 现货收入 + 差价。合约不分解到 96 点。
5. **容量补偿**：申报容量 × 330 元/kW·年 × 容量供需系数，按月分摊；考核按“一次扣 50%、二次扣 100%、三个月扣全年”扣减。
6. **辅助服务**：调峰按低于 50% 额定的深度调峰电量 × 单价 × 调用比例；调频与备用按申报容量比例 × 月单价 × 12，调频再乘性能系数。
7. **成本**：分负荷段煤耗（345/330/315/300 g/kWh）× 煤价 + 15 元/MWh 变动运维；固定运维 110 元/kW·年；折旧 26,400 万元/年；财务费用 14,800 万元/年。
8. **模式选择**：按年度全成本利润最大选模式，同时保留配置默认模式作对照；利润 = 电能量 + 容量 + 辅助服务 − 变动成本 − 固定运维 − 折旧 − 财务费用。
9. **敏感性与临界值**：16 个单因素/组合情景；二分搜索盈亏平衡煤价、容量系数与现货价倍数。

## 4. 合成演示的基准输出（2027 年）

| 项目 | 值 |
|---|---:|
| 铭牌 / 申报容量 | 1,320 / 1,320 MW |
| 年发电量 / 平均负荷率 | 7,310,160 MWh / 65.00% |
| 合约电量 / 对冲比例 | 4,800,000 MWh / 65.66% |
| 现货加权均价 | 318.38 元/MWh |
| 电能量 / 容量 / 辅助服务 | 223,310.55 / 37,026.00 / 8,818.92 万元 |
| 变动成本 / 固定成本 | 169,792.52 / 55,720.00 万元 |
| 年利润 / 度电利润 | 43,642.95 万元 / 59.70 元/MWh |
| 盈亏平衡煤价 | 892 元/吨（基准 700） |
| 盈亏平衡现货价倍数 | 0.45 倍 |
| 容量系数归零后利润 | 6,616.95 万元 |

| 模式 | 谷/平/峰出力 | 发电量（MWh） | 度电利润（元/MWh） | 辅助服务（万元） | 年利润（万元） |
|---|---|---:|---:|---:|---:|
| 晚峰优先 | 40% / 55% / 100% | 7,310,160 | 59.70 | 8,818.92 | 43,642.95 |
| 深调顶峰 | 35% / 50% / 100% | 6,935,280 | 59.93 | 11,208.78 | 41,561.80 |
| 基荷 | 45% / 65% / 90% | 7,497,600 | 48.79 | 6,429.06 | 36,579.13 |
| 平稳少调 | 50% / 70% / 80% | 7,497,600 | 39.22 | 4,039.20 | 29,408.58 |

**“越深越好”不成立**：深调顶峰的度电利润最高（59.93 元/MWh），但年利润比晚峰优先少 2,081.15 万元。谷段从 40% 再压到 35%，多拿的调峰补偿补不上少发电、低价电收入损失和高煤耗。模式排序由**价格形状**决定，换一组谷段价格或调峰单价就可能反转。

**容量补偿是利润的“条件支柱”**：37,026 万元容量补偿只占收入 13.76%，却相当于年利润的 84.8%。7/8/9 三个月各考核一次，全年容量电费清零，利润从 43,642.95 万元降到 6,616.95 万元；燃料 +10%、现货 −20%、晚峰 −15%、容量系数 0.70 再叠加一次考核，利润转负 −3,195.80 万元。不要把容量电费当成无风险固定收入。

## 6. 风格档与指纹

当前风格 `gansu-coal-capacity-ancillary-v1`：先算四种调度模式的年度全成本利润，按利润最大选模式；配置默认“深调顶峰”只作对照；容量补偿按申报容量与供需系数计，考核情景单列；敏感性必须包含“三个月考核清零”和组合压力。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `bfe4f5ecbf48`）。比较两个项目的差异时，先看指纹是否相同：指纹不同，差异首先归因于投决风格；指纹相同，才归因于价格、煤耗或规则。

换风格的做法：复制 `instance.json` 为 `instance.conservative.json`，改 `profile_id`、模式、调用比例与考核假设，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；不调用其他技能。
- **纳入**：四模式调度对比、现货 + 中长期差价、可靠容量补偿与考核扣减、调峰/调频/备用、分负荷段煤耗、固定运维、折旧、财务费用、16 个敏感性情景、三个临界值。
- **未纳入**：供热与热电耦合、检修优化、启停成本、实时偏差两结算、两个细则功率考核、税费与亏损结转、融资结构变化、容量补偿分摊对用户侧的影响。
- **口径**：年度全成本利润，含折旧与财务费用、不含税；不是现金流、不是 IRR/NPV，也不是对真实电厂盈利的判断。
- 真实数据放在仓库外，用 `--market/--out` 指向本地路径；仓库内只保留 D 级合成样例。
