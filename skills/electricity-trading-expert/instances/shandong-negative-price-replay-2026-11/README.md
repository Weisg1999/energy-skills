# 山东午间负价日 · 满发申报策略失败复盘

> **这是失败复盘包，不是成功路径包**：先看错误怎么发生——晴天低负荷假日按 P50 满发申报、午间触地板 −80 元/MWh 卖电即亏、没有任何触发线与预案——再用结算重放把这次错误决策的代价算到时段、把可辩护的决策边界扫出来。它不给出"正确答案"，只回答三个问题：错在哪一栏、亏多少钱、价格压到多低时换姿势才不亏。
>
> 本目录是 [`knowledge/合成案例复盘库-2026-11.md`](../../../../knowledge/合成案例复盘库-2026-11.md) **案例 1（负电价日·光伏聚合商满发申报）的可运行版**：案例文本给叙事与决策点，本包给逐时段结算重放、损失归因表与边界扫描网格。一主体（200 MW 光伏电站/聚合商）× 一规则版本（新版《山东电力市场规则（试行）》+ 鲁发改价格〔2025〕576号 + 鲁发改价格〔2026〕149号）× 一个复盘日 × 三条申报策略（A 满发申报 / B 压出力 / C 压出力 + 储能）。配置改 `instance.json`，数据换 `data/`，运行 `run.py`，不改代码。
>
> 所有电站参数、价格曲线、电量与决策参数均为 **D 级合成数据**，不对应任何真实电站或交易日；规则事实全部取自 [`knowledge/山东电力市场-2026-11.md`](../../../../knowledge/山东电力市场-2026-11.md) 中**已带级别标注**的条目。本实例包是 D 级合成样板，不构成报价、投资或法律建议。

## 3. 运行逻辑（从输入到复盘报告）

1. **配置校验**：`meta` 11 键齐全；四个规则块都有 `grade` + `source`；申报下限必须为负（否则报"山东页最高频错误"）；容量补偿标准值必须标注"待核实"；新能源全量入市必须为 true；扫描下限价必须落在出清限价 [−100, 1,500] 内；容量补偿日值 = 有效容量 × 1000 × 标准 × 供需系数 ÷ 365。
2. **数据校验**：24 时段、slot 0–23 升序、起止对齐整点；出清价落在出清限价内；申报量 ≤ 可用出力；A 未满发、或 B 曲线隐含的压出力时段与"基准情景价格 < 触发线"的时段不一致时给出警告。
3. **边际净额与门槛**：每多发 1 MWh 的边际净额 margin(p) = (1−γ)·p + γ·机制价 − 分摊（D 级假设：机制电量按申报量同比例覆盖、参考价取该时段出清价）。生产条件 margin > 0 给出解析门槛 **p\* = (分摊 − γ·机制价) ÷ (1−γ)**。
4. **结算重放三策略**：A 满发申报；B 在触发线之下的窗口时段压出力至 (1−c)·可用；C = B + 储能（20 MW / 40 MWh、效率 0.88：深谷时段用压出力电量充电——不从公共电网购电、不改变申报，晚峰高价时段放电，放电电量按现货结算、不再享机制差价——均为 D 级口径）。
5. **损失归因**：逐时段 B−A、C−A，标注满发决策最大损失时段（触地板价时段）、储能充电与放电的贡献；合计行给出错误决策的总代价。容量补偿为**分账演示项**：三条策略同额，不进入任何差额；若光伏实际不适用容量补偿，该行清零、全部差额与结论不变。
6. **边界扫描**：把扫描窗口（11:00–15:00 四个时段）价格统一设为某个下限价、其余时段不变，对 9 个下限价 × 10 个压出力比例做网格，求每个下限价 B 首次占优的比例与整体翻转带，并与解析门槛对照。
7. **三情景 + 复盘五问 + 指纹**：同一组 D-1 申报曲线在三种午间价格下重放，检验"姿态 vs 门槛"；按 [`knowledge/交易台日课与异常处置-SOP-2026-11.md`](../../../../knowledge/交易台日课与异常处置-SOP-2026-11.md) §5.1 五问生成归因；`strategy` 块规范化 JSON 的 SHA-1 前 12 位作为风格指纹写入产物。

## 4. 合成演示的基准输出（复盘日 2026-05-02，D 级合成）

| 项目 | 值 |
|---|---:|
| 电站 / 复盘日 | 200 MW 光伏 / 晴天低负荷假日（D 级合成） |
| 全天可用电量 / 午间窗口（11:00–14:00）电量 | 1,700 / 790 MWh |
| 午间价格（S1 深谷） | −60 / −80 / −80 / −30 元/MWh（12、13 点触申报下限 −80） |
| 机制覆盖比例 γ / 机制价 / 分摊 | 0.10 / 261 元/MWh / 6 元/MWh（均为 D 级占位） |
| 解析门槛价 | −22.33 元/MWh |
| 捕获价 / 时段均价 | 124.63 / 279.79 元/MWh（捕获率 44.5%） |
| 负价时段卖电收入 / 午间窗口净额 | −49,550.00 / −28,716.00 元 |

| 策略 | 当日净收入（万元） | 较满发（万元） |
|---|---:|---:|
| A 满发申报（错误基线） | 25.23 | — |
| B 负价时段压出力 90% | 27.81 | +2.58 |
| C 压出力 + 储能配合 | 29.88 | +4.65 |

**满发申报比最优策略少收 46,537.20 元**：申报决策部分（B−A）25,844.40 元，其中 12:00–13:00 与 13:00–14:00 两个触地板时段各贡献 9,342.00 元（合计约 72%）；储能配合部分（C−B）20,692.80 元（深谷充电 40 MWh、晚峰放电 35.2 MWh）。

**三情景比较（同一组 D-1 申报曲线）**：

| 情景 | A 满发 | B 压出力 | C 压出力+储能 | B−A | 最优 |
|---|---:|---:|---:|---:|---|
| S1 深谷负价日（复盘基准） | 25.23 万 | 27.81 万 | 29.88 万 | +2.58 万 | C |
| S2 温和负价日 | 28.34 万 | 28.12 万 | 30.19 万 | −0.22 万 | C |
| S3 无负价日 | 33.58 万 | 28.65 万 | 28.65 万 | −4.94 万 | A |

深谷日 C 最优；温和负价日纯压出力 B 已在高于门槛的时段亏钱（压过头），靠储能才反超；无负价日满发 A 最优，按负价预案压出力白扔约 4.94 万元。**姿态（永远满发 / 永远压出力）不可辩护，门槛 + 触发线才可辩护。**

**边界扫描**：午间预期价 < −22.33 元/MWh 时压出力占优；网格翻转位于 −30（B 占优）与 −20（A 占优）元/MWh 之间，与压出力比例无关——比例决定省多少，门槛决定压不压。触地板 −80 元/MWh 时，90% 压出力较满发单日多收约 3.69 万元。

## 6. 风格档与指纹

当前风格 `shandong-negative-price-replay-v1`：同一 D-1 决策的三种姿态对照（满发 / 压出力 / 压出力 + 储能），决策规则为"避免边际净额为负的申报"（avoid_negative_margin）；容量补偿作为策略无关的分账项。

`strategy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入产物（当前 `fd680df4046d`）。比较不同复盘日或不同电站的失败案例时，先看指纹是否相同：指纹不同，差异首先归因于申报姿态与触发线设定；指纹相同，才归因于价格曲线与电站参数。

换姿态的做法：复制 `instance.json` 为 `instance.variants.json`，改 `profile_id`、压出力比例、触发线或储能参数，用 `--instance` 指向新文件，保留旧文件与旧输出——指纹会随之改变。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库 + 本技能 `tools/contracts.py` 的捕获价函数；不调用其他技能。
- **纳入**：三策略逐时段结算重放（电能量、机制差价、辅助服务分摊、容量补偿分账演示项）、储能充放电、损失归因、三情景比较、下限价 × 压出力比例边界扫描（90 格）、解析门槛推导、复盘五问。
- **未纳入**：预测偏差与偏差考核、两个细则、辅助服务正式结算细则、实时 5 分钟出清曲线细节（小时级近似）、零售侧传导、限价草案（未生效）、压出力的调度考核口径（本包只算账，不判免考）。
- **不是**：不是报价建议或止损指令，不是对负价概率或价格的预测，不是储能配置选型工具，不构成投资或法律建议。
- 真实数据放在仓库外，用 `--price/--declare/--out` 指向本地路径；仓库内只保留 D 级合成样例。
