# 云南水电 · 区域市场组合实例

> 本目录是 `skills/electricity-trading-expert/instances/` 的省内+区域纵向切片：**一主体（两库三级 600 MW 梯级水电运营方）+ 一个规则版本（南方区域现货 2026-10-24 正式运行〔715号〕+ 云南省内中长期 1656 框架 + 198 号 VPP 办法 + 71 号草案）**。配置改 `instance.json`，数据换 `data/` 两个 CSV，运行 `run.py`，不改代码。核心问题不是"水电能不能赚钱"，而是**15 分钟区域出清价 × 96 点日内发电分布得出的捕获价，与中长期月度分解、绿证、机制差价、调节容量四条线怎么合**。
>
> 所有梯级资产、15 分钟价格形态、月度电量、合同比例、绿证比例与单价均为 **D 级合成数据**，不对应任何真实电站、流域或交易；**本实例包是 D 级合成样板，不构成报价、投资或法律建议**。规则事实全部取自[云南省级知识模块](../../../../knowledge/云南电力市场-2026-11.md)已带级别标注的内容；**南方区域正式运行（2026-10-24）不等于云南省内现货转正**，省内限价与偏差考核待核实。与[四川水电实例](../sichuan-hydro-2026-11/)刻意区分：四川走省内丰枯分期中长期，云南走区域市场统一出清 + 省内中长期 + 绿证/调节容量多线。

```bash
  --profile /path/to/profile.csv --shapes /path/to/price_shapes.csv --out /path/to/out
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：meta 十键齐全；八个规则块都有 `grade` + `source`；**待核实字段强制 null**（省内现货限价、偏差公式、常规水电机制价与比例、水电调节容量补偿——填值即 `ConfigError`）；**反向护栏**：`provincial_spot_formal`、`applies_to_hydro`、`transfer_creates_producer_revenue` 必须为 false，`double_count_guard_with_mechanism` 必须为 true；96 点数必须等于 24×60/价格间隔；梯级装机之和与 P50 电量内部一致。
2. **资源数据**：12 个月、汛期（6–10 月）/枯期口径一致；平推权重合计 1、丰枯权重合计 1；年电量偏离计划 ±20% 警告。
3. **价格形态**：丰/枯两季各 96 槽无缺口无重复、日内发电份额合计 1。
4. **合同分解**：合同电量 = 发电量 × 合同比例 × 月度权重（平推与丰枯两套）；余量 = 发电量 − 合同电量，偏差 = 合同电量 − 发电量，均按发电加权捕获价结算（96 点错位的核心）。
5. **96 点错位**：捕获价 = Σ(15 分钟价格 × 日内发电分布) ≠ 时间均价；结算用捕获价，均价对照与误差量级单独输出（`prices.csv` + `average_price_error_cny`）。
6. **多线结算**：绿证单独计线（基数 = 发电量 × 绿证比例 − 机制电量，1 张 = 1 MWh，防重扣减）；机制差价线常规水电参数 null 按 0 占位；调节容量按 0 占位；煤电 330 元/kW·年显式不适用水电。
7. **组合比较与敏感性**：`all_spot`、`contract_flat`、`contract_seasonal` 三种组合取净收入最大者为最优；15 个情景覆盖丰枯水量、区域现货 ±30%、汛期压价、合同价 ±0.02、合同比例 60%/85%、绿证 ±、机制电量 10% 与均价替代演示。

## 4. 合成演示的基准输出（2027 首年）

| 项目 | 值 |
|---|---:|
| 梯级装机 | 600 MW（300 + 200 + 100，两库三级） |
| 计划 / 实际发电量 | 2,400,000 / 2,400,000 MWh（P50 4,000 h） |
| 合同电量（75%） | 1,800,000 MWh |
| 汛期均价 / 捕获价（错位） | 159.58 / 156.88 元/MWh（−2.70） |
| 枯期均价 / 捕获价（错位） | 407.08 / 449.98 元/MWh（+42.90） |
| 年度加权均价 / 捕获价（错位） | 246.21 / 259.46 元/MWh（+13.26） |
| 均价替代的年收入误差 | 3,181.60 万元 |
| 平推偏差 / 丰枯曲线偏差 | 211,196 / 16,800 MWh（≈13 倍） |
| 绿证基数（枯 25% / 汛 35%） | 756,000 张 × 15 元 = 1,134.00 万元 |

| 组合 | 净收入（万元） | 净价（元/kWh） | 较全部现货（万元） |
|---|---:|---:|---:|
| 全部现货（不签中长期） | 63,405.60 | 0.2642 | +0.00 |
| 中长期平推 + 现货余量 | 50,021.26 | 0.2084 | −13,384.34 |
| 中长期丰枯曲线 + 现货余量 | 60,300.62 | 0.2513 | −3,104.98 |

**合成价格假设下"全部现货"最优，但结论方向比排序更重要**：平推分解的 211,196 MWh 偏差按捕获价价差回购（枯期 +42.90 元/MWh 方向）拖垮收入；丰枯曲线把偏差压到 16,800 MWh 后仅落后全部现货 3,104.98 万元。敏感性显示排序会翻转：区域现货 −30% 或汛期压价 −20% 或合同价 +0.02 时，丰枯曲线反超成为最优。15 个情景全部见 `sensitivity.csv`；机制电量 10% 情景演示绿证防重扣减（绿证收入精确减少 360 万元）；均价替代情景演示 96 点错位的代价（−3,181.60 万元）。

## 6. 风格档与指纹

当前风格 `yunnan-hydro-cascade-portfolio-v1`：75% 电量签省内中长期（平推与丰枯两套分解对比），余量与偏差按 96 点发电加权捕获价在区域现货结算；绿证单独计线并与机制电量防重扣减；机制差价与调节容量按 0 占位；组合比较以净收入最大为最优。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `3c686227d7ac`）。比较两个水电主体的差异时，先看指纹是否相同：指纹不同，差异首先归因于组合风格与合同比例；指纹相同，才归因于价格形态、来水或绿证参数。

换风格的做法：复制 `instance.json` 为 `instance.conservative.json`，改 `profile_id`、合同比例与绿证比例，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库 + 本技能 `tools/contracts.py` 的捕获价函数（96 点发电加权）；不依赖 numpy/pandas，全部输出确定性可复现（两次运行逐字节一致）。
- **纳入**：月度资源曲线、平推与丰枯两套合同分解、96 点捕获价与均价错位、绿证单独计线与机制防重扣减、机制差价与调节容量 0 占位、三种组合比较、15 个敏感性情景。
- **未纳入**：省间外送与西电东送合约、辅助服务与调节容量结算细节（待核实）、煤电容量电费分摊、零售套餐、省级偏差考核罚则（待核实）、梯级电站间的水量联系与水库调度优化（用统一日内分布近似）。
- **不是**：不是交易执行工具，不是来水预测，不是对云南区域现货价格的预测，不是投资建议。
- 真实数据放在仓库外，用 `--profile/--shapes/--out` 指向本地路径；仓库内只保留 D 级合成样例。
