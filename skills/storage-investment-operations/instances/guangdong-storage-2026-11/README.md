# 广东独立储能 · 现货 + 调频收益叠加样板实例

> 本目录是 `skills/storage-investment-operations/instances/` 的第二个纵向切片：**一省（广东）+ 一主体（电网侧独立新型储能）+ 一个规则版本（省级现货 2023-12-28 转正、南方区域现货 2026-10-24 转正）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 所有演示数据为 **D 级合成数据**，不代表任何真实电站、报价、结算或收益。**容量电价/容量补偿未纳入**：广东独立储能的省级容量政策未在本库闭环，不能把煤电 165 元/kW·年套到储能。

## 1. 一条命令

```bash
# 配置校验 + 来源分级
python skills/storage-investment-operations/instances/guangdong-storage-2026-11/run.py --check-config

# 合成数据全流程：现货情景 → 调频月度 → 叠加 → 财务指标 → 复核表
python skills/storage-investment-operations/instances/guangdong-storage-2026-11/run.py --demo

# 真实数据（三份文件都必须提供，路径指向仓库外）
python skills/storage-investment-operations/instances/guangdong-storage-2026-11/run.py \
  --scenarios /path/to/scenarios.csv --frequency /path/to/frequency.csv \
  --availability /path/to/availability.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/storage-investment-operations/instances/guangdong-storage-2026-11/make_demo.py
```

## 3. 运行逻辑

1. **配置校验**：六个块齐全；现货 15 分钟 / 96 点、价区下限 < 上限；调频容量价、里程价、K 值范围齐全；`capacity.included` 必须为 `false`、容量价必须为 `null`；调频注册为 `true`；资产可用能量与 SOC 窗口一致；调频预留小于额定功率；叠加折减在 [0,1)。
2. **读三份数据**：5 个年度情景（权重合计 1，价格必须落在现货价区内）；12 个月调频日里程与 K 值；12 个月可用率。月份必须为 `YYYY-MM`、唯一且覆盖 12 个月。
3. **现货套利**：从额定功率中扣除调频预留，按 `stacking.arbitrage` 计算每个情景的毛额、充电量、放电量与退化成本；情景按权重汇总，年度可用率取 12 个月均值。
4. **调频收益**：逐月调用 `stacking.frequency_regulation`，按 `容量 × 容量价 × 24 h + 里程 × 里程价 × K` 计毛收入，乘当月天数与可用率；容量收入与里程收入分列。
5. **收益叠加**：把套利毛额与调频毛额相加，乘 `(1 − stack_haircut)` 得到叠加净额；再扣固定运维与套利退化，得到税前运营净额。三条线分账，不把调频毛收入直接加到套利净额。
6. **财务指标**：`finance.annual_cashflow` 生成 15 年现金流（直线折旧、25% 所得税），输出 NPV / IRR / 回收期 / LCOS；LCOS 含资本开支、固定运维、退化与充电成本，不含税与融资。
7. **容量缺口**：容量收入不计入。若 NPV 为负，用二分法求"把 NPV 拉到 0 所需的年收入增量"，再折算为元/kW·年。该值只是数学缺口，不是政策建议。
8. **复核表**：把规则来源、三线收益、情景尾部、调频月度、容量缺口与未核实项写在一页。

## 4. 合成演示的基准输出

基准资产：100 MW / 200 MWh、可用 180 MWh、RTE 88%；预留 20 MW 调频；现货日循环 0.8 次、年运行 330 天；叠加折减 5%；资本开支 900 元/kWh。

| 项目 | 金额（万元/年） |
|---|---:|
| 现货套利毛额 | 996.48 |
| 现货退化成本 | 133.14 |
| 现货套利净额 | 863.35 |
| 调频容量收入（毛） | 170.09 |
| 调频里程收入（毛） | 445.98 |
| 调频毛收入合计 | 616.07 |
| 叠加净额（扣 5% 折减） | 1,531.93 |
| 固定运维 | 320.00 |
| 运营支出合计 | 453.14 |
| 税前运营净额 | 1,078.79 |
| 资本开支 | 18,000.00 |
| NPV @8% | −8,766.13 |
| IRR | −1.30% |
| 静态回收期 | — |
| LCOS | 906.5 元/MWh |

- 情景期望税前运营净额 1,078.79 万元/年；CVaR（置信 80%）885.63 万元/年。
- 调频月度毛收入在 46.98–55.92 万元之间，5 月可用率 93% 最低。
- **容量收入未纳入**。若要把 NPV 拉到 0，当前假设下每年还需约 1,325.12 万元，折合 **132.5 元/kW·年**；这只是数学缺口，不代表广东存在该政策。

**读数**：本演示的 NPV 为负，不是模型错误，而是 D 级资本开支（900 元/kWh）、2 h 时长、0.8 次日循环与"容量收入为零"共同作用的结果。它说明：在容量政策未闭环时，仅靠现货套利 + 调频，2 h 项目很难在 8% 折现率下打平；把容量缺口写出来，是为了让投决讨论聚焦"政策是否落地、资格是否拿到"，而不是用煤电容量电价或拍脑袋的容量补偿把缺口填平。资本开支、价差与调频价格都是占位，真实项目必须整表替换。

未核实的容量政策不会被估算：`capacity.included` 被运行器强制为 `false`，容量价必须为 `null`；如果改成 `true` 或填一个价格，`--check-config` 会直接报错。

## 6. 风格档与指纹

当前风格 `guangdong-storage-spot-fr-v1`：2 h、日循环 0.8 次、年运行 330 天、调频预留 20 MW、叠加折减 5%、CVaR 置信 80%。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `4be13b138b52`）。比较两个项目时先看指纹：指纹不同，差异首先归因于策略；指纹相同，才归因于资源、价格或规则。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；计算内核来自 `skills/storage-investment-operations/tools/`（`stacking.py`、`finance.py`），不修改内核。
- **纳入**：现货电能量套利、调频容量 + 里程毛收入、月度可用率、套利退化、固定运维、所得税与直线折旧、容量缺口指示。
- **未纳入**：容量电价/容量补偿、容量租赁、备用、绿证、调频额外退化与考核的逐项建模、15 分钟 SOC 逐点优化、融资结构与保险。
- **不是**：不是交易中心结算的替代品，不是投资建议；套利、调频、容量必须分账复核。
- 真实数据放仓库外，用 `--scenarios/--frequency/--availability/--out` 指向本地路径；仓库内只保留 D 级合成样例。
