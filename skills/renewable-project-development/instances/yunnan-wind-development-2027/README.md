# 云南风电开发期投决 · 2027 样板实例

> 本目录是 `skills/renewable-project-development/instances/` 的第一个纵向切片：**一省（云南）+ 一主体（100 MW 陆上风电开发企业）+ 一个规则版本（发改价格〔2025〕136号；云南省 2027 年第一次机制电价竞价，2026-06-16 公示口径）**。配置改 `instance.json`，数据换 `data/resource_demo.csv`，运行 `run.py`，不改代码。
>
> 所有资源、造价、市场价格与绿色证书价格均为 **D 级合成数据**，不对应任何真实风电项目；机制电价批次与参数仅用于演示投决计算链，不构成投标、融资或投资建议。

## 1. 一条命令

```bash
# 配置校验 + 来源表
python skills/renewable-project-development/instances/yunnan-wind-development-2027/run.py --check-config

# 合成数据全流程：月度电量 → 捕获价 → 机制差价 → LCOE → 税后现金流 → 盈亏平衡价 → 投标区间 → 敏感性
python skills/renewable-project-development/instances/yunnan-wind-development-2027/run.py --demo

# 真实数据（路径指向仓库外）
python skills/renewable-project-development/instances/yunnan-wind-development-2027/run.py \
  --resource /path/to/resource.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/renewable-project-development/instances/yunnan-wind-development-2027/make_demo.py
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；四个规则块都有 `grade` + `source`；机制价必须落在申报下限与上限之间；覆盖比例不超过单体上限；只实现 `difference` 差价结算；数据契约必须包含 month / generation_mwh / capture_rate。
2. **资源数据**：12 个月、同一年、月份升序、电量与捕获率非负；加权捕获率 = Σ(月电量 × 月捕获率) / Σ月电量；数据隐含利用小时偏离 P50 超过 20% 时给出警告。
3. **月度结算**：市场收入 = 净电量 × 市场均价 × 月度捕获率（**捕获价**）；机制差价 = (机制价 − 市场均价) × 净电量 × 覆盖比例；绿证收入 = 6 元/MWh × 净电量。市场收入与差价使用两个不同的价格基准，不能合并成一个"机制价 × 全部电量"。
4. **LCOE**：以毛发电量、5% 限电、0.5%/年衰减、1%/年运维涨幅、8% 折现计算 20 年税前平准化成本；再用捕获价和绿证收入反算**税前机制价盈亏平衡**。
5. **税后现金流**：按 25% 所得税、20 年直线折旧、70% 负债、4% 利率、15 年等额还本计算项目现金流；NPV 按 8% 折现，IRR 与静态回收期由现金流序列求得。
6. **税后盈亏平衡价**：对机制电价做二分搜索，使 8% 折现下的项目 NPV 为零；向上取整到 0.1 分作为建议申报下限。
7. **DSCR**：债务本金 = 造价 × 70%；年度还本付息 = 等额本息；DSCR = 当年 CFADS / 还本付息，取还本期内的最低值，门槛 1.20。
8. **投标阶梯与敏感性**：对 0.320–0.3358 元/kWh 逐档计算 NPV/IRR/DSCR；再做造价、电量、运维、限电、捕获率、覆盖比例、P90 与组合压力八类情景。
9. **投决规则**：IRR ≥ 8%、NPV ≥ 0、最低 DSCR ≥ 1.20 三项同时满足才判"通过"。

## 4. 合成演示的基准输出（2028 首年）

| 项目 | 值 |
|---|---:|
| 装机容量 | 100 MW |
| P50 / P90 利用小时 | 2,850 / 2,557.8 h |
| 首年毛发电量 / 净电量 | 285,000 / 270,750 MWh |
| 加权捕获率 / 捕获价 | 92.52% / 0.2313 元/kWh |
| 机制电量（65%） | 175,987.5 MWh |
| 市场收入 / 机制差价 / 绿证 | 6,262.11 / 1,497.65 / 162.45 万元 |
| 合计收入 / 综合度电收入 | 7,922.21 万元 / 0.2926 元/kWh |
| 税前 LCOE | 258.87 元/MWh |
| 税前 / 税后 8% 盈亏平衡价 | 0.2832 / 0.3320 元/kWh |
| 申报上限 / 建议下限 | 0.3358 / 0.3321 元/kWh |
| NPV / IRR / 回收期 | +384.58 万元 / 8.11% / 9.51 年 |
| 首年 / 最低 DSCR | 1.73 / 1.53 |
| 投决结论 | 通过（安全垫很薄） |

| 申报价（元/kWh） | NPV（万元） | IRR | 判定 |
|---:|---:|---:|---|
| 0.3200 | −1,505.11 | 7.56% | 低于税后盈亏平衡 |
| 0.3300 | −253.66 | 7.93% | 低于税后盈亏平衡 |
| 0.3320 | −3.37 | 8.00% | 低于税后盈亏平衡 |
| 0.3340 | +246.92 | 8.07% | 可投（达门槛） |
| 0.3351 | +384.58 | 8.11% | 可投（达门槛） |
| 0.3358 | +472.19 | 8.14% | 可投（达门槛） |

**基准情景是"勉强过线"而非"稳健盈利"**：IRR 只比 8% 门槛高 0.11 个百分点，NPV 仅相当于造价的 0.8%。造价 +10%、电量 −10%、运维 +20%、限电 10%、捕获率 88%、覆盖比例 50%、P90 资源中的任意一项，都会把 IRR 压到 8% 以下；组合压力下 IRR 3.06%、NPV −17,231.89 万元、最低 DSCR 1.01。不要把这组数字当成对云南风电项目的可行性判断。

## 6. 风格档与指纹

当前风格 `yunnan-wind-bid-ceiling-v1`：先算 8% 门槛的税后盈亏平衡机制价，再与申报上限和申报区间比较；IRR、NPV、最低 DSCR 三项同时满足才判通过；申报下限向上取整到 0.1 分。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `886b410b3fdc`）。比较两个项目的差异时，先看指纹是否相同：指纹不同，差异首先归因于投决风格；指纹相同，才归因于资源、造价或规则。

换风格的做法：复制 `instance.json` 为 `instance.conservative.json`，改 `profile_id`、门槛与假设，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库 + 本技能 `tools/` 下的 `lcoe.py`、`finance.py`、`mechanism.py`、`resource.py`；不调用其他技能。
- **纳入**：P50/P90 资源、捕获率、机制差价、绿证、LCOE、税前与税后盈亏平衡价、项目现金流、NPV/IRR/回收期、资本金与 DSCR、投标阶梯、单项与组合压力。
- **未纳入**：土地与林草审批、接入工程与送出线路、建设期利息、保险、运维外包、亏损结转、税收优惠、加速折旧、绿电交易溢价、现货分时捕获、储能配套与容量租赁。
- **不是**：不是投标工具，不是银行可融资报告，不是对云南 2027 年竞价结果或后续批次的预测，不是投资建议。
- 真实数据放在仓库外，用 `--resource/--out` 指向本地路径；仓库内只保留 D 级合成样例。
