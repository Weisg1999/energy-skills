# 山东光储联合报价 · 2026-11 样板实例

> 本目录回答一个独立储能包回答不了的问题：**中午的光伏，是弃掉、存起来，还是报上网？联合主体应该申报多少净头寸？**
>
> 一省（山东）+ 一主体（200 MW 光伏 + 100 MW/200 MWh 配建储能，联合注册）+ 一个规则版本。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 所有演示数据为 **D 级合成数据**，不代表任何真实电站、真实报价或真实收益。

## 1. 一条命令

```bash
# 配置校验 + 来源表 + 未核实项
python skills/spot-bidding-quant/instances/shandong-pv-storage-2026-11/run.py --check-config

# 合成数据全流程：D-1 联合净头寸申报 → 五情景 CVaR → T+1 差异桥 → 复核表
python skills/spot-bidding-quant/instances/shandong-pv-storage-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/spot-bidding-quant/instances/shandong-pv-storage-2026-11/run.py \
  --d1 /path/to/d1.csv --t1 /path/to/t1.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/spot-bidding-quant/instances/shandong-pv-storage-2026-11/make_demo.py
```

## 3. 运行逻辑（从输入到联合申报表）

1. **配置校验**：六个块齐全；每个规则块有 `grade` + `source`；96 点与 15 分钟一致；限价满足 `clear_floor ≤ declare_floor < declare_cap ≤ clear_cap`；储能功率不超过光伏容量的 50%；并网受限出力不超过出清计划上限（光伏额定容量）；`grid_charge_allowed=false` 时购电上限必须为 0。
2. **读 D-1**：单交易日、96 点无缺口、5 组价格与 5 组光伏成对、价格落在出清限价内、光伏在 `[0, 额定容量]`。
3. **参考曲线**：参考价、参考光伏各取情景中位（`policy.*_quantile`）。价格与光伏按同一情景编号配对——低价情景对应高光伏，不能独立抽样后随意拼配。
4. **6 次 DP**：5 个情景各跑一次，再用参考曲线跑一次。调用 `ems-dispatch/tools/dispatch.py` 的 `dispatch_day`，`load_kw=0`、光伏作为唯一电源、`import_kw=0`、`export_kw=并网受限出力`，目标为「上网收益 − 退化成本 − 弃光惩罚」，`terminal="cycle"` 保证日末回到初始 SOC。
5. **净头寸合成**：每个时段把 5 个情景的净上网功率取中位，裁剪到 `[0, 并网上限]`，得到申报净上网曲线。申报的不是光伏出力，也不是储能曲线，而是 `光伏 − 充电 + 放电` 的净额。
6. **情景清算**：固定参考调度，在 5 个情景下执行（充电受可用光伏限制、放电受 SOC 限制、不得从电网充电），得到各情景净边际、期望净边际、CVaR10 与完美预见上界。
7. **T+1 差异桥**：把「参考价口径计划边际」与「实际价量口径实际边际」的差拆成电价、净头寸量差、价量交叉、退化、弃光惩罚、固定成本 6 项，残差应为 0。
8. **复核表**：输出最大差异科目、Top 5 量偏差时段、三个复核问题与次日动作。

关键恒等式（`run.py` 与自测同时锁定）：

```
上网功率 = 光伏功率 − 充电功率 + 放电功率
弃光功率 = max(0, 光伏功率 − 充电功率 + 放电功率 − 并网上限)
等效循环 = (充电量 + 放电量) / (2 × 储能能量)
```

## 4. 合成演示的基准输出（2026-11-18）

| 项目 | 值 |
|---|---:|
| 参考光伏电量 | 720.3 MWh |
| 计划充电量 | 191.9 MWh |
| 计划放电量 | 168.9 MWh |
| 计划净上网（参考调度） | 693.6 MWh |
| 申报净头寸（中位） | 652.6 MWh |
| 期望净上网（按情景） | 634.9 MWh |
| 期望弃光 | 50.9 MWh |
| 等效循环 | 0.90 次 |
| 参考价口径净边际 | 131,348 CNY |
| 情景期望净边际 | 129,021 CNY |
| 情景 CVaR10 | 72,990 CNY |
| 完美预见期望（上界） | 130,626 CNY |
| 预见价值（上界 − 计划） | 1,604 CNY |
| 实际净边际（T+1） | 130,428 CNY |
| 计划 → 实际差异 | −1,083 CNY |
| 差异桥残差 | −9.32e-12 CNY |

**弃光只在光照最好的两个情景出现**：情景 3/4/5 的弃光分别为 3.7 / 49.0 / 91.5 MWh。原因是并网受限出力 100 MW 小于光伏峰值（参考 150 MW、最晴 183 MW），储能先充电、充满后剩余光伏只能弃掉。云层厚的情景 1–2 没有弃光，但价格更高——这就是价格与光伏的负相关：**不能把「高光伏」和「高电价」同时假设**。

## 6. 风格档与指纹

当前风格：申报量、参考价、参考光伏均取 0.5 分位；充放电加价为 0（报量不报价下报价字段填申报下限，仅作占位）；日循环上限 1.5；最小日价差 60 CNY/MWh；弃光惩罚 20 CNY/MWh。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `d634623504c5`）。比较两个交易日的差异时，先看指纹是否相同：指纹不同，差异首先归因于风格；指纹相同，才归因于预测、执行或规则。

换风格的做法：复制 `instance.json` 为 `instance.aggressive.json`，改 `profile_id` 与参数，用 `--instance` 指向新文件，保留旧文件与旧输出。若要做报量报价，把 `bid_mode_code` 改为 `price_quote`，并同步修改 `rules.new_energy_participation.bid_mode`。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；调度内核来自 `skills/ems-dispatch/tools/dispatch.py`，通过绝对路径以独立模块名加载，不修改 EMS 技能。
- **纳入**：现货电能量、联合净上网结算、退化成本、固定成本、弃光惩罚（D 级占位）、五情景 CVaR、T+1 差异桥。
- **未纳入**：机制电价差价、两个细则考核、绿证收益、容量补偿、中长期曲线分解、辅助服务、日内小时级滚动更新、实时 5 分钟偏差结算。
- **不是**：不是实盘下单工具，不是交易中心结算的替代品，不是投资建议。
- 真实数据放在仓库外，用 `--d1/--t1/--out` 指向本地路径；仓库内只保留 D 级合成样例。
