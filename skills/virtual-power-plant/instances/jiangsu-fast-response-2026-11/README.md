# 江苏负荷快速响应聚合商 · 2026-11 样板实例

> 本目录是 `skills/virtual-power-plant/instances/` 的第一个纵向切片：**一省（江苏）+ 一主体（负荷聚合商 / 邀约型 VPP）+ 一个规则版本（苏发改规发〔2026〕1号）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 所有演示数据为 **D 级合成数据**，不对应任何真实聚合商、用户、合同或计量数据。

## 1. 一条命令

```bash
# 配置校验 + 来源表 + 未核实项
python skills/virtual-power-plant/instances/jiangsu-fast-response-2026-11/run.py --check-config

# 合成数据全流程：D-1 申报 → 情景出清/CVaR → T+1 响应认定 → 差异桥 → 复核表
python skills/virtual-power-plant/instances/jiangsu-fast-response-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/virtual-power-plant/instances/jiangsu-fast-response-2026-11/run.py \
  --history /path/to/history.csv --event /path/to/event.csv \
  --t1-loads /path/to/t1_loads.csv --t1-event /path/to/t1_event.csv \
  --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/virtual-power-plant/instances/jiangsu-fast-response-2026-11/make_demo.py
```

只做申报、不做 T+1 复盘时，省略 `--t1-loads` 与 `--t1-event`，产物只到情景与申报表。

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：七个块齐全；每个规则/资源/合同块有 `grade` 与 `source`；`meta.units.price` 必须是 `CNY/kWh`；资源 `control_type` 只能是 `direct` 或 `self`；报价不得超过对应类型上限（直控 15、自控 10 元/kWh）；测试规模与申报值一致可算。
2. **读基线样本**：单资源字段齐全、每个样本日 96 点无缺口、至少 3 个样本日；按事件日类型选最近 5 个工作日或 3 个休息日。
3. **算基线**：调用 `virtual-power-plant/tools/cbl.py` 的 `customer_baseline`，按「日电量 / 候选集均值 < 25% 或 > 200% 剔除」的江苏口径筛选，逐点平均 × 修正系数。VPP 基线为各资源基线之和，同一用户不得重复计入。
4. **申报**：可调能力 = 额定 × 可调比例 × 可用率；申报量 = 可调能力 × 申报比例，按 `declaration_rounding_mw` 向下取整；报价按风格档填写并受类型上限约束。
5. **情景出清**：按「价格优先、容量优先」逐情景判断报价是否不高于边际价；中标量 = min(申报量, 需求量)；毛收入 = 出清价 × 中标量 × 1000 × 事件时长；扣客户分成、变动成本与固定成本，得到期望净收益与 CVaR。
6. **T+1 认定**：响应量 = max(0, 基线 − 实际负荷)；响应率 = 响应量 / 中标量；低于 80% 判无效、不计激励；超过申报值的部分按直控 150%、自控 120% 封顶；执行率低于 95% 时按合同额外让利 5 个百分点给客户。
7. **差异桥**：按「出清价差 → 中标量差 → 执行率差 → 超额封顶或无效扣减 → 客户分成与未达标补偿 → 运营成本」顺序逐项替换，残差应为 0。
8. **合规清单**：逐项检查报价上限、申报不超能力、测试规模 ≥20%、事件落在 17:00–22:00、同一时段不重复参与 DR、响应率 ≥80%。

## 4. 合成演示的基准输出（2026-07-15 19:00–19:30）

| 项目 | direct | self |
|---|---:|---:|
| 可调能力 MW | 30.66 | 10.80 |
| 申报 MW | 26.00 | 8.60 |
| 报价 元/kWh | 13.50 | 9.40 |
| 类型上限 元/kWh | 15.00 | 10.00 |
| 客户分成 | 67.7% | 75.0% |
| 基线候选 / 保留 / 剔除日 | 5 / 4 / 1 | 5 / 4 / 1 |
| T+1 响应量 MW | 24.20 | 10.80 |
| T+1 响应率 | 93.1% | 125.6% |
| 封顶后计量 MW | 24.20 | 10.32 |

| 汇总项 | 值 |
|---|---:|
| 情景期望净收益 | 48,401 元 |
| 情景 CVaR80 | −2,000 元 |
| 计划净收益（执行率 95%） | 45,881 元 |
| 实际净收益 | 53,303 元 |
| 差异 | +7,423 元 |
| 差异桥残差 | 0.00e+00 元 |

**CVaR80 为 −2,000 元是风格使然，不是算错**：情景 s1 的边际价低于两类报价，不中标，但固定成本 2,000 元照常发生；这是"宁可空仓也不低价中标"的风格选择，复盘时要按风格解释。

**self 的 125.6% 响应率被 120% 封顶**：实际响应 10.80 MW，但只有 8.60 × 1.20 = 10.32 MW 计量，多出的 0.48 MW 不计激励；差异桥中「超额封顶或无效扣减」为 −576 元，正是这部分。

## 6. 风格档与指纹

当前风格：直控按可调能力 85%、自控按 80% 申报；报价直控 13.5、自控 9.4 元/kWh；计划执行率 95%；未达标补偿门槛 95%。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `c46bb8a332bf`）。比较两个邀约的差异时，先看指纹是否相同：指纹不同，差异首先归因于风格；指纹相同，才归因于基线、执行或规则。

换风格的做法：复制 `instance.json` 为 `instance.aggressive.json`，改 `profile_id` 与参数，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；基线算法来自 `skills/virtual-power-plant/tools/cbl.py`，新增的上下界筛选是加法扩展，不改变既有对称剔除行为。
- **纳入**：直控/自控快速响应的能力核算、申报、情景出清、CVaR、T+1 响应认定、超额封顶、客户分成、运营成本、差异桥、合规清单。
- **未纳入**：现货电能量、辅助服务、容量补偿、绿证、考核罚款（1号文未见明确罚款条款）、邀约组织方的调度指令跟踪、5 分钟级实时计量。
- **不是**：不是交易中心/供电公司的结算替代品，不是自动投标工具，不是对任何真实用户的响应能力承诺。
- 真实数据放在仓库外，用 `--history/--event/--t1-loads/--t1-event/--out` 指向本地路径；仓库内只保留 D 级合成样例。
