# 上海用户侧虚拟电厂 · 2026-11 样板实例

> 本目录是 `skills/virtual-power-plant/instances/` 的第二个纵向切片：**一省（上海）+ 一主体（用户侧 VPP 聚合商）+ 一个规则版本（沪经信运〔2025〕407号）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 所有演示数据为 **D 级合成数据**，不对应任何真实聚合商、用户、合同或计量数据。

## 1. 一条命令

```bash
# 配置校验 + 来源表 + 未核实项
python skills/virtual-power-plant/instances/shanghai-vpp-2026-11/run.py --check-config

# 合成数据全流程：5 日基线 → 组合能力 → 情景申报 → T+1 认定 → 差异桥 → 复核表
python skills/virtual-power-plant/instances/shanghai-vpp-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/virtual-power-plant/instances/shanghai-vpp-2026-11/run.py \
  --history /path/to/history.csv --event /path/to/event.csv \
  --t1-loads /path/to/t1_loads.csv --t1-event /path/to/t1_event.csv \
  --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/virtual-power-plant/instances/shanghai-vpp-2026-11/make_demo.py
```

本包四个输入文件缺一不可；只做申报不做 T+1 复盘时，先按模板造一份 T+1 数据，或参考江苏包的裁剪方式自行改 `run.py`。

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；每个规则块有 `grade` + `source`；407 号目标必须是 110/160/220 万 kW，2025-08 调用必须是 116.27 万 kW；五类资源 `id` 必须与 407 号五类目标一一对应；96 点与 15 分钟一致；事件窗口、时长、结算价与情景权重复核。
2. **读基线样本**：每个样本日 96 点无缺口、日期唯一；按事件日之前最近 5 日做候选。
3. **算基线**：调用 `virtual-power-plant/tools/cbl.py` 的 `customer_baseline`，剔除日电量偏离候选均值 ±25% 的异常日，逐点平均 × 修正系数（本包取 1.0）。总基线 = 五类资源基线之和。
4. **组合能力**：可调功率 = 额定 × 可调比例 × 可用率；申报能力 = 可调功率 × 同时率；申报量 = 申报能力 × 政策申报比例，按 `declaration_rounding_mw` 向下取整。
5. **情景申报**：报价 4.2 元/kWh（D 级演示价）；激励价高于等于报价的情景中标，中标量 = min(申报量, 需求)；计划响应 = 中标量 × 事件时长 × 计划执行率 95%。
6. **T+1 认定**：响应量 = Σ max(0, 基线 − 实际负荷) × 15 分钟；响应率 = 响应量 / 计划响应；响应率 ≥ 50% 判有效，超过 120% 中标量的部分封顶；响应率 < 95% 触发合同额外让利 5 个百分点。
7. **差异桥**：计划边际 → 实际边际拆成响应量偏差、超额封顶、有效性扣减、客户分成变化、运营成本偏差 5 项，残差应为 0。
8. **复核表**：输出结论摘要、1+5 组合、407 号目标对照、基线口径、情景、响应认定、差异桥与四条口径提醒。

## 4. 合成演示的基准输出（2026-08-14 14:00–15:00）

| 项目 | 值 |
|---|---:|
| 组合理论可调 | 150.0 MW |
| 计入可用率后 | 135.45 MW |
| 同时率 85% 后申报能力 | 115.13 MW |
| 按 80% 申报 | 92.1 MW |
| 占 2027 年 220 万 kW 目标 | 4.19% |
| 报价 | 4.2 元/kWh（D 级演示） |

| 综合项 | 值 |
|---|---:|
| 参考情景（4.2 元/kWh）中标 | 80.0 MW / 计划 76.0 MWh |
| 参考情景聚合商边际 | 108,714 元 |
| 情景期望边际 | 88,057 元 |
| CVaR80（最差 20% 概率质量均值） | 0 元 |
| T+1 实际响应 | 71.5 MWh |
| 响应率 | 94.06%（有效，但低于 95% 合同执行率） |
| 客户分成 | 62.14% → 67.14% |
| 实际边际 | 87,065 元 |
| 计划 → 实际差异 | −21,649 元 |

**CVaR 为 0 不是算错**：报价 4.2 元/kWh 时，3.6 元/kWh 的低价情景不中标，本包把未中标记为边际 0；最差 20% 概率质量（实际落在 30% 权重的 s1）均值为 0。尾部风险是「丢掉高价情景的收入」，不是现金亏损，复盘时要按这个口径解释。

**94.06% 同时是「有效」和「未达标」**：50% 是响应有效性门槛（D 级假设），95% 是合同执行率门槛；前者决定是否结算，后者决定是否额外让利 5 个百分点，两者不能混用。

## 6. 风格档与指纹

当前风格 `shanghai-vpp-1plus5-balanced-v1`：按可调能力 80% 申报；报价 4.2 元/kWh；计划执行率 95%；同时率 85%；CVaR 置信 80%。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `6ac0d5e814ad`）。比较两个交易日的差异时，先看指纹是否相同：指纹不同，差异首先归因于风格；指纹相同，才归因于基线、执行或规则。

换风格的做法：复制 `instance.json` 为 `instance.aggressive.json`，改 `profile_id` 与参数，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；基线与聚合内核来自 `skills/virtual-power-plant/tools/cbl.py` 与 `aggregation.py`，通过绝对路径以独立模块名加载。
- **纳入**：5 日基线、1+5 组合能力、情景申报、CVaR、T+1 响应认定、超额封顶、未达标客户让利、差异桥。
- **未纳入**：中长期、现货、辅助服务、容量补偿、绿证、需求响应与快响的重复参与校验、用户级结算单。
- **不是**：不是实盘申报工具，不是上海 VPP 结算细则的替代品，不是投资建议。
- 真实数据放在仓库外，用 `--history/--event/--t1-loads/--t1-event/--out` 指向本地路径；仓库内只保留 D 级合成样例。
