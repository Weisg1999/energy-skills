# 深圳 V2G 聚合 · 2026-11 样板实例

> 本目录是 `skills/virtual-power-plant/instances/` 的车网互动纵向切片：**一城（深圳）+ 一主体（V2G 聚合商：公共场站私家车 + 公交场站 + 物流园区）+ 一组规则（广东 VPP 准入 ≥5 MW/≥1 h、广东 2026 削峰 DR 申报上限 2,700 元/MWh、南方区域广东价区现货 −50–1,800 元/MWh）**。它要回答的不是“V2G 能不能赚钱”，而是三个更容易算错的问题：**铭牌功率能报多少、报出去的 MW 一年能调用多少小时、车主分走之后聚合商还剩多少**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码；所有演示数据为 **D 级合成数据**，不对应任何真实站点、车辆、聚合商或结算单。

## 1. 一条命令

```bash
# 配置校验 + 来源分级
python skills/virtual-power-plant/instances/shenzhen-v2g-2026-11/run.py --check-config

# 合成数据全流程：站点能力 → 四种品种分配 → 月度收益 → 敏感性 → 临界值 → 复核表
python skills/virtual-power-plant/instances/shenzhen-v2g-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/virtual-power-plant/instances/shenzhen-v2g-2026-11/run.py \
  --market /path/to/market.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/virtual-power-plant/instances/shenzhen-v2g-2026-11/make_demo.py
```

## 3. 运行逻辑

1. **配置校验**：六个规则块齐全，每块有 `grade` + `source`；每个站点满足 `usable_kwh ≤ battery_kwh × (soc_max − soc_min)`；配变反向限额不大于配变容量；车队实测能力 ≥5 MW、持续时间 ≥1 h、单站 ≥0.02 MW；策略的套利 + DR + 备用 ≤ 容量预算；DR 申报 × 单次 2 h ≤ 日可用电量。
2. **站点能力折算**：
   - 车-桩可用功率 = 车辆数 × 单桩功率 × 同时率 × 可用率；
   - 日可用电量 = 车辆数 × 单车可用电量 × 同时率 × 可用率；
   - 实测能力 = min(车-桩可用功率, 配变反向限额)；
   - 聚合持续时长 = 日可用电量 ÷ 实测能力。
3. **套利**：每日套利电量 = min(申报 MW × 峰段小时, 日可用电量 × 95%)；充电成本 = 放电量 ÷ 90% × 谷价；再扣 130 元/MWh 电池退化。申报 MW 超过能量允许功率时，多余 MW 不产生电量，只挤占 DR/备用。
4. **需求响应**：DR 电量 = 申报 MW × 月度调用小时 × 交付率；短供超过 10% 容差的部分按 1.2 倍 DR 单价考核；单次事件按 2 h 校验能量。
5. **备用**：备用收入 = 备用 MW × 1,000 × 元/kW·月；与套利、DR 共用同一份 MW，不能重复卖。
6. **成本与分成**：双向桩投资按 8 年折旧，计安装 10%、年运维 2%，加平台 12 万元/年、计量核证 8 万元/年；套利净收益按车主 50%、DR 按 60%、备用按 30% 分成，固定成本全部由聚合商承担。
7. **策略选择**：VPP 净收益 =（1 − 车主分成）× 各品种净收益 − 固定成本；同时报告车主收益、总盘、套利有效 MW 与能量受限标记。VPP 最优与总盘最优不一致时，必须回到分成与考核条款。
8. **敏感性**：放电价、谷电价、DR 价格、DR 调用小时、交付率、退化、桩成本、运营天数、车主分成与组合压力。
9. **临界值**：VPP 净收益为零的放电价倍数、运营天数、桩成本倍数；DR 优先反超均衡组合的 DR 价格倍数与放电价倍数。
10. **复核表**：把“申报 MW → 有效 MW → 电量 → 净收益”和“车主 → 聚合商 → 总盘”两条链分开写。

## 4. 合成演示的基准输出

基准资产：430 辆车、车-桩可用 7.78 MW、配变限额后 **7.31 MW**、日可用电量 **13.26 MWh**、持续 **1.81 h**；运营 300 天/年；市场数据为 D 级深圳 2026 月度价格。

| 项目 | 值 |
|---|---:|
| 申报套利（均衡组合） | 3.40 MW |
| 套利有效 MW | 2.96 MW（能量受限） |
| 套利电量 | 3,779 MWh |
| DR 申报 / 电量 | 3.20 MW / 353 MWh |
| 备用 | 0.71 MW |
| 套利净收益 | 156.22 万元 |
| DR 净收益 | 92.29 万元 |
| 备用收入 | 6.82 万元 |
| 固定成本 | 101.90 万元 |
| 车主收益 | 135.53 万元 |
| VPP 净收益 | 17.90 万元 |
| 总盘 | 153.43 万元 |
| 只做套利：VPP / 车主 / 总盘 | −23.79 / 78.11 / 54.32 万元 |
| DR 优先：VPP / 车主 / 总盘 | 2.75 / 137.05 / 139.80 万元 |
| 全栈申报：VPP / 车主 / 总盘 | 10.65 / 120.34 / 130.99 万元 |
| 全栈申报考核 | 3.79 万元（交付率 86%） |

**读法**：只做套利时，套利本身赚 156 万元，但车主分走一半后只剩 78 万元，覆盖不了 102 万元固定成本，VPP 净收益为负；均衡组合用同一份 MW 再加 DR 与备用，把 VPP 净收益拉到 17.90 万元。DR 单价是套利净价的数倍，但一年只调用 116 h，套利一年可用约 1,200 h——**决定收益的是 MW × 可调用小时，不是单价**。

临界值（基准 1.00）：

| 变量 | 临界值 | 含义 |
|---|---:|---|
| V2G 放电价 | 0.90 倍（约 826 元/MWh） | 低于此，均衡组合 VPP 净收益转负 |
| 年运营天数 | 231 天 | 低于此，VPP 净收益转负 |
| 桩成本 | 1.22 倍 | 高于此，VPP 净收益转负 |
| DR 价格（DR 优先反超均衡） | 1.54 倍（约 4,039 元/MWh） | 已高于广东 2,700 元/MWh 申报上限 |
| 放电价（DR 优先反超均衡） | 0.82 倍（约 757 元/MWh） | 放电价跌破此，DR 优先占优 |

敏感性（相对基准 VPP 17.90 万元）：放电价 ±20% → ±34.78 万元；谷电价 ±20% → ∓14.25；DR 价格 ±30% → ±11.08；DR 调用 ±50% → ±18.46；交付率 −10pp → −6.22；退化 +50% → −12.28；桩成本 +30% → −24.57；运营 200 天 → −26.04；车主分成 +10pp → −7.63（总盘不变）；组合压力 → −99.75（总盘 −70.39）。

## 6. 风格档与指纹

当前风格 `shenzhen-v2g-mw-hours-v1`：四策略在套利、DR、备用之间分配同一份 7.31 MW；套利交付率 95%；DR 单次 2 h；车主分成 50%/60%/30%；CVaR 未启用（本包为确定性月度模型）。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `b4ca2598e6a4`）。换风格就换 `profile_id` 并保留旧文件与旧输出，便于比较“套利优先 vs DR 优先 vs 均衡”。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；不修改 `skills/virtual-power-plant/tools/` 的聚合、基线、调度与财务内核。
- **纳入**：站点能力折算、配变反向限额、峰谷套利、DR 与考核、备用容量、电池退化、双向桩年化、平台与计量、车主/聚合商分成、敏感性与临界值。
- **未纳入**：现货 96 点报价与偏差结算、调频里程、容量补偿、输配电费抵扣、需量电费、绿证/碳、电池质保成本、补贴、税费与融资。
- **不是**：不是交易中心结算单，不是 V2G 投资建议，不是深圳全市 V2G 容量统计；真实项目以车辆清单、桩铭牌、并网测试、台区承载力评估与合同为准。
- 真实数据放在仓库外，用 `--market/--out` 指向本地路径；仓库内只保留 D 级合成样例。
