# 浙江 VPP 2.0 · 2026-11 样板实例

> 本目录是 `skills/virtual-power-plant/instances/` 的第三个纵向切片：**一省（浙江）+ 一主体（三类聚合单元的 VPP 运营商）+ 一个规则版本（公告〔2026〕第7号，2026-09-23）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 所有演示数据为 **D 级合成数据**，不对应任何真实聚合商、聚合单元、用户或结算数据。

## 1. 一条命令

```bash
# 配置校验 + 来源表 + 三类单元能力
python skills/virtual-power-plant/instances/zhejiang-vpp2-2026-11/run.py --check-config

# 合成数据全流程：门槛校验 → 月度调用结算 → 考核封顶 → 快速型准备费 → 月度评级 → 复核表
python skills/virtual-power-plant/instances/zhejiang-vpp2-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/virtual-power-plant/instances/zhejiang-vpp2-2026-11/run.py \
  --events /path/to/events.csv --response /path/to/response.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/virtual-power-plant/instances/zhejiang-vpp2-2026-11/make_demo.py
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；每个规则块有 `grade` + `source`；三类聚合单元门槛必须是 ≥5 MW / ≥1 h，负荷类另要求立户 >3 个月；补偿档必须是正调节 800/1000/1200、负调节 300/350/380 元/MW；有效响应门槛 70%；评级权重 3:7；快速型无效 ≥3 次归零。
2. **单元能力**：逐资源算 `max_mw × availability × positive_ratio`（负调节用 `negative_ratio`），按单元汇总；任一单元正调节能力 <5 MW 直接拒绝运行。申报能力 = 正/负调节能力 × `bid_ratio`，向下取整到 0.1 MW。
3. **读调用**：事件必须覆盖三类单元、至少一次正调节与一次负调节、至少一次快速型；所有事件在同一自然月、单次 1 h；补偿价必须落在对应方向的档位内。
4. **逐次结算**：中标量 = min(申报能力, 需求量)；补偿 = min(实际 MW, 1.2 × 中标 MW) × 元/MW；响应率 <70% 判无效，考核 = 实际差额 × 补偿价 × 0.5，且不超过该次补偿的 1.2 倍。
5. **月度评级**：能力分 = min(申报正能力 / 5 MW, 1) × 100；响应分 = Σ中标 MW × 响应率 / Σ中标 MW × 100；总分 = 0.3 × 能力分 + 0.7 × 响应分；按 A+ ≥95、A ≥90、B ≥80、C ≥70 分级。
6. **快速型准备费**：有快速型调用的单元，按申报正能力 × 2,000 元/MW·月计；月内快速型无效调用 ≥3 次归零；当月无快速型调用则不适用。
7. **汇总**：响应净额 = 补偿 − 考核；当月净额 = 响应净额 + 准备费 − 平台与计量成本。
8. **复核表**：输出门槛、逐次结算、评级、准备费与四条口径提醒。

## 6. 风格档与指纹

当前风格 `zhejiang-vpp2-balanced-v1`：三类单元统一按可调能力 90% 申报；考核系数 0.5；快速型准备费 2,000 元/MW·月；申报取整 0.1 MW。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `5ceaa246ace4`）。比较两个月的差异时，先看指纹是否相同：指纹不同，差异首先归因于风格；指纹相同，才归因于资源、执行或规则。

换风格的做法：复制 `instance.json` 为 `instance.aggressive.json`，改 `profile_id` 与参数，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；本包不调用引擎层函数，能力折算与结算逻辑在 `run.py` 内自洽实现，便于按省规则独立演进。
- **纳入**：三类聚合单元门槛、正/负调节结算、有效性判定、考核与 1.2 倍封顶、月度 A+–D 评级、快速型能力准备费。
- **未纳入**：基线认定（浙江 2.0 基线口径未核到）、现货、辅助服务、容量补偿、绿证、用户零售结算、涉网试验与调度协议。
- **不是**：不是实盘申报工具，不是省负荷管理中心评级或结算的替代品，不是投资建议。
- 真实数据放在仓库外，用 `--events/--response/--out` 指向本地路径；仓库内只保留 D 级合成样例。
