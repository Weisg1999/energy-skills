# 广东多用户绿电直连 · 2027 样板实例

> 本目录是 `skills/retail-electricity-risk/instances/` 的多用户纵向切片：**一省（广东）+ 一主体（绿电直连项目公司/多用户联合体）+ 一个规则版本（650/688 号多用户直连、1192 号就近消纳价格、广东 267/1848 号）**。配置改 `instance.json`，数据换 `data/profile_demo.csv`，运行 `run.py`，不改代码。核心问题不是"直连能不能建"，而是**三个法人用户怎么分电、怎么分摊容量费、谁在补贴谁**。
>
> 所有发用电量、用户结构、LCOE、储能成本、输配电价、系统运行费、基金、上网电价与绿证价格均为 **D 级合成数据**，不对应任何真实园区、用户或项目；规则文号仅用于演示计算链，不构成投资、报价或签约建议。

## 1. 一条命令

```bash
# 配置校验 + 来源表
python skills/retail-electricity-risk/instances/guangdong-multi-user-direct-2026-11/run.py --check-config

# 合成数据全流程：月度发用电 → 项目级匹配 → 用户级分配 → 合规校核 → 成本堆叠 → 四种分摊口径 → 敏感性
python skills/retail-electricity-risk/instances/guangdong-multi-user-direct-2026-11/run.py --demo

# 真实数据（路径指向仓库外）
python skills/retail-electricity-risk/instances/guangdong-multi-user-direct-2026-11/run.py \
  --profile /path/to/profile.csv --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/retail-electricity-risk/instances/guangdong-multi-user-direct-2026-11/make_demo.py
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；四个规则块都有 `grade` + `source`；用户数不少于 2、合同份额之和为 1、年用电量与配置一致；政策门槛在 0–1；分摊口径必须是 `energy` / `capacity` / `contract` / `two_part` 之一。
2. **月度匹配**：项目级先算总盈余与总缺口；上网电量受"月度可用发电量的 20%"约束，超出部分计弃电；下网电量补足项目缺口。
3. **用户分配**：按合同份额把当月发电量分到用户；每个用户自用、盈余、缺口分别计量；项目内先互济，剩余盈余再按比例上网或弃电，剩余缺口按下网处理。
4. **合规校核**：自用/可用发电量 ≥ 60%、自用/总用电量 ≥ 35%（2030 年前口径）、上网/可用发电量 ≤ 20%、用户数 ≥ 2；四项全部通过才算合规。
5. **成本堆叠**：发电成本按可用发电量计（弃电也摊成本）；储能年化、专线运维、容需量电费、1192 号折算电费、下网系统运行费与线损、总用电量政府性基金；上网收入与绿证收入抵减。
6. **分摊口径**：按用电量、按最大需量、按合同份额、两部制（容量费按需量、其余按电量）四种口径分别计算用户单位成本与极差。
7. **临界 LCOE**：二分搜索使直连净成本等于原模式全口径成本；高于该值，直连不再优于直接买电。
8. **敏感性**：LCOE ±、发电量 ±、用电量 ±、上网电价 ±、接入容量下降、储能成本上升、合同份额调整、用户 C 用电上升，共 12 个情景。

**用户结构是刻意错配的**：数据中心合同份额 50%、用电份额 52%，年度缺口 3,000 MWh；电子制造合同份额 30%、用电份额 28%，年度盈余 36,000 MWh，其中 10,400 MWh 内部卖出、15,158 MWh 上网、10,442 MWh 弃电；冷链仓储合同份额与用电份额都是 20%，但夏季缺口、冬季盈余并存。多用户直连的价值不只在"多用绿电"，还在**用户间的时序互补**；但互补必须通过内部结算价落地，否则分摊口径会变成成员争议。

## 5. 分摊口径比较

| 口径 | 数据中心 A | 电子制造 B | 冷链仓储 C | 极差（元/MWh） |
|---|---:|---:|---:|---:|
| 按用电量 | 486.77 | 486.77 | 486.77 | 0.00 |
| 按最大需量 | 468.05 | 452.00 | 584.13 | 132.12 |
| 按合同份额 | 468.05 | 521.54 | 486.77 | 53.49 |
| 两部制（容量+电量） | 479.62 | 473.49 | 523.97 | 50.48 |

- **按用电量**：单位成本完全相同，但容量费被高电量用户多摊，低负荷率用户占便宜。
- **按最大需量**：冷链仓储 C 负荷率最低，单位成本 584.13 元/MWh，比 B 高 132.12 元/MWh。
- **按合同份额**：电子制造 B 合同份额 30% 高于用电份额 28%，单位成本 521.54 元/MWh，成为最高。
- **两部制**：容需量与 1192 折算费按容量、其余成本按电量，极差收窄到 50.48 元/MWh，是成本因果最接近的口径。

## 7. 风格档与指纹

当前风格 `guangdong-multi-user-direct-v1`：先做 60%/35%/20% 合规校核，再比全口径度电成本，最后比较四种分摊口径；主口径为两部制，临界 LCOE 用二分搜索。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `c0cab5a8ab4a`）。比较两个直连项目的差异时，先看指纹是否相同：指纹不同，差异首先归因于合规门槛、分摊口径与价格假设；指纹相同，才归因于资源、负荷或成本参数。

换风格的做法：复制 `instance.json` 为 `instance.conservative.json`，改 `profile_id`、门槛、分摊主口径与价格假设，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 8. 依赖与边界

- **依赖**：仅 Python 标准库；不调用其他技能的 `tools/`，因为多用户分摊与项目内互济不在售电引擎层的现有函数范围内。
- **纳入**：月度发用电匹配、项目级上网/弃电/下网、用户级分配与内部互济、60%/35%/20% 合规、容需量与 1192 折算、成本堆叠、四种分摊口径、临界 LCOE、12 个敏感性情景。
- **未纳入**：专线建设与土地、融资与税、备用电源、储能容量配置优化、绿证核发/划转/核销细则、省级正式参数、用户信用与违约、内部结算价谈判、接入电压等级与防孤岛细则。
- **不是**：不是接入系统设计，不是价格核定文件，不是对广东任何园区或项目的可行性判断，不是投资建议。
- 真实数据放在仓库外，用 `--profile/--out` 指向本地路径；仓库内只保留 D 级合成样例。
