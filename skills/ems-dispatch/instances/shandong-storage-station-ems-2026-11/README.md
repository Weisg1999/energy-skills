# 山东独立储能电站 EMS 日运行 · 2026-11 样板实例

> 本目录是 `skills/ems-dispatch/instances/` 的第二个纵向切片：**一省（山东）+ 一主体（独立储能电站运营主体）+ 一个规则版本（山东电力现货市场规则；并网运行考核两个细则仅作考核口径参照）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 与第一个切片（江苏零碳园区微网）的差别：园区是**用户侧**微网，盯电费与需量；本包是**电网侧独立储能电站**，盯现货能量套利与涉网考核。与 `spot-bidding` 下的山东储能报价实例也不同：那边是**报价/出清**视角，本包是**电站级日运行 + 考核复盘**视角。
>
> 全部价格、AGC 指令、频率偏差、储能与考核参数均为 **D 级合成数据**，不对应任何真实电站、调度指令或电网事件。

## 1. 一条命令

```bash
# 配置校验 + 规则来源表
python skills/ems-dispatch/instances/shandong-storage-station-ems-2026-11/run.py --check-config

# 合成数据全流程：能量套利调度 → AGC 考核复盘 → 一次调频考核复盘 → 综合净收益
python skills/ems-dispatch/instances/shandong-storage-station-ems-2026-11/run.py --demo

# 换一份配置（数据路径可指向仓库外）
python skills/ems-dispatch/instances/shandong-storage-station-ems-2026-11/run.py \
  --instance /path/to/instance.json --out /path/to/out
```

合成数据可重新生成：

```bash
python skills/ems-dispatch/instances/shandong-storage-station-ems-2026-11/make_demo.py
```

## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：五个块齐全；每个规则块有 `grade` + `source`；电价满足峰 ≥ 平 ≥ 谷；储能功率/容量为正、RTE 与 SOC 窗口合法；一次调频峰段上调可用功率不超过额定功率。
2. **读数据**：必须 96 点、序号与时间连续；电价为正且与该点 `segment` 对应电价一致；AGC 指令在 ±额定功率内；频率偏差在 ±1 Hz 内。
3. **能量套利调度**：调用共享内核 `tools/storage.py`（封装 `tools/dispatch.py` 的 SOC 网格动态规划），100 MW/200 MWh、RTE 0.88、SOC 10%–90%、期初 0.1、期末回到初值，目标为日前能量净收益最大，退化按 0.03 元/kWh 计入。
4. **AGC 考核复盘**：逐时段算指令需求速率 = |Δ指令| / 15 min，与速率能力比较；精度误差与门槛比较；不合格时段按 |指令| × 时长 × 考核系数积分考核电量。
5. **一次调频考核复盘**：死区内不动作；死区外理论出力 ΔP = −(1/R)·(Δf/f0)·Pn，实际出力受可用功率（峰段上调受限）与性能系数限制；逐事件贡献比 = 实际/理论，低于门槛时按欠贡献电量 × 系数考核。
6. **综合经济性**：考核电费 = 考核电量 × 平段电价（D 级假设）；综合净收益 = 套利净收益 − AGC 考核 − 一次调频考核。

## 4. 合成演示的基准输出（代表日）

| 指标 | 数值 |
|---|---:|
| 充电量 MWh | 341.12 |
| 放电量 MWh | 300.19 |
| 吞吐 MWh | 641.31 |
| 等效循环次数 | 1.603 |
| 充电成本 元 | 51,168.17 |
| 放电收入 元 | 202,625.96 |
| 退化成本 元 | 19,239.23 |
| **能量套利净收益 元/日** | **132,218.56** |
| AGC 考核电费 元 | 0.00 |
| 一次调频考核电费 元 | 618.75 |
| **综合净收益 元/日** | **131,599.81** |

- **套利做了约 1.6 个等效循环**：午间低价段（100 元/MWh）与谷段（200 元/MWh）充电，峰段（900 元/MWh）与平段（450 元/MWh）放电；吞吐 641 MWh，退化 19,239 元已扣。
- **AGC 不触发考核**：最大需求速率 4.16 MW/min 远低于能力 100 MW/min，精度 2% ≤ 门槛 3%。储能响应快，AGC 速率/精度通常合格——考核风险更多来自精度门槛收紧、通信中断或可用率不足，本例不演示这些异常。
- **一次调频在峰段欠贡献**：4 个频率事件中 19:00 的 −0.50 Hz 事件理论需增发 20 MW，但峰段套利放电占用了上调裕度（D 级假设可用 10 MW），实际仅 9 MW，贡献比 45% < 70%，考核电量 (20−9)×0.25×0.5 = 1.375 MWh。

| 时段 | 段 | 频差 Hz | 理论 MW | 实际 MW | 贡献比 | 考核 MWh |
|---|---|---:|---:|---:|---:|---:|
| 05:00 | valley | +0.06 | −2.40 | −2.16 | 90% | 0.000 |
| 10:00 | midday | −0.10 | +4.00 | +3.60 | 90% | 0.000 |
| 19:00 | peak | −0.50 | +20.00 | +9.00 | 45% | 1.375 |
| 21:00 | peak | −0.15 | +6.00 | +5.40 | 90% | 0.000 |

- 聚合贡献比 62.2%（实际 5.04 / 理论 8.10 MWh）低于 70% 门槛，但**考核按逐事件计算**，只有 19:00 一个事件被考核；不能用聚合比一刀切。

## 6. 风格档与指纹

当前风格 `shandong-storage-station-ems-assessment-v1`：日前能量净收益最大化、期末 SOC 回到初值、400 个 SOC 状态；考核复盘独立于能量调度（容量互斥见 `pitfalls.md`）。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `109cd87cce2e`）。比较两次调度时先看指纹：指纹不同，差异首先归因于目标函数或参数；指纹相同，才归因于价格、AGC 指令或频率事件。

换风格的做法：复制 `instance.json` 为 `instance.reserve.json`，把 `primary_freq_peak_available_mw` 调高或给调度加 `reserve_up_mw`，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；复用 `tools/storage.py`（封装 `tools/dispatch.py`），SOC 网格动态规划口径与技能层一致。
- **纳入**：96 点现货电价、储能能量套利、退化成本、AGC 速率/精度考核复盘、一次调频贡献考核复盘、综合净收益。
- **未纳入**：实时市场出清、调频里程竞价、容量拍卖、辅助服务分成结算、AGC 响应时间实测、SOC/功率联合优化、计量点映射与结算对账。
- **不是**：不是并网验收意见，不是考核申诉依据，不是储能投资建议。代表日结果不能直接乘以 365 当年度收益。
- 真实数据放在仓库外，用 `--instance/--out` 指向本地路径；仓库内只保留 D 级合成样例。
