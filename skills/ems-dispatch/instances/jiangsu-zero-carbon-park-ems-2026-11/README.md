# 江苏零碳园区微网 EMS · 2026-11 样板实例

> 本目录是 `skills/ems-dispatch/instances/` 的第一个纵向切片：**一省（江苏）+ 一主体（零碳园区能源运营主体）+ 一个规则版本（国发〔2026〕22号、1082 号，绿电直连仅作边界参照）**。配置改 `instance.json`，数据换 `data/*.csv`，运行 `run.py`，不改代码。
>
> 全部负荷、光伏、电价、需量与排放因子均为 **D 级合成数据**，不对应任何真实园区。

## 1. 一条命令

```bash

python skills/ems-dispatch/instances/jiangsu-zero-carbon-park-ems-2026-11/run.py --check-config

# 合成数据全流程：基线 → 能量套利 → 需量封顶搜索 → 碳指标 → 孤岛校核 → 敏感性
python skills/ems-dispatch/instances/jiangsu-zero-carbon-park-ems-2026-11/run.py --demo

# 换一份配置（数据路径可指向仓库外）
python skills/ems-dispatch/instances/jiangsu-zero-carbon-park-ems-2026-11/run.py \
  --instance /path/to/instance.json --out /path/to/out
```


## 3. 运行逻辑（从输入到复核表）

1. **配置校验**：六个块齐全；每个规则块有 `grade` + `source`；电价满足峰 ≥ 平 ≥ 谷；储能参数、SOC 窗口与孤岛窗口合法。
2. **读数据**：必须 96 点、序号与时间连续；负荷与光伏非负；光伏不超过装机 105%；每点电价必须与该点 `segment` 对应的电价一致。
3. **基线**：无储能、PCC 6 MW、并网不上网；盈余光伏全部弃掉，按分时电价结算电量电费，按峰值计需量电费。
4. **仅能量套利**：投入 2 MW/4 MWh 储能，PCC 仍为 6 MW，目标只有电量成本；用于暴露“套利抬高峰值”的问题。
5. **需量封顶搜索**：对 6,000 / 5,500 / 5,000 / 4,800 / 4,600 / 4,500 kW 六个 PCC 上限逐一调度，按“电量 + 需量 + 退化”选总成本最低者；不可行候选记录原因。
6. **碳核算**：排放 = 下网电量 × 电网因子；单位能耗碳排放 = 排放 ÷ (负荷电量 × 0.1229 tce/MWh)；同时给出 tCO2/MWh，避免两种口径混用。
7. **孤岛校核**：保安负荷 = 负荷 × 20%；可用能量 = 储能可用电量（3,000 kWh）+ 窗口内光伏 × 90% 可用率；按 10% 备用率判断白天 / 夜间是否可行。
8. **敏感性**：需量单价 30 / 50 元时基线与封顶情景同价重算；光伏 −10% 时基线与封顶情景同幅重算。

## 4. 合成演示的基准输出（代表日）

| 指标 | 基线（无储能） | 仅能量套利 | 需量封顶 4,500 kW |
|---|---:|---:|---:|
| 下网电量 MWh | 62.28 | 60.86 | 60.73 |
| 弃光 MWh | 2.20 | 0.00 | 0.00 |
| 峰值 kW | 5,400 | 5,990 | 4,498 |
| 电量电费 元 | 38,100 | 33,767 | 34,074 |
| 需量电费 元 | 216,000 | 239,600 | 179,906 |
| 退化成本 元 | 0 | 304 | 254 |
| 合计 元/月 | 254,100 | 273,670 | **214,235** |

- **仅能量套利比基线贵 19,570 元/月**：电量省了 4,333 元，但峰值从 5,400 kW 抬到 5,990 kW，需量电费多付 23,600 元。储能不控需量，可能越套越亏。
- **需量封顶 4,500 kW 比基线省 39,866 元/月**：电量 4,026 元 + 需量 36,094 元 − 退化 254 元。
- **单位能耗碳排放**从 2.885 降至 2.813 tCO2/tce（−2.5%），度电排放从 0.3545 降至 0.3457 tCO2/MWh；光伏占负荷从 35.5% 升至 37.8%。
- **减排来自多消纳 2.20 MWh 弃光**，储能本身不产绿电；扣除往返损耗后，下网电量只少 1.55 MWh。

| 孤岛窗口 | 保安负荷需要 MWh | 含备用需要 MWh | 可用能量 MWh | 余量 MWh | 可行 |
|---|---:|---:|---:|---:|---|
| 白天 10:00-14:00 | 3.50 | 3.85 | 19.78 | +15.93 | 是 |
| 夜间 18:00-22:00 | 4.08 | 4.49 | 3.00 | −1.49 | 否 |

- 夜间保安负荷约 1.02 MW、持续 4 h，需要 4.08 MWh；2 MW/4 MWh 储能只有 3.0 MWh 可用，**撑不到 4 小时**。孤岛能力不能按额定容量算。

## 6. 风格档与指纹

当前风格 `zero-carbon-park-ems-demand-cap-v1`：能量成本优先、期末 SOC 回到初值、400 个 SOC 状态、在候选需量上限中选总成本最低者。

`policy` 块规范化 JSON 的 SHA-1 前 12 位作为**风格指纹**写入复核表（当前 `696a22fd40dd`）。比较两次调度时先看指纹：指纹不同，差异首先归因于目标函数或参数；指纹相同，才归因于负荷、光伏或价格。

换风格的做法：复制 `instance.json` 为 `instance.energy-only.json`，把需量候选改成 `[6000]`，用 `--instance` 指向新文件，保留旧文件与旧输出。

## 7. 依赖与边界

- **依赖**：仅 Python 标准库；复用 `tools/microgrid.py`（封装 `tools/dispatch.py`），SOC 网格动态规划口径与技能层一致。
- **纳入**：96 点负荷 / 光伏、分时电价、需量电费、储能能量套利、需量封顶搜索、弃光、退化成本、单位能耗碳排放、孤岛能量平衡。
- **未纳入**：绿电直连 60%/30%/20% 合规认定、专线与防孤岛保护、绿证与碳抵消、园区评价申报、配电网络潮流与电压、需求响应与辅助服务收益。
- **不是**：不是园区评价结论，不是绿电直连合规意见，不是储能投资建议。代表日结果不能直接乘以 365 当年度账单。
- 真实数据放在仓库外，用 `--instance/--out` 指向本地路径；仓库内只保留 D 级合成样例。
