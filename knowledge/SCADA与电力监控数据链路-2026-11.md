# SCADA 与电力监控数据链路：VPP/EMS 的数据底座（2026-11）

> 数据截止：2026-11-09｜定位：知识库笔记，不是技能。调度优化查[储能 EMS](储能EMS优化调度-算法与工程-2026-11.md)与[微网 EMS](微网EMS优化调度-算法与工程-2026-11.md)；市场规则查[电力交易专家](../skills/electricity-trading-expert/SKILL.md)；项目测算查[储能投资与运营专家](../skills/storage-investment-operations/SKILL.md)。

> 用途：SCADA 是 VPP/EMS 的"眼睛和手"——把现场设备状态采上来，把控制指令送下去，并留下可追溯的时标、质量码与审计记录。本文只写数据链路与监控安全，不写调度算法；参数为工程示例，落地以本省规则、设备手册与合同为准。

> 引用纪律：政策与标准标注文号、版本与时点；未核实项写"待核实"；涉及具体站点时，点表、IP、端口、参数一律以现场文件为准。本文不含任何真实站点数据。

## 0. 一页看懂

### 0.1 三句话

1. **SCADA 是数据平面，EMS 是决策平面**：SCADA 负责"采得准、传得稳、控得住、查得到"，EMS 负责"算得优"；两者用点表与数据契约解耦，不能把优化器直接接到设备寄存器上。
2. **四遥不是四个按钮**：遥测、遥信、遥控、遥调各有自己的点表字段、质量码、时标与确认语义；把遥控当普通写入，等于把安全联锁交给网络。
3. **安全分区先于技术选型**：27号令下，储能电站监控、虚拟电厂监控、分布式电源监控都在电力监控系统范围内；公网到生产控制区没有"直连"选项。

┌───────────────┴───────────────────────────▼────────────────
│  安全接入区：代理转发 · 端到端认证 · 不直连生产控制区
└───────────────┬────────────────────────────────────────────

这张图只回答"谁在哪里、走哪条路"，不回答"优化怎么算"。VPP 的预测、报价、调度模型在管理信息区或安全接入区运行；真正碰一次设备的控制指令，必须穿过安全边界进入生产控制区，或在安全接入区完成代理与认证后受控转发。边缘侧与云端两种部署形态的职责差异见 1.5、1.6 节。

| 层级 | 典型设备或软件 | 主要职责 | 不该放什么 |
|---|---|---|---|
| 现场设备层 | 测控、保护、关口表、BMS、PCS、逆变器、充电桩、PLC | 采样、执行、保护、就地联锁 | 跨站调度逻辑、市场报价 |

| 生产控制区 | SCADA 前置、实时库、历史库、告警、HMI、AGC/AVC | 实时监视、控制下发、SOE、审计 | 公网服务、办公应用、邮件 |
| 安全接入区 | 接入网关、代理、认证、加密 | 外部资源接入、代理转发、端到端认证 | 直接控制、通用网络服务 |
| 管理信息区 | VPP 云平台、EMS 优化、交易、结算、看板 | 预测、优化、申报、对账、经营分析 | 实时控制、保护定值 |
| 外部主体 | 调度主站、交易中心、计量主站、第三方聚合商 | 计划、结算、考核、计量 | 绕过边界直连现场 |

### 0.4 与相邻系统的边界

| 系统 | 主要回答 | 与 SCADA 的接口 | 本文是否展开 |
|---|---|---|---|
| SCADA | 现在是什么状态、能不能控 | 点表、实时库、历史库、告警 | 是 |
| EMS 优化调度 | 下一时段怎么发、怎么充放 | 读 SCADA 数据，写功率/SOC 计划 | 只写接口，不写算法 |
| DCS | 厂内过程闭环控制 | 网关或硬接线，通常不跨广域 | 否 |
| PLC | 设备/产线逻辑控制 | Modbus、OPC UA、硬接线 | 只写协议 |
| RTU | 站端采集与转发 | 104、Modbus、DL/T 476 | 是 |
| 计量主站 | 结算电量与费率 | 专用计量通道，不经 SCADA | 只写边界 |
| 调度主站 | 电网运行与考核 | 104、DL/T 476、纵向加密 | 是 |
| 交易平台 | 申报、出清、结算 | API/文件，不直接控制设备 | 只写边界 |
| 碳/能耗平台 | 碳排放与能耗核算 | 读历史数据或报表 | 否 |

### 0.5 适用与不适用

| 适用 | 不适用 |
|---|---|
| VPP/EMS 的点表设计与数据契约 | 通用 SCADA 教材式的全领域铺陈 |
| 储能站、微网、分布式电源的监控链路 | 保护定值整定与电磁暂态仿真 |
| 104/61850/Modbus/MQTT 选型与联调 | 芯片、操作系统与数据库内核实现 |
| 采集频率、时延、对时与历史库设计 | 电力市场出清算法与报价策略 |
| 电力监控安全分区、接入与等保 | 渗透测试操作步骤与攻击手法 |
| 监控系统验收、运维与故障排查 | 具体厂商产品的采购与比价 |

## 1. 数据链路全景

### 1.1 一条遥测的旅程

一条遥测从现场到看板，通常要过七道关：

1. **传感/变送**：CT/PT、温度、SOC、开关位置等转成电信号或数字量；
2. **采集装置**：测控、RTU、BMS、PCS 按扫描周期采样，形成原始值；
3. **边缘处理**：滤波、标度变换、死区判断、打时标、加质量码；
4. **通信**：104/61850/Modbus/MQTT 把数据送到前置或云平台；
5. **前置处理**：解帧、点表映射、合法性检查、双通道去重；
6. **实时库**：写当前值、时标、质量码，触发告警与计算点；
7. **历史库与应用**：压缩入库、报表、优化模型、结算对账。

每一道关都可能改变数值的含义。**点表错一个变比，后面所有优化和考核都错**；时标错一个时区，SOE 顺序就会反过来。数据链路的第一原则不是"快"，而是"每个数都能追到来源"。

### 1.2 一条控制指令的闭环

```
EMS/VPP 决策
   │ ① 生成指令：目标值、时限、指令ID、权限
   ▼
指令网关 / 边缘代理
   │ ② 鉴权、限幅、互锁、有效期校验
   ▼
站控 / 设备控制器
   │ ③ 选择-执行（SBO）或直接执行
   ▼
PCS / BMS / 逆变器 / 充电桩
   │ ④ 执行，回读实际值
   ▼
SCADA 实时库 ◀── ⑤ 遥测/遥信确认 ── 现场
   │
   ▼
历史库 + 审计日志 + 考核/对账
```

控制链路的每一环都要有**明确回执**：谁发的、发给谁、发的是什么、什么时候失效、设备有没有执行、执行后的实际值是多少。没有回执的"成功"等于没有执行；只有下发没有回读，等于把控制变成了广播。

### 1.3 五条链路

| 链路 | 关键问题 | 关键指标 | 常见断点 |
|---|---|---|---|
| 采集链路 | 采得到、采得准 | 完整率、正确率、时延 | 点表错、变比错、网关单点 |
| 控制链路 | 控得动、控得对 | 下发成功率、回读一致率、时延 | 权限、互锁、超时、无回执 |
| 对时链路 | 所有时标同一把尺 | 对时误差、守时能力 | 无 GPS、NTP 漂移、时区错 |
| 历史链路 | 查得到、查得全 | 入库完整率、保留期、可追溯 | 压缩过度、磁盘满、补数丢失 |
| 安全链路 | 进不来、出不丢 | 边界合规、审计完整、告警闭环 | 直连、弱口令、无监测 |

### 1.4 时间尺度

| 环节 | 典型时间尺度 | 关注点 |
|---|---|---|
| 保护/就地联锁 | 毫秒级 | 不依赖 SCADA，SCADA 只记录 |
| GOOSE/快速报文 | 毫秒级 | 网络优先级、订阅关系、测试模式 |
| SOE | 1 ms 分辨率 | 对时精度、时标来源、事件顺序 |
| 遥测刷新 | 1–15 s | 扫描周期、死区、通信带宽 |
| AGC/AVC | 秒级 | 指令周期、调节速率、闭锁 |
| EMS 经济调度 | 5–15 min | 预测、SOC、市场计划 |
| 市场申报 | 15 min 或更粗 | 交易规则、计量口径 |
| 结算 | 月/周期 | 关口表、对账、考核 |

按部署重心，工程上常把 SCADA 分成边缘侧与云端两种形态。先说结论：**SCADA 是功能定义，不是按位置划分的两类标准系统**；"边缘 SCADA""云 SCADA"是工程与市场叫法，不是 IEC/国标的正式分类。判断一套系统是不是 SCADA，看它是否具备采集、监视、控制、告警、历史与审计能力，而不是看机柜放在哪里。两种形态通常是云边协同，而不是二选一；安全分区细节见 §8.3。

### 1.5 边缘侧 SCADA（站控/设备侧）

**定位**：部署在站控层或设备侧，直接对接 PCS、BMS、逆变器、充电桩、PLC 与关口表，是"最后一公里"的采集与控制执行端。典型载体包括站控机、通信管理机、边缘网关、边缘计算节点，以及设备厂商自带的本地监控。

| 维度 | 典型做法 |
|---|---|
| 部署位置 | 站控室、升压站/配电房、设备柜内、边缘机房 |
| 采集周期 | 100 ms–5 s（关键量），SOE 1 ms 分辨率 |
| 控制职责 | SBO 执行、就地联锁、AGC/AVC 执行端、指令回执与回读 |
| 协议 | 104、61850（MMS/GOOSE/SV）、Modbus、OPC UA、DL/T 476 |
| 本地能力 | 本地 HMI、告警、趋势、断网缓存、断点续传、本地历史 |
| 数据保留 | 数天到数月，按容量滚动 |
| 断网行为 | 独立运行，缓存后按原时标补传 |
| 典型时延 | 毫秒到秒级，控制闭环不依赖广域网 |

**典型软硬件组成**：

| 层 | 典型组成 | 关注点 |
|---|---|---|
| 采集与控制 | 站控机、通信管理机、边缘网关、PLC | 多协议接入、双网、SBO、就地联锁 |
| 本地监控 | HMI、一次接线图、告警窗、趋势 | 重启恢复、操作权限、画面与点表一致 |
| 本地历史 | 边缘时序库、嵌入式数据库、文件缓存 | 滚动保留、断点续传、原时标 |
| 对时 | 北斗/GPS 主钟、PTP/NTP、IRIG-B | 守时、失锁告警、时标来源 |
| 站内网络 | 工业交换机、双网/环网、VLAN | 带宽、隔离、共因故障 |
| 供电与环境 | 双电源/UPS、宽温、防尘、看门狗 | 掉电保护、自动恢复 |
| 安全加固 | 加固系统、白名单、证书、审计 | 最小端口、无默认口令、补丁可控 |

**站内网络与冗余**：采集网与控制网分开，至少用 VLAN 隔离；关键链路双网，环网可用 PRP/HSR 或厂商冗余环；前置、网关、交换机、电源都不要共用单点。**双网不是把两根网线插进同一台交换机**：路径、电源、交换设备要独立，否则一条命令就能同时打掉两条"冗余"通道。冗余层级与切换演练见 §7。

**边缘计算该做什么、不该做什么**：

| 适合放在边缘 | 不适合放在边缘 |
|---|---|
| 数据清洗、标度变换、死区、质量码 | 跨站经济调度、市场出清、报价 |
| 就地联锁、SBO、指令校验与回执 | 结算计量、跨租户分析 |
| 断点续传、本地缓存、本地告警 | 替代保护与安全自动装置 |
| 轻量模型推理（异常检测、预测修正） | 全局长期历史与经营报表 |

**容量与保留估算**：

`边缘原始存储 ≈ 点数 × 采样频率 × 单点字节 × 保留秒数`

例：5,000 点、1 次/s、16 B/点、保留 7 天，原始约 48.4 GB；按 5:1 压缩约 9.7 GB，再加 30% 余量。实际按死区后的采样率、压缩率、索引与副本修正。**历史保留空间不能当补数缓存**：断网缓存按 §5.4 单独估算，否则一断网就把历史库写满。

**边缘侧常见反模式**：

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 网关当 SCADA | 只有转发，没有本地监视/控制 | 本地 HMI + 告警 + 联锁 |
| 所有逻辑上云 | 云断或网断即失控 | 控制闭环与联锁留在边缘 |
| 单网关、单电源 | 一挂全盲 | 双机/双通道、双电源 |
| 本地不存历史 | 断网期间数据永久缺失 | 滚动缓存 + 断点续传 |
| 各站点表各一套 | 上层模型反复适配 | 模板化点表 + 版本管理 |
| 远程维护直连 | 绕过安全边界 | 跳板、审批、全程审计 |
| 升级无回滚 | 升级失败现场停摆 | A/B 分区 + 配置备份 + 回滚 |

**验收与演练**：

| 项目 | 方法 | 通过标准 |
|---|---|---|
| 断网补数 | 断开上行 15 min | 原时标补入、不丢不重 |
| 双机/双通道切换 | 杀主、断链 | 切换时间达标、数据不丢 |
| 对时 | 主钟失锁 1 h | 守时误差达标、告警正确、恢复后时标正常 |
| SBO | 选择-执行、拒绝、超时 | 回执、回读、互锁齐全 |
| 点表 | 抽点比对源表/标准源 | 变比、量纲、时标一致 |
| 升级回滚 | 模拟升级失败 | 自动回滚、配置与历史保留 |

**优势**：时延低、断网可用、控制闭环短、数据在站内可控、容易满足生产控制区分区要求。保护与就地联锁本来就不该依赖 SCADA，边缘层只负责监视、执行与记录。

**局限**：算力与存储有限、跨站视图弱、点表与版本容易各站漂移、升级和运维要逐站进行、备件与现场支持成本高。

**适用**：站内实时监视与控制、储能/微网/配电房的本地自治、AGC/AVC 执行端、对断网续传和 SOE 有要求的场景。

**验收重点**：断网 15 min 补数不丢不重、双机/双通道切换、主钟失锁守时、SBO 互锁与超时、点表与现场源一致。

### 1.6 云端 SCADA（云化监控平台）

**定位**：部署在云平台或区域集控中心，面向多站、多租户做集中监视、历史存储、告警聚合、远程运维与开放接口。"云 SCADA"不是标准术语，厂商口径不一，常见叫法还有云集控、集中监控平台、VPP 聚合平台；有的只做监视分析、不承担实时控制，严格说是"云侧监控平台"而不是完整 SCADA。若集控中心承担生产控制，它应按生产控制区（或安全接入区）建设，不能因为叫"云"就放进管理信息区。

| 维度 | 典型做法 |
|---|---|
| 部署位置 | 管理信息区（III/IV）、区域集控中心、云平台 |
| 数据来源 | 边缘网关/前置经隔离装置或安全接入区上行 |
| 主要职责 | 跨站监视、告警聚合与派单、长期历史、报表对账、远程运维、开放 API |
| 数据保留 | 月到年，按时序库/对象存储分层 |
| 扩展方式 | 水平扩容，按点数、流量、租户计费 |
| 断网行为 | 云侧不可用不影响站内自治；恢复后补数 |
| 典型时延 | 秒级到分钟级，受广域网与隔离装置影响 |

**参考分层**：

| 层 | 典型组件 | 职责 |
|---|---|---|
| 接入层 | MQTT Broker、HTTPS API、104/61850 网关、边缘代理 | 认证、限流、协议转换、断链重连 |
| 消息与流处理 | 消息队列、规则引擎、流计算 | 缓冲、去重、乱序处理、水位线 |
| 存储层 | 时序库、对象存储、关系库 | 原始/聚合/元数据分层保留 |
| 模型层 | 资产模型、点表、租户/站点树 | 统一命名、映射与数据血缘 |
| 应用层 | 监视、告警、报表、运维、开放 API | 跨站视图与业务功能 |
| 治理层 | 身份、权限、审计、计量 | 多租户隔离与合规 |

**接入与数据治理约定**：

| 约定 | 要求 | 原因 |
|---|---|---|
| 三级标识 | 租户/站点/设备全局唯一 | 多租户不串数据 |
| 双时标 | 设备时标 + 接收时标 | 判断迟到、乱序与补数 |
| 幂等键 | 设备 ID + 点 ID + 源时标 | 重传不重复入库 |
| 乱序窗口 | 允许迟到 N 分钟，超窗入迟到分区 | 补数可计算、不覆盖新值 |
| 质量码透传 | Good/Invalid/Questionable 等不丢 | 云端不把坏点当真好 |
| 补数去重 | 原时标 + 版本号 + 去重窗口 | 断网恢复不重复 |
| 点表版本 | 边缘与云端同版本、变更留痕 | 映射不漂移 |

**多租户与权限**：租户可用逻辑隔离（`tenant_id`）或物理隔离（独立库/集群）；关键客户、生产控制类业务优先独立实例。权限至少做到"角色 + 数据范围"（站点/设备/点），控制类操作双人复核；登录、查询、导出、配置、指令全留痕。数据存放地域、跨境限制与导出审批要在合同里写清。

**SLA 与合同条款**：

| 条款 | 建议写法 | 备注 |
|---|---|---|
| 可用性 | 月度 99.9%/99.95%，明确计划维护窗口 | 不要只写"高可用" |
| 时延 | P95/P99，注明"网关出口到云入库" | 含隔离装置与公网段 |
| 完整率 | ≥99.5%，按点按日统计 | 与补数规则一起约定 |
| RPO/RTO | 如 15 min / 4 h | 与备份、切区演练一致 |
| 数据归属 | 归客户，服务商仅受托处理 | 含衍生数据与备份 |
| 导出与退出 | 标准格式、全量导出、过渡期 | 避免厂商锁定 |
| 故障通知 | 15 min 内通报、根因报告时限 | 含第三方云与网络 |
| 分包与跨境 | 提前告知、书面同意 | 不得默认 |

**容量与成本估算**：

`云端原始存储 ≈ 点数 × 采样频率 × 单点字节 × 保留秒数 × 副本数`

例：50,000 点、0.2 次/s、32 B/点、保留 1 年，原始约 10.1 TB；按 5:1 压缩约 2 TB，双副本约 4 TB，再加索引与元数据。按量计费还要算上行流量、API 调用、告警短信、长期归档与跨区复制。**先把"点数 × 频率 × 保留"算清，再谈单价**。

**云端常见反模式**：

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 云直连设备/公网 Broker | 违反分区与边界要求 | 边缘网关 + 安全接入区 |
| 只做看板不做治理 | 数据不可信、无法对账 | 点表、质量码、血缘、补数 |
| 多租户共用点表 | 串数据、越权 | 租户隔离 + 数据范围权限 |
| 无幂等、无补数 | 断网后重复或缺失 | 幂等键 + 水位线 + 原时标 |
| 把云当唯一副本 | 云故障全丢 | 边缘保留 + 异地备份 |
| 无退出条款 | 数据被锁定 | 标准导出 + 过渡期 |
| 忽略隔离装置时延 | SLA 不达标 | 端到端口径含隔离与公网 |

**选型决策**：

| 场景 | 推荐形态 | 关键理由 | 不能做什么 |
|---|---|---|---|
| 单站实时控制（储能/微网/配电房） | 边缘为主，云可选 | 断网自治、低时延 | 云不能替代本地联锁 |
| 多站集中监视与运维 | 云为主 + 边缘网关 | 跨站视图、集中运维 | 云不直控设备 |
| VPP 聚合、预测与交易 | 云平台 + 安全接入区 | 聚合、分析、申报 | 不绕过安全边界 |
| 生产控制云化/集控中心 | 生产控制区私有云/集控 | 合规、可控 | 不能放管理信息区 |
| 只做数据服务与报表 | 云侧监控平台 | 成本低、接口开放 | 不称完整 SCADA |

**云边故障演练**：

| 演练 | 方法 | 通过标准 |
|---|---|---|
| 上行中断 30 min | 断网后恢复 | 边缘自治、补数不丢不重 |
| 云区域故障 | 切备区/降级运行 | 站内不受影响、RTO 达标 |
| Broker 过载 | 压测与限流 | 关键告警不丢、背压可控 |
| 时钟跳变 | 改边缘时钟/主钟失锁 | 时标不倒退、告警正确 |
| 证书过期 | 短期证书轮换 | 提前告警、轮换不中断 |
| 租户误配 | 越权访问测试 | 拒绝并留痕 |

**优势**：跨站统一视图、弹性存储与算力、集中升级与运维、开放接口便于接 EMS/VPP/交易/碳平台、多租户与权限体系成熟。

**局限**：依赖广域网，P95/P99 时延和抖动不可控；不能把实时控制闭环放在云上；安全边界与合规要求高；数据主权、跨租户隔离、云厂商锁定和按量计费都要提前算清。

**适用**：多站聚合监视、经营分析与报表、远程运维、历史数据服务、EMS/VPP 的预测与优化、非实时指令的计划与下发（经受控通道）。

**验收重点**：边缘断网时站内自治、补数去重、跨租户隔离、越权访问、API 限流与审计、云侧故障演练。

**两者怎么分工**：

| 维度 | 边缘 SCADA | 云端 SCADA |
|---|---|---|
| 部署位置 | 站控/设备侧 | 管理信息区/集控中心 |
| 实时性 | 毫秒–秒 | 秒–分钟 |
| 断网可用 | 站内自治 | 不承担站内实时控制 |
| 控制职责 | 执行、互锁、回执、回读 | 生成目标与约束，指令经受控通道 |
| 数据保留 | 数天–数月 | 月–年 |
| 扩展方式 | 逐站扩容 | 水平扩容、多租户 |
| 安全边界 | 生产控制区/边缘 | 管理信息区/安全接入区 |
| 典型成本 | 现场设备与运维 | 云资源、流量、订阅 |
| 适用场景 | 实时监视与控制 | 跨站聚合、分析、运维 |

**云边协同三条铁律**：

1. **控制闭环留在边缘**：云侧只给目标值、约束和计划，SBO、互锁、超时、回执、回读在站内完成；
2. **云不直连设备**：任何云端指令都要经安全接入区或生产控制区，带指令 ID、权限、有效期与审计；
3. **边缘能独立运行**：云故障、广域网中断时站内不受影响，恢复后按原时标补数并去重。

## 2. 点表：SCADA 的合同

### 2.1 对象模型

点表不是一张 Excel，而是"站—间隔—设备—测点"的对象模型。推荐至少四层：

```
区域/聚合商
  └─ 场站（储能站、微网、充电站、分布式光伏）
       └─ 间隔/设备（1# 储能单元、PCS、BMS、关口表）
            └─ 测点（遥测、遥信、遥控、遥调、遥脉）
```

对象模型的价值在于：当设备增容、改名或更换通信地址时，只改一层映射，不用修改上层优化模型和报表公式。

### 2.2 四遥与遥脉

| 类型 | 方向 | 典型量 | 关键字段 | 常见错误 |
|---|---|---|---|---|
| 遥测 | 上行 | 功率、电压、电流、SOC、温度、频率 | 量纲、变比、死区、时标、质量码 | 把 kW 当 W、把百分比当小数 |
| 遥信 | 上行 | 开关位置、保护动作、告警、运行状态 | 单点/双点、取反、抖动抑制 | 双点遥信压成布尔，丢失中间态 |
| 遥控 | 下行 | 分合闸、启停、复位 | 选择-执行、超时、回执、互锁 | 直接执行、无回读、无权限校验 |
| 遥调 | 下行 | 功率目标、电压目标、SOC 上限 | 目标值、爬坡率、有效期、回执 | 把遥调当遥测写、无变化率限制 |
| 遥脉 | 上行 | 电度脉冲、累计电量 | 脉冲常数、累计清零、时标 | 把脉冲当瞬时功率、清零未记录 |

### 2.3 点表最小字段集

| 字段 | 说明 | 示例 |
|---|---|---|
| 点 ID | 全局唯一、永不复用 | `ESS01.PCS01.P_AC` |
| 点名 | 人中英文可读名称 | `1#PCS 交流侧有功` |
| 对象路径 | 站/间隔/设备 | `ESS01/BAY01/PCS01` |
| 类型 | AI/DI/AO/DO/Pulse | `AI` |
| 协议地址 | 104 IOA、61850 引用、Modbus 寄存器 | `IOA=1001` |
| 量纲 | kW、kVar、V、A、℃、% | `kW` |
| 变比/偏移 | 工程值 = 原始值 × 变比 + 偏移 | `0.1 / 0` |
| 死区 | 归档死区与告警死区分开 | `1 kW / 5 kW` |
| 扫描周期 | 采集与上报周期 | `5 s` |
| 时标来源 | 设备时标/网关时标/前置时标 | `设备` |
| 质量码映射 | 协议位到统一质量枚举 | `IV→Invalid` |
| 告警阈值 | 高/低/高高/低低、延时 | `> 1.1 MW 持续 10 s` |
| 归档标志 | 是否入历史库、压缩方式 | `是/旋转门` |
| 控制权限 | 谁可写、是否需双人复核 | `调度/运维` |
| 关联计算点 | 派生点公式与版本 | `SOC_avg = ...` |

### 2.4 命名与点号

- **稳定**：点 ID 一旦投运不改；设备改名只改显示名；
- **唯一**：跨站、跨协议不重复；不把 IP 或寄存器地址当点 ID；
- **可读**：人能看懂对象路径，机器能解析；
- **不复用**：退役点保留并标记 `retired`，不复用给新设备；
- **可版本化**：点表有版本号、生效时间、变更记录与回滚方案。

### 2.5 变比、量纲与死区

工程值换算：

```
工程值 = 原始值 × 变比 + 偏移
```

三个常见坑：

1. **CT/PT 变比重复**：设备已经按一次值输出，网关又乘了一次变比；
2. **单位混用**：kW 与 W、kWh 与 MWh、百分比与小数混在一张表里；
3. **死区过大**：为了省带宽把死区设成量程的 5%，小功率变化全被吃掉，考核时"没有数据"。

死区至少分三种：**采集死区**（设备上报）、**归档死区**（历史库存储）、**告警死区**（阈值判断）。三者目的不同，不能共用一个值。

### 2.6 质量码

| 统一质量 | 含义 | 常见来源位 | 处理建议 |
|---|---|---|---|
| Good | 有效 | 无异常 | 正常使用 |
| Invalid | 无效 | IV、故障、超量程 | 不参与优化与考核 |
| Questionable | 可疑 | 抖动、通信质量差、替代值 | 标记并人工复核 |
| Substituted | 人工替代 | 手动置数、调试 | 记录操作人、原因、时限 |
| Test | 测试 | 调试/检修 | 不进入结算与考核 |
| Blocked | 闭锁 | 联锁、检修 | 保留原值并说明 |
| Overflow | 溢出 | 量程溢出、计数器翻转 | 检查变比与量程 |

质量码必须**端到端保留**。很多系统在网关处把质量码丢掉，到了 EMS 只剩一个数；优化器无法区分"0 MW"和"通信中断"，会把断线当成真实零功率。

### 2.7 双点遥信与中间态

双点遥信有四种状态：`00` 中间态、`01` 分、`10` 合、`11` 故障。把双点压成布尔，会同时丢掉"中间态"和"故障态"：

- 开关操作过程中的中间态是正常的，不应立即告警；
- `11` 通常表示辅助触点故障或接线错误，应告警；
- 双点取反要在点表里配置，不要在显示层临时取反。

### 2.8 点表核对清单

- [ ] 每个点有唯一 ID、对象路径、协议地址和量纲；
- [ ] 变比、偏移、CT/PT 只乘一次，抽点与现场表计核对；
- [ ] 双点遥信、取反、抖动抑制已配置；
- [ ] 质量码从设备到实时库全链路保留；
- [ ] 遥测死区、归档死区、告警死区分别设置；
- [ ] 遥控/遥调有权限、互锁、超时、回执与回读；
- [ ] 点表版本、生效时间、变更人、回滚方案齐全；
- [ ] 退役点标记 `retired`，未复用；
- [ ] 计算点有公式、输入点、版本与责任人。

## 3. 协议选型

### 3.1 一张选型表

| 协议 | 典型场景 | 传输 | 时标 | 质量码 | 控制语义 | 安全 | 不该用在哪 |
|---|---|---|---|---|---|---|---|
| IEC 60870-5-104 | 调度/站端远动 | TCP/IP，常用 2404 | CP56Time2a | 有 | 遥控/遥调、选择-执行 | 本身不加密，靠 TLS/VPN/62351 | 设备内部寄存器级 |
| IEC 61850 | 变电站、DER、微网 | MMS/TCP、GOOSE、SV | 有 | 有 | 控制模型、SBO | 靠网络隔离与 62351 | 跨公网直连 |
| Modbus RTU/TCP | 设备级、仪表、PLC | 串口/ TCP 502 | 通常无 | 通常无 | 寄存器写 | 无内建认证/加密 | 广域调度、公网 |
| MQTT | 云边遥测、聚合商平台 | TCP/TLS，常用 1883/8883 | 载荷自定义 | 载荷自定义 | 应用层确认 | TLS、用户名/证书、ACL | 毫秒级闭锁、保护 |
| OPC UA | 工业互联网、楼宇、工厂 | TCP/HTTPS | 有 | 有 | 方法调用/写 | 证书、签名、加密 | 简单电表轮询 |
| DL/T 476 | 调度主站间 | 专用通道 | 有 | 有 | 调度数据 | 专用网络 | 设备级 |
| CIM (61970/61968) | 模型交换 | 文件/服务 | 不适用 | 不适用 | 不适用 | 按传输通道 | 实时控制 |

### 3.2 IEC 60870-5-104

**定位**：IEC 60870-5-101 的 TCP/IP 传输映射，国内调度与站端远动最常用的协议之一。默认 TCP 端口 2404。

**报文结构**：APCI（启动/停止/测试/确认）+ ASDU。ASDU 里最关键的四件事：

- **类型标识**：遥测、遥信、遥控、遥调、总召、对时等；
- **传送原因**：周期、突发、总召、命令确认、激活终止等；
- **公共地址**：站地址；
- **信息对象地址（IOA）**：点号，3 字节。

常用类型标识（只列最常见）：

| 类型 | 含义 |
|---|---|
| M_SP_NA_1 / M_SP_TB_1 | 单点遥信 / 带时标单点遥信 |
| M_DP_NA_1 / M_DP_TB_1 | 双点遥信 / 带时标双点遥信 |
| M_ME_NA_1 / M_ME_NB_1 / M_ME_NC_1 | 归一化/标度化/浮点遥测 |
| M_ME_TD_1 / M_ME_TE_1 / M_ME_TF_1 | 带时标遥测 |
| C_SC_NA_1 / C_DC_NA_1 | 单点/双点遥控 |
| C_SE_NA_1 / C_SE_NB_1 / C_SE_NC_1 | 归一化/标度化/浮点遥调 |
| M_EI_NA_1 | 初始化结束 |

**链路参数**：标准给出 k/w 与 t0–t3 的缺省值（k=12、w=8、t0=30 s、t1=15 s、t2=10 s、t3=20 s），工程上按通道质量与设备能力调整，但必须两侧一致。k 是未确认 I 帧上限，w 是收到多少帧后必须确认；t1 是发送/测试超时，t2 是无数据时的确认超时，t3 是空闲测试周期。

**工程要点**：

- 启动后先总召，再按组召/周期上送；总召期间的数据要防止重复入库；
- 遥控优先用**选择-执行**，直接执行只用于明确允许的场景；
- 命令要有超时、回执、激活终止与回读确认；
- CP56Time2a 是**本地时间**且带夏令时标志位，跨时区/跨系统要统一换算；
- 104 本身不提供加密与强身份认证，公网或跨区必须叠加 TLS/VPN/IEC 62351 或安全接入区；
- 双通道运行时，前置要去重、判活、防止双通道同时下发。

### 3.3 IEC 61850

**定位**：变电站自动化与 DER 通信的对象模型标准，国内等同采用为 DL/T 860 系列。它不是"寄存器表"，而是"有语义的模型"。

**三套通信映射**：

- **MMS**：客户端/服务器，用于监视、控制、报告、定值；
- **GOOSE**：发布/订阅，快速报文，用于跳闸、联锁、状态互锁；
- **SV**：采样值，用于电流/电压采样。

**模型层次**：IED/Server → Logical Device → Logical Node → Data Object → Data Attribute。工程上通过 SCL 文件（ICD/CID/SCD）交换模型，再绑定通信参数。

**控制模型**：直接控制、选择-执行（SBO）、增强型选择-执行等；控制对象有 `Oper`、`SBOw`、`Cancel` 等结构，必须按模型而不是按寄存器地址操作。

**工程要点**：

- ICD/CID/SCD 版本必须与现场装置一致，改模型要重新联调；
- GOOSE 依赖 VLAN 优先级与订阅关系，交换机配置错误会导致"信号发了但没人收"；
- GOOSE/SV 的测试模式要显式标记，检修测试不能误动；
- 61850 的时间戳通常是 UTC，显示层再转本地时区；
- DER 场景可参考 IEC 61850-90-7 的对象模型，但别把"模型支持"当成"设备已实现"。

### 3.4 Modbus

**定位**：设备级寄存器通信，简单、便宜、生态广。RTU 走串口，TCP 常用 502 端口。

**常用功能码**：

| 功能码 | 用途 |
|---|---|
| 01 / 02 | 读线圈 / 读离散输入 |
| 03 / 04 | 读保持寄存器 / 读输入寄存器 |
| 05 / 06 | 写单线圈 / 写单寄存器 |
| 15 / 16 | 写多线圈 / 写多寄存器 |

**局限**：

- 没有标准时标、质量码、事件顺序；
- 没有内建身份认证与加密；
- 寄存器语义靠厂商手册，字节序/字序可能不同；
- 轮询模式，点数多时延线性上升；
- 写寄存器没有"选择-执行"语义，安全联锁要在网关/控制器做。

**结论**：Modbus 适合"设备 → 网关"的最后一段，不适合"站 → 调度"的广域链路，更不应把 502 端口暴露到公网。

### 3.5 MQTT

**定位**：发布/订阅消息协议，适合云边遥测、聚合商平台、海量分布式资源接入。常用 1883（明文）/8883（TLS）。

**关键机制**：

- **Broker**：消息中转，主题（topic）分层；
- **QoS 0/1/2**：最多一次/至少一次/恰好一次（ broker 与客户端之间，不是端到端业务确认）；
- **Retained**：保留最后一条消息，适合状态量；
- **LWT**：遗嘱消息，客户端掉线时由 broker 发布；
- **Session**：持久会话与离线消息。

**工程要点**：

- QoS 2 不等于"控制可靠"：端到端要有指令 ID、应用层 ACK、幂等与回读；
- 主题设计要能按站/设备/点分层，ACL 要限制到最小范围；
- 载荷要带 schema 版本、时标、质量码、设备 ID；
- 离线队列要有上限与过期策略，避免恢复后"补发一堆过期指令"；
- Broker 要做认证、TLS、审计与限流；匿名 Broker 等于公开的控制面板。

### 3.6 OPC UA、DL/T 476 与 CIM

- **OPC UA（IEC 62541）**：带信息模型、订阅、证书与加密的工业互联协议，适合工厂、楼宇、园区设备集成；比 Modbus 重，但语义和安全更完整。
- **DL/T 476**：国内电力系统实时数据通信应用层协议，主要用于调度主站之间；具体版本与互操作细则以现行标准和两侧系统为准。
- **CIM（IEC 61970/61968）**：电网模型交换标准，用于模型拼接、图模维护，不是实时遥测协议。
- **IEC 62351**：电力系统通信安全系列标准，给 104、61850 等协议提供 TLS、端到端安全与证书体系；"加个密码"不等于满足 62351。

### 3.7 协议网关的五个坑

1. **点表漂移**：网关配置改了，SCADA 点表没改，数据错位；
2. **时标翻译**：源协议无时标，网关用"收到时间"代替"事件时间"；
3. **质量丢失**：源协议有质量位，网关映射时丢掉；
4. **控制语义错位**：源协议是"写寄存器"，目标协议是"选择-执行"，直接映射会绕过互锁；
5. **网关单点**：所有协议、所有站共用一个网关，网关一挂全盲。

## 4. 采集频率、时延与时间同步

### 4.1 采样、上报与存储

三个周期要分开：

- **采样周期**：设备内部采样，毫秒到秒；
- **上报周期**：通信上送，秒到分钟；
- **存储周期**：历史库落盘，秒到分钟，或按死区压缩。

"采集频率 1 s"不等于"历史库 1 s 一个点"，也不等于"EMS 1 s 更新一次"。合同里必须写清是哪一个周期。

### 4.2 时延预算

下表是工程示例（D 级），用于说明分解方法，不是标准限值：

| 环节 | 示例目标 | 说明 |
|---|---|---|
| 设备采样到出口 | ≤ 200 ms | 采样、滤波、打包 |
| 网关处理 | ≤ 200 ms | 协议转换、点表映射 |
| 通信传输 | ≤ 200 ms | 专网/专线；公网另计 |
| 前置处理 | ≤ 100 ms | 解帧、去重、入库 |
| 实时库到应用 | ≤ 1 s | 计算点、告警、推送 |
| 控制下发到回读 | ≤ 5 s | 含鉴权、互锁、执行、回读 |

端到端时延要按**测量点**定义：从设备采样时刻到实时库可读，还是从指令发出到收到执行回执。两者不能混为一个"系统时延"。

### 4.3 时延指标怎么写进合同

- 写 **P50 / P95 / P99**，不写"平均时延"；
- 写测量点、测量方法、负载条件、统计窗口；
- 写超时判定与补数/重传规则；
- 写控制链路的**回执时限**与失败处理；
- 写验收时的最大并发点数和背景流量。

只写"平均小于 1 秒"的合同，在告警风暴或大批量总召时会失效。

### 4.4 时钟同步

| 方式 | 典型精度 | 适用 | 注意 |
|---|---|---|---|
| 北斗/GPS + 1PPS | 微秒级 | 站端主时钟、SOE | 天线、馈线、防雷、守时 |
| PTP (IEEE 1588) | 亚微秒到微秒 | 61850、采样值、站控 | 交换机需支持透明时钟 |
| IRIG-B | 微秒级 | 电力系统传统对时 | 编码/解码、通道延时 |
| NTP | 毫秒级 | 服务器、通用设备 | 无 GPS 时漂移大，难保 1 ms SOE |
| 手动对时 | 不可控 | 仅调试 | 不能用于生产 |

**四条纪律**：

1. **存储统一 UTC，显示转本地**；跨时区系统不要存本地时间；
2. **CP56Time2a 是本地时间**，61850 时间戳通常是 UTC，转换要显式；
3. **时钟跳变要检测**：发现大步长回跳，标记数据质量并记录，不用错误时标回填；
4. **对时质量要入点表**：主时钟失锁、偏差超限、天线故障都要告警。

### 4.5 数据质量指标

```
完整率 = 有效采样点数 / 应采样点数 × 100%
正确率 = 与参考源一致的点数 / 抽检点数 × 100%
及时率 = 在时限内到达的点数 / 应到达点数 × 100%
可用率 = MTBF / (MTBF + MTTR) × 100%
```

| 可用率 | 年停机时间（约） |
|---|---|
| 99.9% | 8.76 小时 |
| 99.99% | 52.6 分钟 |
| 99.999% | 5.26 分钟 |

"数据可用率 99.9%"听起来很高，但一年仍有近 9 小时；对按 15 分钟结算的考核，足以丢掉几十个时段。指标要和业务后果一起看。

### 4.6 常见时标错误

- 用服务器收到时间代替设备事件时间，SOE 顺序失真；
- 服务器本地时间与设备时间不一致，跨时区/夏令时错一小时；
- NTP 只对服务器不对设备，设备时标漂移；
- 时钟回跳后继续写入，历史曲线出现"负时间"；
- 总召数据不带原时标，全部盖成入库时间；
- 测试环境与生产环境共用时钟源，测试数据污染生产。

## 5. 实时库、历史库与数据治理

### 5.1 实时库

实时库保存"当前值 + 时标 + 质量码 + 人工置数标志 + 闭锁标志"。它服务的是秒级监视、告警、控制联锁和计算点，不是长期存储。

设计要点：

- 按扫描类组织点表，避免所有点同一周期；
- 计算点要有依赖关系与计算顺序，避免循环依赖；
- 人工置数、强制、闭锁要显式标记并审计；
- 实时库重启后能从历史库/设备快速恢复，不把"0"当初始值。

### 5.2 历史库

历史库保存时间序列，服务于报表、优化、考核、结算对账和审计。选型关注：

| 维度 | 要问的问题 |
|---|---|
| 写入吞吐 | 峰值多少点/秒，总召/补数时会不会丢 |
| 压缩方式 | 死区、旋转门、差值压缩，是否可还原 |
| 保留期 | 原始/分钟/小时/日报各留多久 |
| 查询性能 | 单站一年曲线、跨站聚合的响应 |
| 补数能力 | 断网恢复后能否按原时标补入 |
| 审计 | 谁改了点表、谁置了数、谁导出了数据 |
| 容灾 | 双机/副本/备份，RPO/RTO 是多少 |

### 5.3 压缩与死区

历史库常用死区/旋转门压缩。压缩会丢细节，因此：

- **结算、考核、事故分析**用的点，保留原始采样或可审计的压缩参数；
- **趋势监视**用的点，可以用较大死区；
- 压缩参数变更要版本化，否则同一份报表前后不可比；
- 不要拿压缩后的曲线反推电量，再拿去和关口表对账。

### 5.4 补数与断点续传

边缘网关/RTU 应具备本地缓存与断点续传：

```
缓存容量 ≈ 点数 × 每秒采样次数 × 单条字节数 × 断网时长
```

示例（D 级）：5,000 点、5 s 扫描、单条 32 B、断网 15 min：

```
5,000 × 0.2 × 32 × 900 ≈ 28.8 MB
```

补数规则要写清：

- 补数数据的时标用**原采样时标**，不用补传时间；
- 重复数据按"设备+点+时标"去重；
- 迟到数据有水位线（watermark），超过窗口不再入实时库，只入历史；
- 补数不能覆盖人工置数/检修标记，冲突要告警。

### 5.5 数据血缘

每个进入报表/结算/考核的数字，应能回答：

1. 来自哪个点、哪台设备、哪个协议地址；
2. 经过哪些计算点、公式版本是什么；
3. 时标是设备时标还是入库时标；
4. 有没有人工置数、补数、压缩；
5. 谁在什么时候改过点表或参数。

没有数据血缘，出现争议时只能"信系统"，无法自证。

### 5.6 数据治理清单

- [ ] 点表、计算点、报表公式均有版本与责任人；
- [ ] 实时库与历史库的时标、质量码语义一致；
- [ ] 压缩参数变更留痕，结算点保留原始数据；
- [ ] 补数、去重、迟到数据处理规则已文档化；
- [ ] 数据导出有审批与审计；
- [ ] 历史库容量与保留期按业务后果测算，不按磁盘剩余空间拍脑袋。

## 6. 告警与运行监视

### 6.1 告警分级

| 级别 | 示例 | 响应目标（示例） | 通知方式 |
|---|---|---|---|
| P1 紧急 | 保护动作、火灾、母线失压、通信全断 | 立即 | 声光 + 短信/电话 |
| P2 重要 | 单体过压、PCS 故障、SOC 越限 | 5–15 min | 声光 + 消息 |
| P3 一般 | 风扇故障、通信抖动、温差偏大 | 1 h | 消息/工单 |
| P4 提示 | 维护提醒、证书到期、磁盘将满 | 当日 | 看板/日报 |

分级不是按"严重"两个字拍脑袋，而是按**后果 × 概率 × 可探测性**定，并与运维SLA、备件、值班安排对齐。

### 6.2 告警风暴与抑制

ISA 18.2 给了一个常用设计参考：一名操作员在 10 分钟内处理约 10 条告警。超过这个量级，告警就从"提醒"变成"噪声"。

常用抑制手段：

- **抖动抑制**：短时反复动作合并为一条；
- **因果抑制**：上级故障时抑制下属派生告警；
- **首出（first-out）**：保留第一个原因，后续标为衍生；
- **检修模式**：设备检修期间屏蔽已知告警，但要有到期时间；
- **搁置（shelving）**：人工临时搁置，必须记录原因与到期时间；
- **分层聚合**：站级/设备级/点级分级展示，默认只看站级。

### 6.3 告警生命周期

```
检测 → 播报 → 确认 → 派单 → 处理 → 恢复 → 关闭 → 复盘
```

每一环要有时间戳、责任人、处理记录。只"报"不"闭环"的告警系统，最后一定被静音。

### 6.4 事件与告警的区别

- **事件（Event/SOE）**：发生了什么，按时间顺序记录，不一定需要人处理；
- **告警（Alarm）**：需要人关注或处理的事件，有级别、确认、闭环。

把 SOE 全部当告警，会淹没操作员；把告警只当事件记录，会漏掉处理。

### 6.5 HMI 降噪

- 默认首页只放"当前最需要处理的 5 件事"，不是所有点的瀑布流；
- 按站/设备/告警级别分组，支持一键钻取；
- 曲线默认叠加参考线（额定、阈值、计划值），不要只画一条裸线；
- 移动端只保留告警、关键曲线和确认操作，不做全量组态；
- 深色/浅色主题下都要保证告警颜色可辨，不能只靠红绿区分。

## 7. 冗余与可靠性

### 7.1 冗余层级

| 层级 | 冗余方式 | 切换目标（示例） | 常见缺口 |
|---|---|---|---|
| 设备 | 双机、双电源、双网口 | 秒级 | 共用一个电源/交换机 |
| 网络 | 双交换机、双上行、环网 | 秒级 | 双网走同一管沟 |
| 前置 FEP | 主备/双活 | 秒级 | 共享同一采集端口 |
| 服务器 | 主备/集群 | 分钟级 | 共享存储单点 |
| 历史库 | 副本/备份 | 分钟级 | 备份未演练 |
| 时钟 | 双主钟、北斗+GPS | 微秒级 | 双钟同源 |
| 广域通道 | 双通道、不同运营商 | 秒到分钟 | 双通道同路径 |

### 7.2 主备、双活与仲裁

- **主备**：备机平时不写，切换时接管；逻辑简单，但备机可能"冷"；
- **双活**：两台都工作，需要仲裁/一致性协议；搞不好会脑裂；
- **仲裁**：双活必须有第三方仲裁或共享锁，否则网络分区时两边都以为自己是主。

没有仲裁的双活，比单机更危险。

### 7.3 冗余不等于可靠

冗余只能对付**独立故障**，对付不了共因故障：

- 双机接同一台交换机；
- 双通道走同一根光缆；
- 双时钟共用同一根天线；
- 双系统跑同一版本、同一配置错误；
- 双人复核用同一个账号；
- 备份盘和主机放在同一个机柜。

做冗余设计时，先列共因，再谈切换。

### 7.4 切换演练

至少覆盖：

- 杀掉主 FEP 进程/主服务器；
- 断开主用网络，观察切换与恢复；
- 拔掉主时钟天线，观察守时与告警；
- 填满历史库磁盘，观察写入降级与告警；
- 停掉 MQTT Broker，观察边缘缓存与补数；
- 模拟数据库主备切换，核对数据不丢不重；
- 双通道同时中断 15 min，核对补数与对账。

演练要有记录、有结论、有整改项，不能只看"切换成功"一个灯。

### 7.5 可用性指标

可用率、MTBF、MTTR 的定义要与业务对齐：

- 计划检修算不算停机；
- 单点失效但未影响业务算不算；
- 数据丢失但系统仍在线算不算；
- 切换时间从"故障发生"还是"发现故障"开始算。

指标口径不写清，99.99% 可以有很多种解释。

## 8. 电力监控安全防护与等保

### 8.1 现行规章

**《电力监控系统安全防护规定》（国家发展改革委2024年第27号令）**，2024年11月25日公布，**2025年1月1日施行**，同时废止2014年第14号令。这是当前电力监控安全防护的顶层规章，不是"草案"，也不是"即将施行"。

要点：

- **适用范围**：电力监控系统运营者，以及相关的规划设计、研究开发、产品制造、施工建设、安装调试单位；
- **系统范围**：明确包括新能源发电监控、分布式电源监控、储能电站监控、虚拟电厂监控、配电自动化、电力现货市场交易等功能的系统，以及支撑它们的通信设施、数据网络与网管系统；
- **结构原则**：坚持"安全分区、网络专用、横向隔离、纵向认证"；
- **分区**：生产控制区（安全 I / II）、管理信息区（安全 III / IV），并设置安全接入区；
- **边界**：禁止任何穿越生产控制区与管理信息区、安全接入区之间边界的通用网络服务；
- **全生命周期**：投运前安全加固，运行中漏洞整改，供应链不得选用存在已知缺陷且未补救的产品和服务；
- **监测**：建设基于内置探针等的网络安全监测手段，与调度数据网相连的系统要将告警同步送至相应调度机构。

### 8.2 分区与边界

| 区域 | 典型系统 | 允许 | 不允许 |
|---|---|---|---|
| 生产控制区 I/II | SCADA、AGC/AVC、保护、站控 | 实时监控、控制、保护 | 公网服务、办公、邮件、通用远程桌面 |
| 安全接入区 | 外部资源接入网关、代理、认证 | 代理转发、端到端认证、受控数据交换 | 直接控制、通用网络服务、绕过隔离 |
| 管理信息区 III/IV | VPP 云平台、交易、结算、看板 | 预测、优化、申报、分析 | 实时控制、保护定值、直接写生产库 |

**安全接入区不是"隔离区"的替代品**。它解决的是外部资源（分布式光伏、储能、充电桩、第三方聚合商）如何受控接入，不是让公网流量直接进生产控制区。

### 8.3 VPP 云边安全架构

| 场景 | 部署位置 | 允许的数据流 | 控制路径 | 注意 |
|---|---|---|---|---|
| VPP 只做监测/预测/交易 | 管理信息区 | 生产数据经隔离上行；交易数据经 API | 不控制设备 | 不能回写生产实时库 |
| VPP 需要下发功率指令 | 生产控制区或安全接入区 | 计划/指令经受控通道 | 指令网关 → 站控 → 设备 | 需鉴权、限幅、互锁、回执 |
| 第三方聚合商接入 | 安全接入区 | 代理转发、端到端认证 | 仅限授权资源与指令类型 | 最小权限、审计、可熔断 |
| 户用光伏/储能 | 安全接入区/边缘 | 遥测、状态、计量 | 受控的启停/功率限制 | 不能直连公网 Broker 控制 |
| 充电桩 V2G | 安全接入区/边缘 | 状态、功率、计量 | 受控的充放电指令 | 车端/桩端双重校验 |

一句话：**公网可以"看"，生产控制必须"过边界"**。任何"手机 App 直接控制储能"的方案，都要先回答它走的是哪条安全链路。

### 8.4 等保与关基

- **网络安全等级保护 2.0**：GB/T 22239-2019 等系列标准，电力监控系统同样要落实等级保护制度；
- **关键信息基础设施安全保护**：《关键信息基础设施安全保护条例》（国务院令第745号）与相关要求；
- **GB/T 36572-2018《电力监控系统网络安全防护导则》**：现行国家标准，给出技术防护框架；
- **国能安全〔2015〕36号《电力监控系统安全防护总体方案》等**：现行技术支撑文件；后续版本状态以国家能源局正式发布为准，不能把"正在修订"写成"已发布"；
- **IEC 62351 系列**：电力系统通信安全标准，用于 104/61850 等协议的加密与身份认证。

等保测评不是"买设备"，而是"制度 + 技术 + 运维 + 审计"一起过。只做管理信息区、不做生产控制区的测评，等于没做。

### 8.5 常见违规

- Modbus 502、104 端口直接暴露公网；
- MQTT Broker 匿名可写，主题用 `#` 通配；
- SCADA 服务器开远程桌面，运维从办公网直连；
- 生产控制区与管理信息区共用一台交换机/VLAN；
- 测试系统、厂商远程维护通道直接接入生产；
- 默认口令、共享账号、长期不换证书；
- 只做边界防火墙，不做纵向认证与入侵监测；
- 日志只留 7 天，出事查不到；
- 备份文件放在同一台主机；
- 把"安全接入区"当成"公网直连缓冲区"。

### 8.6 上线前安全清单

- [ ] 系统定级、备案、测评范围覆盖生产控制区与安全接入区；
- [ ] 分区边界、隔离装置、纵向加密均已部署并策略核对；
- [ ] 无通用网络服务穿越边界（RDP、SMB、HTTP 代理等）；
- [ ] 安全接入区完成代理转发、端到端认证、最小权限；
- [ ] 默认口令、共享账号、测试账号已清理；
- [ ] 证书、密钥、VPN/APN 配置有归属人与到期提醒；
- [ ] 网络安全监测探针/日志接入，告警能送到调度机构；
- [ ] 供应链安全要求写入合同（漏洞响应、补丁、后门声明）；
- [ ] 备份、恢复、切换演练完成并有记录；
- [ ] 运维远程接入有审批、双人复核、全程审计。

## 9. 与 EMS、VPP 和结算的接口

### 9.1 数据契约

SCADA 与 EMS/VPP 之间至少要约定：

| 字段 | 要求 | 示例 |
|---|---|---|
| 点表版本 | 双方一致，变更有通知 | `v2026.11.1` |
| 采样/上报周期 | 分点配置，不搞全局一刀切 | `5 s / 15 s` |
| 时标 | 设备时标优先，统一 UTC | `2026-11-09T02:00:00Z` |
| 质量码 | 统一枚举，端到端保留 | `Good/Invalid/...` |
| 量纲与变比 | 工程值，注明单位 | `kW，一次侧` |
| 死区 | 归档/告警分开 | `1 kW / 5 kW` |
| 补数规则 | 原时标、去重、水位线 | `15 min 窗口` |
| 保留期 | 原始/分钟/日报 | `90 d / 5 y / 10 y` |
| 责任人 | 点表、数据、接口各有人 | `数据Owner` |

### 9.2 控制契约

| 字段 | 要求 |
|---|---|
| 指令 ID | 全局唯一，可追溯 |
| 目标对象 | 站/设备/点，不能只写"储能" |
| 目标值/爬坡率 | 单位、范围、变化率 |
| 生效/失效时间 | 过期指令不得执行 |
| 权限 | 谁可发、是否双人复核 |
| 互锁 | SOC、温度、并网点、检修状态 |
| 回执 | 接收、拒绝、执行、完成、失败原因 |
| 回读 | 执行后实际值与时标 |
| 幂等 | 重发不重复执行 |
| 审计 | 指令、操作人、审批、结果全留痕 |

### 9.3 SCADA 不是结算表

| 维度 | SCADA 遥测 | 结算计量 |
|---|---|---|
| 目的 | 监视、控制、优化 | 贸易结算、考核 |
| 精度 | 满足监视/控制 | 按计量装置准确度等级 |
| 时标 | 设备/网关时标 | 计量装置时标 |
| 校验 | 一般不做贸易校验 | 检定、封印、比对 |
| 数据完整性 | 允许补数/压缩 | 需可审计、可追溯 |
| 用途 | 不能直接作为结算依据 | 结算依据 |

**结论**：SCADA 的电度/功率数据可以用来做运行分析、偏差预警和对账参考，但不能替代关口表。结算必须用专用计量装置与计量主站数据；两者出现差异时，按计量口径为准，并查明 CT/PT、时标、线损、未注册负荷等原因。

**SCADA 也不是交易系统**：申报、报价与市场承诺属于交易/聚合层，SCADA 与 EMS 只负责把可调能力包络交给上层、执行分解后的指令并回传实际值。四种融合模式、容量分区与未来接口变化见[储能 EMS 优化调度](储能EMS优化调度-算法与工程-2026-11.md) §1.7.1、§1.10。

### 9.4 对账

1. **对齐时标**：统一 UTC/本地时区，确认计量周期（15 min/1 h）；
2. **对齐单位与变比**：kW/kWh、一次/二次值、CT/PT；
3. **对齐边界**：关口表位置、并网点、内部负荷；
4. **对齐口径**：是否含线损、厂用电、辅助服务；
5. **设差异阈值**：按电量比例/绝对量设告警；
6. **留差异说明**：通信中断、补数、人工置数、计量故障都要有记录。

### 9.5 联调

| 用例 | 方法 | 通过标准 |
|---|---|---|
| 点对点遥测 | 逐点加信号/比对源 | 数值、单位、变比、时标一致 |
| 遥信变位 | 实际动作/短接 | 状态、时标、SOE 顺序正确 |
| 遥控 | 选择-执行/直接执行 | 回执、执行、回读一致 |
| 遥调 | 给定值/爬坡 | 目标、速率、回读一致 |
| 总召 | 重启/手动总召 | 不丢点、不重复、时标正确 |
| 对时 | 主钟失锁/恢复 | 告警、守时、恢复后时标正确 |
| 双机切换 | 杀主/断网 | 切换时间、数据不丢不重 |
| 断网补数 | 断开 15 min | 原时标补入、去重正确 |
| 告警风暴 | 批量变位 | 不丢告警、抑制生效 |
| 安全边界 | 端口扫描/策略核对 | 无违规穿越、审计完整 |

## 10. 工程验收与运维

### 10.1 P0 清单

| 检查项 | 通过标准 |
|---|---|
| 点表一致性 | 现场、网关、SCADA、EMS 四方一致，版本可查 |
| 变比与量纲 | 抽点与源表/标准源核对，无重复变比 |
| 质量码 | 断线、超量程、人工置数能正确显示 |
| 时标 | 设备事件时标保留，UTC/本地转换正确 |
| 遥控/遥调 | 权限、互锁、超时、回执、回读齐全 |
| 双点遥信 | 中间态、故障态不丢失 |
| 总召/补数 | 不丢不重，原时标入库 |
| 冗余 | 主备/双通道切换演练通过 |
| 对时 | 主钟失锁告警，守时满足 SOE 要求 |
| 安全分区 | 无通用网络服务穿越边界 |
| 安全接入 | 代理、认证、最小权限、审计 |
| 监测 | 探针/日志接入，告警可送达 |
| 备份 | 备份可恢复，RPO/RTO 达标 |
| 文档 | 点表、网络图、IP 表、端口表、运维手册齐全 |

### 10.2 P1 清单

| 检查项 | 通过标准 |
|---|---|
| 命名规范 | 点 ID、设备名、告警名统一 |
| 容量 | 点数、带宽、存储按 3–5 年增长预留 |
| 性能 | 总召/告警风暴下时延仍达标 |
| 可维护性 | 点表变更、版本回滚有流程 |
| 可观测性 | 通道状态、进程、队列、磁盘有监控 |
| 审计 | 操作、配置、导出有日志 |
| 培训 | 运维会看告警、会切机、会补数 |
| 演练 | 每季度至少一次切换/断网演练 |

### 10.3 上线验收用例

- 逐点遥测核对（至少覆盖所有关口、PCS、BMS 关键点）；
- 遥信实际变位与 SOE 顺序；
- 遥控选择-执行、拒绝、超时、回读；
- 遥调目标值、爬坡率、失效时间；
- 总召期间数据不重复、不丢点；
- 双机/双网/双通道切换；
- 主时钟失锁与恢复；
- 断网 15 min 补数；
- 告警风暴与抑制；
- 安全边界端口/策略核对；
- 备份恢复；
- 与 EMS/VPP/计量主站联调。

### 10.4 日常运维

- **每日**：通道状态、关键告警、磁盘、时钟偏差；
- **每周**：点表变更核对、备份检查、异常点复核；
- **每月**：证书/账号/权限、补数记录、性能趋势；
- **每季度**：切换演练、断网演练、告警复盘；
- **每年**：等保测评/自查、容量评估、点表全量核对；
- **变更**：点表、网络、证书、版本变更都要有审批、回滚与通知。

## 11. 常见故障与误区

| 误区/故障 | 为什么错 | 正确做法 |
|---|---|---|
| Modbus 502 暴露公网 | 无认证、无加密、可写寄存器 | 网关隔离 + VPN/专线 + 白名单 |
| MQTT QoS 2 当控制可靠 | QoS 只保证 broker 链路，不保证设备执行 | 指令 ID + 应用层 ACK + 回读 |
| 双点遥信压成布尔 | 丢失中间态与故障态 | 保留四态，分别处理 |
| 用收到时间当事件时间 | SOE 顺序失真 | 设备时标优先，记录时标来源 |
| 死区设成量程 5% | 小变化被吃掉，考核无数据 | 采集/归档/告警死区分设 |
| 历史库只存压缩值 | 无法还原、无法对账 | 结算/考核点保留原始或可审计参数 |
| 遥控无选择-执行 | 误动风险高 | SBO + 互锁 + 超时 + 回读 |
| 前置双机共用一台交换机 | 共因故障 | 独立网络路径与电源 |
| 只做管理信息区等保 | 生产控制区才是重点 | 全分区定级、测评、整改 |
| 安全接入区当隔离区 | 外部流量仍可能穿透 | 代理转发 + 端到端认证 + 最小权限 |
| SCADA 电度直接结算 | 精度、时标、校验不满足 | 专用关口表 + 计量主站 |
| NTP 不带 GPS 保 SOE | 毫秒级漂移 | 北斗/GPS + PTP/IRIG-B |
| 网关单点 | 一挂全盲 | 双网关/双通道 + 本地缓存 |
| 把云平台当实时控制通道 | 广域网抖动、断网即失控 | 控制闭环留在边缘，云只下计划/目标 |
| 边缘只缓存不补数 | 断网期间数据永久缺失 | 断点续传 + 原时标补入 + 去重 |
| 告警只报不闭环 | 操作员静音 | 分级 + 确认 + 派单 + 复盘 |
| 备份从未恢复演练 | 备份可能不可用 | 定期恢复演练，记录 RPO/RTO |

## 13. 术语表

| 术语 | 含义 |
|---|---|
| SCADA | 数据采集与监视控制，本文指 VPP/EMS 的数据底座 |
| 边缘 SCADA | 部署在站控层/设备侧的采集与控制执行端，强调低时延与断网自治 |
| 云 SCADA | 云化集中监控平台的工程叫法，不属标准术语；侧重跨站监视、历史与分析 |
| 云边协同 | 边缘负责实时控制与补数，云端负责聚合、分析与远程运维的分工模式 |
| RTU | 远程终端单元，站端采集与转发设备 |
| FEP | 前置处理器，负责多通道接入、解帧、点表映射 |
| 四遥 | 遥测、遥信、遥控、遥调 |
| 遥脉 | 电度脉冲/累计电量，常用于电量采集 |
| SOE | 事件顺序记录，要求毫秒级时标 |
| 点表 | 设备对象、测点、协议地址、量纲、死区等字段的集合 |
| 质量码 | 标识数据有效性的枚举，如 Good/Invalid/Questioned |
| 死区 | 变化超过阈值才上报/归档的过滤参数 |
| 总召 | 主站请求站端全量/分组数据的交互 |
| SBO | 选择-执行，先选择目标再执行命令的控制方式 |
| GOOSE | IEC 61850 的快速发布/订阅报文 |
| SV | IEC 61850 的采样值报文 |
| MMS | IEC 61850 的客户端/服务器通信映射 |
| SCL | 变电站配置语言，ICD/CID/SCD 的统称 |
| CIM | 公共信息模型，IEC 61970/61968 的模型交换标准 |

| 等保 2.0 | 网络安全等级保护 2.0 系列标准 |
| 关基 | 关键信息基础设施 |
