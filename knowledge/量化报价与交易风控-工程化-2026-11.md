## 0. 一页看懂

### 0.1 一条闭环

```
 市场规则/合同/调度/气象/计量/信用
              │
              ▼
      数据接入与质量校验
              │
              ▼
   预测（价格/负荷/新能源）──► 场景与概率分布
              │                         │
              └────────┬────────────────┘
                       ▼
            报价与组合优化（量价曲线）
                       │
                       ▼
        规则校验 → 限额校验 → 双人审批
                       │
                       ▼
              申报网关（回执/改单/留痕）
                       │
                       ▼
        出清结果 → 结算单 → 对账 → 归因
                       │                    │
                       └──── 风控与绩效 ◄───┘
                                  │
                                  ▼
                        规则/模型/限额迭代
```

- **闭环的重点不是"预测更准"，而是每一环都能被追溯、复现和拦截**：错了要知道错在哪一环，改了什么、谁批准的、影响多少钱。
- **风控不是最后一道止损**：限额、授权、校验、对账要嵌进流程；事后止损只能减少损失，不能防止错误发生。

### 0.3 七个判断

1. **报价是约束优化，不是价格预测比赛**：预测再准，合约覆盖、爬坡、最小出力、考核和限额任一不满足，收益都归零甚至为负。
2. **风控先于收益**：先定义"最多能亏多少、谁能批、什么情况必须停"，再谈策略；没有限额的策略只是赌方向。
3. **规则版本是一等公民**：2026-2027 是换版年，草案与正式稿、省级与区域、旧版与新版必须分库存放，报价系统要能按生效日切换。
4. **结算对账是最后一道风控**：申报、出清、计量、结算四处任一错位，都会表现为"模型很准但钱对不上"。
5. **回测必须能复现申报时点**：任何特征都要回答"D-1 申报截止前是否已存在"；用未来数据做回测，等于用答案倒推过程。
6. **工程化的核心是数据契约与审计链**：字段、单位、时点、版本、来源、质量标记缺一不可；没有留痕的改单等于放弃复盘。
7. **2026 的草案不能当现行规则**：现货新规、风险防控、售电管理、信用评价均在征求意见阶段，2027 年起才可能切换；答题与系统配置都要标注状态。

## 1. 边界与角色

### 1.1 报价、交易、风控不是一件事

| 职能 | 目标 | 关键产出 | 典型失败 |
|---|---|---|---|
| 量化研究 | 找到可复现的预测/策略增益 | 特征、模型、回测报告 | 过拟合、样本外失效 |
| 报价/交易 | 在规则与限额内最大化风险调整后收益 | 量价曲线、申报文件、改单记录 | 规则误读、申报越限、追涨杀跌 |
| 风控 | 把损失控制在可承受范围 | 限额、授权、压力测试、预警 | 限额虚设、事后才看见 |
| 结算/财务 | 把市场结果准确变成钱 | 结算单、对账单、差异说明 | 科目漏项、计量错位、跨期错配 |
| 运营/IT | 让上述流程稳定、可审计 | 数据管道、申报网关、监控 | 数据断供、重复申报、无回滚 |

- **四眼原则**：报价、风控、结算不能由同一人兼任；模型上线、限额调整、人工改单都要有第二人复核。
- **职责分离不是形式**：前台负责收益，中台负责独立计量与限额，后台负责对账与资金；三者的考核指标不能完全相同。

### 1.2 三类主体的报价身份与主要风险

| 主体 | 常见报价身份 | 主要收益来源 | 主要风险 | 关键约束 |
|---|---|---|---|---|
| 煤电/气电 | 报量报价 | 电能量 + 辅助服务 + 容量 | 燃料价格、启停成本、考核、市场力监管 | 最小出力、爬坡、启停时间、供热 |
| 新能源 | 报量报价或报量不报价 | 电能量 + 机制电价差价 + 绿证 | 出力预测偏差、捕获价下降、偏差考核 | 预测精度、并网考核、场站可用率 |
| 储能 | 报量报价（部分省） | 现货套利 + 辅助服务 + 容量补偿 + 租赁 | 价差收窄、退化、SOC 越限、考核 | 充放电效率、循环寿命、并网性能 |
| 售电公司 | 价格接受者/组合买方 | 批零价差 + 服务费 | 现货敞口、用户违约、保函不足 | 履约保障、零售套餐、偏差考核 |
| VPP/负荷聚合商 | 报量报价/响应 | 现货 + 辅助服务 + 需求响应 | 基线偏差、聚合资源失约、通信中断 | 基线认定、响应精度、聚合边界 |

### 2.2 2026-10 现货新规草案：七个方向性变化

| 变化 | 草案表述（要点） | 对报价系统的影响 | 级别 |
|---|---|---|---|
| 市场范围 | 日前、日内、实时电能量交易 | 系统要支持日内调整与实时偏差 | A（草案） |
| 主体扩围 | 新型储能、VPP、负荷聚合商、智能微电网、绿电直连项目 | 聚合主体与联合报价需要独立建模 | A（草案） |
| 价格机制 | 以节点边际电价（LMP）为主，减少分区价与节点价并存 | 报价与结算要落到节点/分区，不能只用系统均价 | A（草案） |
| 中长期金融化 | 合同进一步向差价合约靠拢 | 合约覆盖与现货敞口要分账核算 | B |
| 省间衔接 | 省间现货制度化，明确与省内的边界 | 跨省组合要区分省间/省内两套价格 | B |

- **生效时间**：草案拟 2027-01-01 施行，有效期 5 年；2026 年内仍以 1217 号文及各省细则为准。
- **答题纪律**：引用时必须写"公开征求意见稿"；不能把"拟施行"写成"已施行"。

### 2.3 中长期与合约：覆盖比例决定报价动机

- **1656 号文**（2025-12-17 印发，2026-03-01 施行）：对直接参与市场交易的经营主体，不再人为规定分时电价水平和时段；电网代理购电用户仍按政府优化后的峰谷执行。
- **合约是报价的起点**：中长期合约在现货中按差价结算，不物理执行；合约覆盖率越高，机组越希望被调度，报价越贴近成本；纯现货敞口越大，越有动机赌高价时段。
- **分解曲线**：合约电量要落到 96 点或 288 点；分解曲线与申报曲线冲突，是申报校验的常见拦截项。
- **金融化趋势**：草案提出中长期进一步向差价合约靠拢；系统要把"物理执行"与"财务结算"分开建模，不能混在一个 PnL 里。

### 2.4 辅助服务、容量与绿电：多市场叠加不是简单相加

| 市场 | 主要文件 | 收益/成本口径 | 与现货的关系 |
|---|---|---|---|
| 辅助服务 | 发改能源规〔2025〕411号；发改价格〔2024〕196号 | 调频、备用、爬坡、无功等；调频性能系数原则 ≤2，里程价 ≤0.015 元/kW | 同一容量可能被能量与辅助服务重复调用，需做机会成本 |
| 容量 | 发改价格〔2023〕1501号；发改价格〔2026〕114号 | 煤电 330 元/kW·年固定成本，2026 年起回收 ≥50%；独立储能按折算比例 | 容量电费不是电能量收入，不能按度电叠加 |
| 绿电/绿证 | 1044 号、136 号及省级细则 | 绿电溢价、绿证价格、机制电价差价 | 绿证与电能量分开结算，避免重复计算 |
| 机制电价 | 发改价格〔2025〕136号 | 存量/增量、各省竞价，10/12 年执行期 | 机制差价与现货收入分开归因 |

- **叠加原则**：同一物理容量在同一时段只能提供一种主服务；辅助服务、容量、现货收益要按可用容量与调用时长分摊，不能把三者都按满容量计算。
- **考核扣减**：并网考核、偏差考核、辅助服务考核会直接扣减收益；报价系统要把考核作为成本项，而不是事后才知道的"意外"。

### 2.5 零售、信用与履约：2026 年监管密集期

| 文件 | 时间/状态 | 关键内容 | 对交易系统的含义 |
|---|---|---|---|
| 《关于加强电力零售市场管理有关事项的通知》 | 2026-06-08 印发（B/C，原文待核） | 零售市场规范、套餐与信息披露 | 零售套餐要留痕、可解释 |

| 《电力市场风险防控管理办法（公开征求意见稿）》 | 2026-09-30，反馈至 10-30；7 章 32 条（B/C） | 市场内部/外部风险分类；重大/一般、紧急/非紧急；监测—预警—处置—报告闭环 | 风控要分市场、分主体、分紧急程度 |
| 《全国统一电力市场信用评价指引（公开征求意见稿）》 | 2026-10-13 发布（10-19 公开），反馈 30 日 | A/B/C/D 四级；季度评价；全国通用；C/D 级约束 | 信用等级进入准入、保证金与交易权限 |

- **履约保障不是"交了保函就没事"**：草案要求按日监测剩余额度与风险敞口，动态调整下一交易日交易限额；保函不足会直接限制交易。
- **信用评价不是道德标签**：A/B/C/D 与准入、交易权限、保证金挂钩；C/D 级主体可能被提高核验频次、限制交易或强制退出。
- **零售侧的现实**：2026 年前 7 月 400+ 售电公司退出（C）；广东上半年 298/500 亏损（C）；广西批零倒挂最大 0.373 元/kWh（C）；系统运行费 Q1-Q3 平均 0.068 元/kWh（B/C）。这些数字说明"吃固定价差"的模式已经失效。

### 2.6 报价前必须锁定的 12 项参数

| 参数 | 要确认什么 | 常见量级/口径 |
|---|---|---|
| 规则版本 | 省/区域、文件号、生效日、是否草案 | 逐省逐年不同 |
| 交易窗口 | 日前申报开放/截止、日内调整窗口 | 通常 D-1 上午截止 |
| 报价段数 | 量价对最大段数、是否允许空段 | 常见 3–10 段 |
| 单调性 | 价格是否必须随段递增 | 多数省要求单调不减 |
| 价格上下限 | 申报限价、出清限价、二次限价 | 上限常见 1000–1500 元/MWh；下限 −100–0 元/MWh |
| 申报充足率 | 监管关注的供给申报比例 | 常见 125% 量级 |
| 最小技术出力 | 机组可调下限、必开必停 | 煤电常见 30%–50% 额定 |
| 启停约束 | 启动时间、最小运行/停机时间 | 按机组类型 |
| 合约分解 | 中长期电量如何落到 96/288 点 | 分月分解、分日执行 |
| 结算方式 | 日前+实时双结算、偏差处理、TTS | 逐省不同 |
| 考核条款 | 偏差、并网、辅助服务、功率预测 | 罚款可能超过报价收益 |
| 信用/保函 | 保证金、保函、交易限额 | 售电公司最低 200 万元（草案） |

### 2.7 规则版本管理：把"规则"当代码管

- **规则登记表**：每条规则记录 `市场 / 品种 / 条款 / 参数 / 生效日 / 失效日 / 来源 / 级别 / 影响模块 / 负责人`。
- **差异比对**：新版本上线前，逐条比对旧版；重点看限价、段数、结算、考核、申报时限。
- **影响评估**：每条差异标注影响的策略、模型、报表、合同；不能只改前端提示。
- **双版本并行**：跨生效日时，回测与结算要能按"业务日期"选择规则版本，不能用当前版本重算历史。
- **回滚预案**：规则切换失败时，能退回旧版申报模板与校验规则，并保留已提交记录。

## 3. 数据层：数据契约与防泄露

### 3.1 七个数据域

| 数据域 | 典型字段 | 主要来源 | 更新频率 |
|---|---|---|---|
| 市场 | 日前/实时价格、出清量、阻塞、限价、规则版本 | 交易中心、调度 | 日/15 分钟/5 分钟 |
| 物理 | 机组容量、最小出力、爬坡、启停、供热、检修 | 生产系统、调度公告 | 日/月 |
| 成本 | 燃料价格、热耗、厂用电、启停成本、退化 | ERP、燃料、财务 | 日/月 |
| 气象 | 温度、辐照、风速、降水、台风 | 气象服务、公开 API | 小时/日 |
| 合约 | 中长期、零售、绿电、辅助服务、容量 | 交易系统、合同系统 | 日/月 |
| 结算 | 计量电量、结算单、考核、分摊、返还 | 计量、交易中心、财务 | 日/月 |
| 信用 | 保函、保证金、信用等级、敞口 | 交易中心、财务、信用平台 | 日/季 |

### 3.2 数据契约模板

| 字段 | 说明 | 示例 |
|---|---|---|
| `name` | 字段名，统一英文 snake_case | `da_price` |
| `type` | 数据类型与精度 | `decimal(10,4)` |
| `unit` | 单位 | `CNY/MWh` |
| `timestamp` | 业务时点与发布时点分开 | `delivery_start`, `published_at` |
| `market` | 市场与品种 | `province=SD`, `product=DA` |
| `rule_version` | 规则版本 | `SD-2026-05` |
| `source` | 来源系统与接口 | `exchange_api_v3` |
| `quality` | 质量标记 | `ok/missing/outlier/estimated` |
| `vintage` | 数据版本/修订号 | `2026-11-01T08:00Z#2` |

- **单位必须显式**：元/MWh 与元/kWh、MW 与 MWh、AC 与 DC 混用，是结算差异的常见根因。
- **时点必须成对**：业务时点（交付/结算）与知识时点（发布/修订）分开；回测只能用知识时点之前的数据。

### 3.3 时间对齐与版本

- **粒度统一**：日前统一到 96 点（15 分钟）；实时 5 分钟数据先聚合成 15 分钟再加权，不要与 96 点混用。
- **时区**：中国无夏令时，跨系统对接确认 UTC+8 标注，避免"少一小时"。
- **缺失处理**：连续缺失 ≤2 点可线性插值；超过则整日剔除并标注，不能静默填零。
- **异常处理**：价格超出限价区间、负荷单点跳变超过 30%、新能源出力为负，标记待查；**负电价必须保留**，它是市场信号，不是脏数据。
- **修订版本**：交易中心可能修正历史数据；回测要保留原始版本与修订版本，不能直接用最新版覆盖历史。

### 3.4 数据质量 SLO（示例）

| 指标 | 定义 | 示例目标 | 告警动作 |
|---|---|---|---|
| 完整性 | 应有记录数/实际记录数 | ≥99.5% | 缺测 >0.5% 暂停自动申报 |
| 及时性 | 数据到达到规定时点的比例 | ≥99% | 关键数据迟到 15 分钟升级 |
| 准确性 | 通过校验规则的比例 | ≥99.9% | 越限/跳变进入人工复核 |
| 一致性 | 跨系统同一指标差异 | ≤0.1% | 超差冻结结算 |
| 可追溯 | 有来源、版本、质量标记的比例 | 100% | 无来源数据不得入模 |

- 上述阈值是示例（D），不是监管标准；按主体规模与市场要求设定。
- **关键数据"双源"**：价格、负荷、计量至少两个来源交叉校验；单源故障时能切换。

### 3.5 防泄露与常见偏差

| 偏差 | 表现 | 防法 |
|---|---|---|
| 前视偏差 | 用 D 日实时价、D 日实际负荷做 D-1 预测 | 建立"知识时点"字段，回测按 as-of 取数 |
| 幸存者偏差 | 只回测赚钱的时段/机组/用户 | 全样本回测，报告最差样本 |
| 选择偏差 | 只选规则有利的省份/月份 | 按市场、季节、规则版本分层报告 |
| 过拟合 | 参数在样本外漂移、特征只在特定月份有效 | 滚动窗口、参数稳定性、多重比较校正 |
| 标签泄露 | 特征中隐含未来信息（如结算后的考核结果） | 特征清单逐项标注最早可得时点 |
| 规则泄露 | 用新版规则回测旧版市场 | 规则版本与业务日期绑定 |

- **一条硬规则**：任何进入特征的数据，必须能回答"这个数在 D-1 申报截止前是否已经存在"。答不上来的，就不能进模型。
- **回测与实盘同源**：回测用的价格、负荷、规则版本，要与实盘申报时一致；不能用"事后清洗过的完美数据"。

### 3.6 数据血缘与审计

- 每个报表数字能下钻到：源系统 → 接口 → 原始记录 → 清洗规则 → 聚合口径 → 模型版本。
- 关键表保留 `created_at / updated_at / version / hash`；申报文件与结算单保留原始文件与解析结果。
- 审计日志至少保留一个完整结算周期；涉及争议、考核、信用评价的记录延长保留。

## 4. 预测：从点预测到决策分布

### 4.1 三个预测对象

| 对象 | 预测期 | 主要用途 | 关键难点 |
|---|---|---|---|
| 电价 | 日前 96 点、日内、实时 | 报价、套利、合约估值 | 尖峰、负价、拐点、规则变化 |
| 负荷 | 日前 96 点、超短期 | 售电采购、偏差管理、VPP 基线 | 气温、节假日、用户行为 |
| 新能源出力 | 日前 96 点、超短期 | 申报量、偏差考核、净负荷 | 天气突变、云遮挡、弃风弃光 |
| 净负荷 | 日前 96 点 | 价格形状、稀缺时段 | 新能源与负荷的相关性 |

### 4.2 点预测不够，报价要分布

- **点预测**回答"最可能多少"；**概率预测**回答"有多少概率超过某个阈值"。
- 报价决策通常需要分位数：P10/P50/P90，或场景集；只用均值会把尾部风险抹平。
- **不对称损失**：少报和多报的罚则不同，最优申报量不是均值，而是使期望损失最小的分位数。
- **场景生成**：历史场景、参数分布、蒙特卡洛、对抗场景；场景要保留相关性（负荷-新能源-价格），不能独立抽样。

### 4.3 评价指标

| 目标 | 指标 | 说明 |
|---|---|---|
| 点预测 | MAE、RMSE、sMAPE | sMAPE 要设分母下限，避免低价时段爆炸 |
| 偏差 | bias、分时段 bias | 系统性偏高/偏低比随机误差更危险 |
| 概率 | pinball loss、CRPS | 评价分位数/分布是否校准 |
| 方向 | 方向正确率（带死区） | 必须说明步长、死区、样本区间 |
| 尖峰 | 尖峰召回、负价召回 | 少数极端点决定尾部收益 |
| 决策 | 元/MWh、元/日、命中率、CVaR | 最终看钱，不只看误差 |

- **只报平均值是回测造假最常见的形式**：必须给逐日分布、最差 5 天、分时段误差。
- **误差要换算成钱**：`误差经济价值 ≈ |误差| × 电量 × 价格 × 罚则系数`；不同时段的误差价值不同。

### 4.4 残差校正与分层

- **残差校正**是性价比最高的一层：按"时段 × 星期"与外生变量（温度、辐照、负荷、节假日）分解系统偏差，再做收缩估计。
- **分层建模**：正常时段、尖峰时段、负价时段、极端天气分别建模；用一个模型包打天下，通常在拐点失效。
- **规则特征**：检修、阻塞、必开必停、外送计划、机组报价行为，都是价格形状的驱动因素；纯时序外推不够。
- **方法细节**见《现货报价量化专家》第 3–5 章；本文只保留接口与评价。

### 4.5 预测到报价的接口

```
预测分布 ──► 场景/分位数 ──► 风险偏好 λ ──► 报价优化
   │              │                │
   └─ 校准/回测 ──┴─ 限额/合约 ────┘
```

- **输入契约**：预测服务输出 `timestamp, quantile, value, model_version, trained_until`；报价服务不得直接读原始模型。
- **风险偏好**：`λ` 越大越保守；λ 应由风险委员会设定，不能由报价员临时调。
- **回退**：预测服务故障时，回退到"季节朴素 + 成本报价 + 保守申报量"，并记录降级原因。

### 4.6 漂移监控

- **数据漂移**：PSI、KS、分布均值/方差；特征漂移超过阈值触发复核。
- **模型漂移**：分时段误差、方向正确率、尖峰召回；连续 N 天恶化触发重训。
- **规则漂移**：限价、段数、结算方式变化；规则变更必须重新校准，不能沿用旧参数。
- **监控看板**：按市场、品种、时段、模型版本四个维度展示；异常自动告警到责任人。

## 5. 报价与组合决策

### 5.1 目标函数：收益减去风险

```
max  E[π] − λ · CVaR_α(L)
s.t. 申报量 ≤ 可用容量 − 检修容量
     最小技术出力 ≤ 申报量
     爬坡约束、启停约束、合约分解约束
     价格/段数/单调性符合市场规则
     敞口/限额/保函满足风控要求
```

- `π` 是组合利润，`L = −π` 是损失；`CVaR_α` 是尾部条件期望。
- **λ=0** 是风险中性，追求期望收益；**λ 越大**越保守，尾部损失权重越高。
- 约束不是"附带条件"，而是报价可行域；不可行的"最优解"没有意义。

### 5.2 发电侧：边际成本 + 机会成本

- **价格接受者**：最优报价接近边际成本；加价只会降低中标概率，不改变价格。
- **枢机机组**：加价空间来自剩余需求，不是主观愿望；要评估对手报价与阻塞。
- **多段曲线**：按成本分段，确保单调；低段保出清，高段捕捉稀缺。
- **启停决策**：启动成本、最小运行时间、未来机会成本要一起算；不能只看当日现货价。
- **合约覆盖**：合约比例高时，报价更贴近成本以保调度；纯现货敞口大时，才考虑赌高价。

### 5.3 新能源：先解决量与偏差

- **申报量**：在预测分布上按不对称罚则选分位数；少报的罚则与多报的罚则不同。
- **配储联合报价**：新能源与场站内配套储能可作为联合报价主体参与申报、出清、调用、结算、考核（2026-10 草案方向，A（草案））。
- **捕获价**：高比例风光省份，午间低价/负价会拉低捕获价；报价要结合储能/负荷灵活性。
- **考核**：功率预测准确率、并网考核、偏差考核都要计入成本；不能只算电能量收益。

### 5.4 储能：价差要覆盖循环成本

```
单次套利净收益 ≈ Q_dis × (p_dis − p_ch / η_rt) − Q_dis × (c_deg + c_om)
可行条件：p_dis − p_ch / η_rt ≥ c_deg + c_om
```

- `Q_dis` 是可放电量（受 DoD、RTE、SOC 约束）；`η_rt` 是往返效率；`c_deg` 是退化成本；`c_om` 是运维成本。
- **机会成本**：SOC 是稀缺资源；低价充电会占用高价放电机会，要用边际价值曲线，而不是简单阈值。
- **辅助服务**：调频、备用会占用 SOC 与容量，收益要与现货套利比较，不能重复计算。
- **容量补偿**：114 号文的容量电价按可用容量与时长折算，不是按放电量；与套利收益分账。
- **退化**：循环次数、深度、温度影响寿命；报价模型要把退化成本内生化，不能只算电费。

### 5.5 售电：组合、对冲与传导

```
零售毛利 = 零售收入 − [w_h × 合约价 + (1 − w_h) × 现货价] × 用电量 − 服务成本
```

- `w_h` 是对冲比例；对冲不足，现货上涨会侵蚀毛利；对冲过度，现货下跌会失去竞争力。
- **用户结构**：居民、商业、工业的负荷曲线不同；组合的偏差风险不等于单用户风险相加。
- **套餐设计**：固定价、浮动价、峰谷价、现货联动；1656 号后，固定分时套餐失去政府定价保护，套餐要与现货风险匹配。
- **履约保障**：保函/保险/保证金要覆盖风险敞口；按日监测，动态调整交易限额（2026-09 草案方向）。
- **批零倒挂**：零售价低于采购成本时，越卖越亏；系统要能实时测算"每卖一单亏多少"。

### 5.6 多市场协同：同一容量不能重复卖

| 市场 | 占用资源 | 收益口径 | 冲突点 |
|---|---|---|---|
| 电能量 | 发电/放电能力、SOC | 元/MWh | 与辅助服务争夺容量 |
| 调频 | 调节容量、响应速度 | 元/MW·里程/容量 | 频繁调用影响 SOC 与退化 |
| 备用 | 可用容量 | 元/MW·小时 | 与电能量申报互斥 |
| 容量 | 可用容量 | 元/kW·年 | 与现货/辅助服务叠加规则不同 |
| 绿电/绿证 | 电量属性 | 元/MWh、元/张 | 与电能量重复计算风险 |
| 需求响应 | 可削减负荷 | 元/kW、元/kWh | 与基线、现货偏差交互 |

- **统一资源模型**：把发电能力、SOC、可削减负荷统一成"可用容量 × 时段"，再做多市场分配。
- **机会成本**：每个市场占用资源都有机会成本；优化目标是组合收益，不是单市场收益最大化。
- **结算分账**：不同市场分开结算、分开考核；合并报表可以，合并计算会出错。

### 5.7 场景优化与 CVaR

- **均值-CVaR**：在期望收益与尾部损失之间取舍；适合报价、储能、售电组合。
- **随机规划**：两阶段/多阶段，第一阶段报价，第二阶段出清/实时调整；场景树不能太大，否则不可解。
- **鲁棒优化**：对价格/负荷/出力不确定性设不确定集；保守但稳定，适合规则切换期。
- **样本外检验**：优化用的场景与回测场景要分开；用同一批场景优化和评估，会高估效果。

### 5.8 市场力与合规红线

- **市场力**：份额高、剩余需求缺乏弹性、阻塞时，报价可能影响价格；监管会用成本数据、报价行为、集中度指标识别。
- **红线**：操纵价格、持留容量、串通报价、哄抬/压低价格、虚假申报、利用内幕信息，均属违规。
- **成本数据**：草案提出成本数据用于市场力监管与成本补偿；成本要真实、可审计，不能为报价随意调整。
- **合规审查**：报价策略上线前做合规评审；涉及市场力的策略要有书面论证。

### 5.9 报价校验清单

| 检查项 | 规则 | 失败动作 |
|---|---|---|
| 段数与单调性 | 符合省级规则 | 拦截，提示修改 |
| 价格区间 | 含申报限价、出清限价、二次限价 | 拦截 |
| 申报量 | ≤ 可用容量 − 检修；≥ 最小出力 | 拦截 |
| 爬坡/启停 | 满足物理约束 | 警告/拦截 |
| 合约分解 | 与中长期曲线不冲突 | 警告 |
| 必开必停 | 标记正确 | 拦截 |
| 文件格式 | 编码、字段顺序、模板版本 | 拦截 |
| 限额 | 敞口、VaR、单日亏损、保函 | 拦截/升级 |
| 审批 | 双人复核、授权范围 | 未审批不得提交 |
| 版本 | 规则版本、模型版本、文件版本 | 缺失不得提交 |

### 5.10 人工 override

- **允许场景**：模型故障、极端天气、规则临时变更、系统异常；必须有原因代码。
- **控制**：双人复核、限额内、留痕（时间、人员、改前/改后值、原因）；事后 T+1 复盘。
- **禁止**：无记录改单、绕过限额、一人完成报价与审批、用个人账号代操作。

## 6. 回测与仿真

### 6.1 回测协议（必须写进报告）

- **滚动起点**：第 t 天只用 t 之前的数据训练，预测第 t 天，然后向前滚动。
- **样本外**：残差校正只能用历史样本外误差拟合，不能用训练集残差。
- **窗口**：训练窗口长度固定并披露（如 14/21/30 天）；窗口变化单独报告。
- **成本**：手续费、偏差考核、辅助服务考核、资金占用都要计入；只算毛收益会高估。
- **结算复现**：回测要按当时规则、当时价格、当时计量口径复现结算，不能只用日前价。
- **基准**：季节朴素、成本报价、历史中位数、买入持有；没有基准的"提升"无法判断。

### 6.2 三种回测，回答不同问题

| 类型 | 假设 | 能回答 | 不能回答 |
|---|---|---|---|
| 价格接受者回测 | 报价不影响价格 | 预测/策略在给定价格下的收益 | 中标概率、对手反应 |
| 报价接受度回测 | 用历史出清结果判断是否中标 | 报价曲线的大致可行性 | 改变报价后的价格变化 |
| 全仿真回测 | 模拟出清/对手/网络 | 策略对价格的影响、市场力 | 真实对手行为、规则细节 |

- **不要用全仿真代替实盘**：仿真能验证逻辑，不能证明收益；参数、对手、规则任一失真，结论就不可靠。
- **报价扫描**：固定对手，扫描自身报价，画出收益-价格曲线；这是最有用的一张图，但要注意"固定对手"的假设。

### 6.3 指标集

| 类别 | 指标 | 用途 |
|---|---|---|
| 收益 | 总 PnL、元/MWh、元/日、元/年 | 绝对收益 |
| 风险调整 | Sharpe、Sortino、Calmar | 单位风险收益 |
| 尾部 | 最大回撤、CVaR、最差 5 天 | 生存能力 |
| 命中 | 方向正确率、尖峰召回、中标率 | 策略有效性 |
| 成本 | 偏差成本、考核费用、交易费用 | 隐性损失 |
| 稳定性 | 逐日分布、参数敏感性、分省/分季表现 | 可复现性 |

### 6.4 过拟合与多重比较

- **参数稳定性**：同一参数在多个滚动窗口的最优值是否漂移；漂移大说明过拟合。
- **多重比较**：试了很多策略再选最好的，会高估效果；用 deflated Sharpe、白噪声检验或独立样本验证。
- **PBO**：回测过拟合概率；策略数量多、样本短时尤其重要。
- **最差样本**：必须报告最差 5 天/最差月份；只看平均值会掩盖尾部风险。
- **经济逻辑**：策略要有可解释的经济逻辑；纯数据挖掘的"规律"在规则变化后容易失效。

### 6.5 回测与实盘的差异

| 差异 | 影响 | 处理 |
|---|---|---|
| 规则变化 | 限价、段数、结算方式变了 | 按规则版本回测；切换期单独评估 |
| 对手行为 | 报价改变会影响出清价 | 用报价扫描/仿真做敏感性 |
| 执行偏差 | 爬坡、故障、限电 | 回测中加入可用率与执行误差 |
| 流动性 | 无法按理想价格成交 | 加入滑点/成交概率 |
| 数据修订 | 历史数据被修正 | 保留 vintage，按当时可见数据回测 |

### 6.6 T+1 复盘模板

| 归因项 | 计算 | 说明 |
|---|---|---|
| 预测误差 | 按预测完美执行的收益 − 按实际价格的收益 | 价格/负荷/出力误差 |
| 报价偏离 | 实际报价收益 − 按预测最优报价的收益 | 策略/人工改单 |
| 执行偏差 | 实际出力收益 − 按申报量执行的收益 | 爬坡、故障、限电 |
| 规则/市场 | 规则变化、限价、检修、对手行为 | 外部因素 |
| 残差 | 总差异 − 上述四项 | 残差大说明模型遗漏变量 |

## 7. 交易风控体系

### 7.1 治理架构

```
董事会/风险管理委员会
        │  批准风险偏好、年度限额
        ▼
  风险管理部门（中台，独立报告）
        │  限额、计量、压力测试、预警
        ├──────────────┐
        ▼              ▼
  前台（报价/交易）   后台（结算/财务）
  收益与执行          对账、资金、审计
```

- **三道防线**：业务部门（第一道）、风险/合规（第二道）、审计（第三道）。
- **独立性**：中台不能由前台负责人兼任；限额调整要经风险委员会，不能由交易员自己改。
- **授权体系**：按品种、市场、金额、期限设授权；超授权必须升级，不能"先做后补"。

### 7.2 风险分类

| 风险 | 触发信号 | 主要缓释 |
|---|---|---|
| 价格风险 | 现货价格波动、尖峰、负价 | 限额、对冲、场景分析、止损 |
| 电量/偏差风险 | 负荷/出力预测偏差、考核 | 分位数申报、备用、偏差准备 |
| 基差/形状风险 | 合约价与现货价、峰谷形状不一致 | 分时段对冲、差价合约 |
| 流动性风险 | 保证金不足、无法平仓 | 现金流预测、授信、保函 |
| 信用风险 | 用户/对手违约、保函不足 | 信用评估、保证金、限额 |
| 操作风险 | 数据错误、重复申报、改单 | 校验、双人复核、审计 |
| 模型风险 | 过拟合、漂移、参数失效 | 验证、监控、冠军 challenger |
| 合规风险 | 市场力、串谋、虚假申报 | 合规审查、红线清单、培训 |
| 政策风险 | 规则切换、限价调整 | 规则版本管理、情景分析 |
| 结算风险 | 计量争议、结算差异、跨期 | 对账、差异管理、证据链 |

### 7.3 限额体系

| 层级 | 示例 | 批准 | 复核 |
|---|---|---|---|
| 战略限额 | 年度最大亏损、最大敞口、市场集中度 | 董事会/风险委员会 | 年度 |
| 战术限额 | 分市场/品种/期限的 VaR、Notional | 风险委员会 | 季度 |
| 操作限额 | 单日亏损、单笔申报量、单机组敞口、保函使用率 | 风险负责人 | 日/周 |
| 对手限额 | 单一用户/对手的应收、预付、保函 | 信用/风险 | 月/季 |

- **限额要可计算**：每个限额都要有明确公式、数据源、更新频率、责任人；不能只写"控制风险"。
- **限额要可执行**：事前拦截优于事后报告；系统里没有限额校验，等于没有限额。
- **限额要可调整**：市场/规则变化时能复核调整，但不能由前台随意改。

### 7.4 风险度量

```
VaR_α = inf{ l : P(L ≤ l) ≥ α }
CVaR_α = E[L | L ≥ VaR_α]
限额使用率 U = 当前敞口 / 限额
```

- **VaR 不是最大损失**：它只说明"以 α 概率不超过"，尾部可能更大；必须配合 CVaR 与压力测试。
- **历史模拟**：用历史价格/负荷场景重估组合；简单，但依赖历史代表性。
- **参数法**：假设正态/厚尾分布；计算快，但极端行情会低估。
- **蒙特卡洛**：模拟价格、负荷、出力、违约；灵活，但模型风险高。
- **压力测试**：价格翻倍、负价持续、来水偏枯、台风、规则突变；不依赖概率，直接看生存能力。

### 7.5 事前、事中、事后

| 阶段 | 控制 | 工具 |
|---|---|---|
| 事前 | 限额、授权、合规、报价校验 | 预交易检查、规则引擎 |
| 事中 | 实时敞口、价格预警、异常申报 | 监控看板、告警、熔断 |
| 事后 | 对账、归因、压力测试、复盘 | 结算系统、归因报告、风险报告 |

- **事前**：价格/电量/敞口/保函/授权五项检查，任一不通过不得提交。
- **事中**：价格突破阈值、申报量异常、重复提交、系统延迟，自动告警；紧急情况可熔断。
- **事后**：T+1 归因、T+3 对账、月度风险报告；差异要闭环，不能只记录不处理。

### 7.6 极端行情

- **价格上限/下限**：限价会改变报价与结算；报价扫描要覆盖限价触发场景。
- **负电价**：新能源高发、最小出力、供热机组可能导致负价；储能充电可能获利，但要注意充电成本与 SOC。
- **稀缺定价**：高峰缺电时价格飙升；容量补偿/可靠性机组组合会改变稀缺时段收益。
- **价格跳跃**：天气突变、机组故障、阻塞；历史 VaR 可能低估，必须做跳跃/压力测试。
- **相关性上升**：极端行情下，价格、负荷、新能源出力、信用风险同时恶化；分散化失效。

### 7.7 信用与履约保障

- **履约保障**：保函、保险、现金保证金；草案要求最低 200 万元，保函/现金额度应超过保险额度。
- **按日监测**：交易机构按日监测剩余额度与风险敞口，动态调整下一交易日交易限额（2026-09 草案方向）。
- **对手管理**：用户/售电公司/聚合商的信用等级、欠费、违约记录；C/D 级提高保证金或限制交易。
- **保函成本**：银行保函费用可能高于保险；选择工具时要算成本与流动性，不能只看费率。
- **省级样本**：贵州 2027 年规则要求履约保险额度占比不超过 40%，最低 200 万元（C，媒体口径）；具体以省级原文为准。

### 7.8 模型风险

- **模型清单**：每个模型记录用途、输入、输出、版本、负责人、验证报告。
- **独立验证**：模型上线前由非开发团队复核；重点看假设、边界、样本外表现。
- **持续监控**：漂移、误差、命中率、收益归因；连续恶化触发重训或下线。
- **冠军/挑战者**：新模型与旧模型并行，按同一口径比较；不能只看宣传效果。
- **人工兜底**：模型故障时回退到规则/成本报价；降级要记录，事后评估影响。

### 7.9 风控红线清单

1. 不得无授权报价、超限额交易、绕过审批。
2. 不得一人完成报价、复核、申报、结算。
3. 不得使用未来数据、伪造数据、篡改计量。
4. 不得操纵价格、持留容量、串通报价、虚假申报。
5. 不得无记录改单、删除申报/结算记录。
6. 不得把草案当现行规则配置系统。
7. 不得用单一历史场景代替压力测试。
8. 不得把容量/辅助服务收益重复计入现货收益。
9. 不得忽视考核、偏差、保函成本。
10. 不得在模型失效时继续自动申报而不降级。

## 8. 结算对账与收益归因

### 8.1 结算科目

| 科目 | 内容 | 常见差异来源 |
|---|---|---|
| 电能量 | 日前/实时电量 × 价格 | 计量、价格版本、分时点 |
| 偏差 | 实际与申报/合约的偏差 | 考核规则、罚则、阈值 |
| 辅助服务 | 调频、备用、爬坡、无功 | 性能系数、调用时长、考核 |
| 容量 | 煤电/储能/抽蓄容量电费 | 清单、可用率、折算比例 |
| 绿电/绿证 | 绿电溢价、绿证交易 | 核发、交易、注销 |
| 零售 | 用户电费、套餐、服务费 | 用户数、电量、套餐版本 |
| 考核/罚款 | 并网、预测、偏差、违约 | 规则版本、免考、证据 |
| 分摊/返还 | 不平衡资金、辅助服务分摊 | 分摊比例、返还规则 |

### 8.2 结算流程

```
计量数据 → 结算初算 → 结算单 → 对账 → 差异处理 → 确认 → 开票/收付
   │           │          │        │          │
   └─ 校验 ────┴─ 规则版本 ┴─ 科目 ┴─ 证据链 ─┘
```

- **计量是起点**：计量点、倍率、时点、正反向、失压失流，任何一项错位都会传导到结算。
- **规则版本**：结算要按业务日期对应的规则版本，不能用当前规则重算历史。
- **结算单**：保留原始文件、解析结果、版本号；不能只存汇总数。
- **争议**：规定期限内提出，附证据（计量、调度指令、规则条款、计算过程）；逾期可能不被受理。

### 8.3 对账五步法

| 步骤 | 检查 | 工具 |
|---|---|---|
| 完整性 | 科目、时段、主体是否齐全 | 科目清单、结算单结构 |
| 算术 | 电量 × 价格 = 金额；汇总 = 明细 | 重算、交叉表 |
| 价格 | 规则版本、限价、分时、节点/分区 | 价格表、规则库 |
| 电量 | 计量、申报、出清、考核 | 计量系统、调度记录 |
| 跨期 | 月末/年末、结算周期、追溯调整 | 时间轴、版本对比 |

### 8.4 差异处理

- **分级**：金额/比例阈值（示例：差异 >0.5% 或 >10 万元升级，D）；不同主体可按规模设定。
- **分类**：计量、价格、规则、电量、考核、跨期、人工录入；每类有责任人与处理时限。
- **证据链**：原始数据、计算过程、规则条款、沟通记录；不能只有一句"系统差异"。
- **闭环**：差异确认后调整/冲销，更新对账台账；重复出现的差异要改流程，不能每次手工修。

### 8.5 PnL 归因

```
ΔPnL = 预测误差 + 报价偏离 + 执行偏差 + 规则/市场 + 残差
```

- **预测误差**：价格/负荷/出力预测与实际差异导致的收益差。
- **报价偏离**：实际报价曲线与"按预测最优"曲线的差异；含人工改单。
- **执行偏差**：实际出力/用电与申报量的差异；含爬坡、故障、限电。
- **规则/市场**：限价、结算、考核、检修、对手行为。
- **残差**：四项解释不了的部分；残差过大说明模型遗漏变量或数据错误。

### 8.6 审计留痕

- 申报文件、回执、改单记录、审批记录、模型版本、规则版本、结算单、对账底稿，全部归档。
- 关键操作日志不可篡改；保留期限覆盖结算周期、考核申诉期、信用评价周期。
- 对外报送（监管、交易中心、审计）的数据要与内部报表同源；不能两套口径。

- **注册**：模型名称、版本、训练区间、特征集、参数、指标、负责人。

- **部署**：灰度/冠军挑战者；记录上线时间与回滚版本。
- **监控**：误差、漂移、收益、限额；异常自动告警。

### 9.5 非功能要求

| 要求 | 说明 |
|---|---|
| 幂等 | 同一申报重复提交不产生重复订单；用业务键去重 |
| 可重放 | 给定日期、数据版本、规则版本，能重算报价与结算 |
| 可回滚 | 模型、规则、申报模板都能回退 |
| 可审计 | 所有写操作有日志、有责任人、有时间戳 |
| 权限 | 最小权限、职责分离、双人复核 |
| 时间同步 | 全链路 NTP；申报截止以交易中心时钟为准 |
| 容灾 | 关键服务多活/备份；断网时能本地暂存 |
| 安全 | 传输加密、密钥管理、访问审计、防篡改 |

### 9.6 自建 vs 采购

| 维度 | 自建 | 采购 |
|---|---|---|
| 数据独占性 | 强，能深度定制 | 依赖供应商接口 |
| 规则适配 | 快，但要养团队 | 供应商适配，可能滞后 |
| 最后一公里 | 校验/改单/归因可控 | 往往仍需自建 |
| 成本 | 前期高、长期可控 | 前期低、按量/按年付费 |
| 风险 | 人才、交付、运维 | 供应商锁定、规则变更责任 |

- **建议**：预测/优化可采购或混合；**申报校验、改单留痕、结算对账、归因**必须自建或深度定制，因为这是主体自己的责任与数据。
- **合同**：写明规则变更后的适配责任、响应时限、数据归属、退出迁移；不能只买"收益提升"的承诺。

### 9.7 最小可行系统

| 阶段 | 目标 | 最小交付 |
|---|---|---|
| 0 | 规则与数据 | 规则登记表、数据契约、历史数据 |
| 1 | 预测与回测 | 基线预测、滚动回测、指标报告 |
| 2 | 报价与申报 | 报价曲线、规则校验、申报文件、回执 |
| 3 | 风控与结算 | 限额、预交易检查、对账、归因 |
| 4 | 自动化 | 模型监控、自动申报、异常熔断、审计 |

- 不要一开始追求"全自动"；先把**可复现、可审计、可回退**做出来，再谈自动化。
- 每个阶段都要有验收标准：数据完整率、回测样本外表现、申报成功率、对账差异率。

## 10. 算例（合成，D 级）

> 以下算例只用于演示方法，参数为合成值，不代表任何省份、任何项目。

### 10.1 储能 100 MW / 400 MWh 日前套利与 CVaR

**假设**

| 参数 | 取值 |
|---|---|
| 额定功率/能量 | 100 MW / 400 MWh |
| 可用深度 DoD | 90% |
| 往返效率 RTE | 85% |
| 退化成本 | 0.05 元/kWh（按放电量） |
| 运维成本 | 0.02 元/kWh（按放电量） |
| 谷段充电价 | 0.20 元/kWh |
| 峰段放电价 | 0.65 元/kWh |
| 年运行天数 | 330 天 |
| 单日循环 | 1 次 |

**计算**

```
可放电量 = 400 × 90% × 85% = 306 MWh
充电成本 = 306 / 0.85 × 0.20 = 72,000 元
放电收入 = 306 × 0.65 = 198,900 元
退化+运维 = 306 × (0.05 + 0.02) = 21,420 元
单日净收益 = 198,900 − 72,000 − 21,420 = 105,480 元
年净收益 ≈ 105,480 × 330 = 3,481 万元
单位放电净收益 ≈ 105,480 / 306 = 344.7 元/MWh
```

**价差情景与 CVaR**

| 峰谷价差（元/kWh） | 概率 | 单日净收益（万元） |
|---|---|---|
| 0.25 | 10% | −1.69 |
| 0.35 | 20% | 1.37 |
| 0.45 | 40% | 4.43 |
| 0.55 | 20% | 7.49 |
| 0.65 | 10% | 10.55 |

```
期望收益 = 4.43 万元/日
最差 10% 条件均值（CVaR90）≈ −1.69 万元/日
```

- **读法**：价差 0.25 元/kWh 时，扣掉充电、退化、运维后为负；套利不是"有价差就赚钱"。
- **风控**：若单日亏损限额 2 万元，最差情景 −1.69 万元在限额内，但已接近；若价差进一步收窄到 0.20 元/kWh，亏损会超过限额，应降低申报量或不出手。
- **策略**：设置最低价差门槛（例：0.30 元/kWh，D），低于门槛不套利；门槛要用当前效率、退化、运维参数重算，不能固定不变。

### 10.2 售电公司 10 亿 kWh 组合压力测试

**假设**

| 参数 | 取值 |
|---|---|
| 年售电量 | 10 亿 kWh |
| 日均售电量 | 约 2.74 GWh |
| 零售价 | 0.42 元/kWh（固定价） |
| 中长期对冲比例 | 70%，对冲价 0.36 元/kWh |
| 现货敞口 | 30% |
| 基准现货价 | 0.35 元/kWh |

**基准毛利**

```
综合采购价 = 70% × 0.36 + 30% × 0.35 = 0.357 元/kWh
单位毛利 = 0.42 − 0.357 = 0.063 元/kWh
日毛利 ≈ 2.74 GWh × 0.063 = 17.26 万元/日
```

**压力情景：现货价 +0.30 元/kWh**

```
综合采购价 = 70% × 0.36 + 30% × 0.65 = 0.447 元/kWh
单位毛利 = 0.42 − 0.447 = −0.027 元/kWh
日亏损 ≈ 2.74 GWh × 0.027 = 7.40 万元/日
连续 10 日 ≈ 74.0 万元
```

- **读法**：70% 对冲下，现货 +0.30 元/kWh 仍会出现日亏；若对冲比例只有 30%，日亏损会放大到约 39 万元，10 日约 392 万元，超过 200 万元最低保函额度。
- **保函**：草案最低 200 万元；上述 10 日压力已消耗 37%，若叠加用户违约、偏差考核，保函可能不足。
- **风控**：设置现货敞口上限、单日亏损限额、压力测试触发线；零售套餐要能传导部分现货风险，不能全部固定价。

### 10.3 结算对账差异

**假设**：某月电能量结算，预期 4,000 万元，结算单 3,920 万元，差异 −80 万元。

| 差异项 | 计算 | 金额（万元） |
|---|---|---|
| 计量差异 | 500 MWh × 0.40 元/kWh | −20 |
| 价格版本差异 | 100,000 MWh × 0.002 元/kWh | −20 |
| 辅助服务漏项 | 结算单未列 | −15 |
| 考核罚款 | 偏差/并网考核 | −25 |
| 合计 | — | −80 |

- **处理**：计量差异查表计/倍率；价格差异查规则版本与节点/分区；漏项补列；考核查免考证据。
- **纪律**：差异要分解到科目与原因，不能只写"系统差异 80 万元"；重复出现的差异要改流程。

### 10.4 T+1 归因示例

| 归因项 | 金额（万元） | 说明 |
|---|---|---|
| 预测误差 | −12 | 峰段价格预测偏低，少放 20 MWh |
| 报价偏离 | −5 | 人工改单提高首段价格，中标量下降 |
| 执行偏差 | −3 | 一次设备故障，少放 10 MWh |
| 规则/市场 | +2 | 限价调整，实际结算价高于预期 |
| 残差 | −1 | 未解释 |
| 合计 | −19 | 与实际 PnL 差异一致 |

- **读法**：预测误差是主因，但不能忽略报价偏离与执行；只盯模型会漏掉流程问题。
- **行动**：预测误差 → 检查峰段特征；报价偏离 → 复核改单授权；执行偏差 → 检修/可用率。

## 11. 常见误解（15 条）

1. **"预测准就能赚钱"**：报价还受合约、约束、考核、限额影响；预测只是输入之一。
2. **"报价 = 成本加成"**：价格接受者接近边际成本，枢机机组有机会成本，合约覆盖改变动机。
3. **"回测收益 = 实盘收益"**：滑点、规则变化、对手反应、执行偏差都会侵蚀收益。
4. **"用历史数据越多越好"**：用未来数据、修订后数据、旧规则数据，都会造成前视/规则泄露。
5. **"只看均价"**：尾部风险、尖峰、负价才决定生存；必须看分布与最差样本。
6. **"VaR 就是最大损失"**：VaR 是分位数，尾部可能更大；要配 CVaR 与压力测试。
7. **"风控就是止损"**：风控是限额、授权、校验、对账、归因的整套体系。
8. **"设了限额就没事"**：没有系统拦截、监控、问责，限额只是纸面数字。
9. **"结算对账是财务的事"**：结算差异往往源于报价、计量、规则版本，交易团队必须参与。
10. **"偏差电量只按现货价结算"**：还有考核、罚则、分摊、返还；只算现货会低估成本。
11. **"储能只看峰谷价差"**：效率、退化、SOC、辅助服务机会成本都要算。
12. **"售电靠价差"**：现货敞口、用户违约、保函、系统运行费都会吃掉价差。
13. **"负电价是异常数据"**：负价是供需信号，必须保留并建模。
14. **"全国规则一样"**：省级/区域规则差异大，报价前必须确认省份与版本。
15. **"2026 草案可以直接用"**：草案不是现行规则；2027 年起才可能切换，系统要按生效日管理。

## 速查：公式、指标与参数

### 核心公式

| 内容 | 公式 |
|---|---|
| 期望利润 | `E[π] = Σ_s p_s Σ_t [q_{s,t}(p_{s,t} − c_t) − C_fixed]` |
| 均值-CVaR | `max E[π] − λ · CVaR_α(L)`，`L = −π` |
| VaR | `VaR_α = inf{l : P(L ≤ l) ≥ α}` |
| CVaR | `CVaR_α = E[L where L ≥ VaR_α]` |
| 限额使用率 | `U = 敞口 / 限额` |
| 储能套利门槛 | `p_dis − p_ch / η_rt ≥ c_deg + c_om` |
| 储能可放电量 | `Q_dis = E_rated × DoD × η_rt` |
| 售电毛利 | `m = p_retail − [w_h p_hedge + (1−w_h) p_spot]` |
| 预测误差经济价值 | `≈ abs(e) × 电量 × 价格 × 罚则系数` |
| 结算差异 | `Δ = ΔQ × P + Q × ΔP + ΔQ × ΔP + 其他` |
| PnL 归因 | `ΔPnL = 预测 + 报价 + 执行 + 规则 + 残差` |

### 数据口径提醒

- **MW 与 MWh 不能混**：功率是瞬时能力，能量是累计电量；储能收益按放电量算，容量补偿按可用容量算。
- **元/MWh 与元/kWh 差 1000 倍**：报价表、结算单、合同可能用不同单位，必须显式标注。
- **日前与实时是两套价格**：日前申报、实时偏差，结算可能双结算；不能只用日前价算收益。
- **96 点与 288 点不能混**：15 分钟与 5 分钟粒度不同，聚合要加权，不能简单平均。
- **毛收益与净收益**：净收益要扣退化、运维、考核、分摊、资金占用；只算价差会高估。
- **容量与电量**：容量电价、辅助服务容量、现货电量是不同口径，不能重复计算。
- **草案与正式稿**：2026 年多份文件仍是征求意见稿；引用必须写"草案/拟施行"。
- **省级与区域**：南方区域市场正式运行，不等于省内规则统一；报价前确认市场层级。
- **信用等级与保函**：信用评价 A/B/C/D 与履约保函额度是两件事，但会共同影响交易权限。
