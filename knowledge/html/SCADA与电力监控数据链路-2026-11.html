0. 一页看懂

0.1 三句话

  1. SCADA 是数据平面，EMS 是决策平面：SCADA 负责"采得准、传得稳、控得住、查得到"，EMS 负责"算得优"；两者用点表与数据契约解耦，不能把优化器直接接到设备寄存器上。
  2. 四遥不是四个按钮：遥测、遥信、遥控、遥调各有自己的点表字段、质量码、时标与确认语义；把遥控当普通写入，等于把安全联锁交给网络。
  3. 安全分区先于技术选型：27号令下，储能电站监控、虚拟电厂监控、分布式电源监控都在电力监控系统范围内；公网到生产控制区没有"直连"选项。

1. 数据链路全景

1.1 一条遥测的旅程

一条遥测从现场到看板，通常要过七道关：

  1. 传感/变送：CT/PT、温度、SOC、开关位置等转成电信号或数字量；
  2. 采集装置：测控、RTU、BMS、PCS 按扫描周期采样，形成原始值；
  3. 边缘处理：滤波、标度变换、死区判断、打时标、加质量码；
  4. 通信：104/61850/Modbus/MQTT 把数据送到前置或云平台；
  5. 前置处理：解帧、点表映射、合法性检查、双通道去重；
  6. 实时库：写当前值、时标、质量码，触发告警与计算点；
  7. 历史库与应用：压缩入库、报表、优化模型、结算对账。

每一道关都可能改变数值的含义。点表错一个变比，后面所有优化和考核都错；时标错一个时区，SOE 顺序就会反过来。数据链路的第一原则不是"快"，而是"每个数都能追到来源"。

控制链路的每一环都要有明确回执：谁发的、发给谁、发的是什么、什么时候失效、设备有没有执行、执行后的实际值是多少。没有回执的"成功"等于没有执行；只有下发没有回读，等于把控制变成了广播。

按部署重心，工程上常把 SCADA 分成边缘侧与云端两种形态。先说结论：SCADA 是功能定义，不是按位置划分的两类标准系统；"边缘 SCADA""云 SCADA"是工程与市场叫法，不是 IEC/国标的正式分类。判断一套系统是不是 SCADA，看它是否具备采集、监视、控制、告警、历史与审计能力，而不是看机柜放在哪里。两种形态通常是云边协同，而不是二选一；安全分区细节见 §8.3。

1.5 边缘侧 SCADA（站控/设备侧）

定位：部署在站控层或设备侧，直接对接 PCS、BMS、逆变器、充电桩、PLC 与关口表，是"最后一公里"的采集与控制执行端。典型载体包括站控机、通信管理机、边缘网关、边缘计算节点，以及设备厂商自带的本地监控。

维度典型做法
部署位置站控室、升压站/配电房、设备柜内、边缘机房
采集周期100 ms–5 s（关键量），SOE 1 ms 分辨率
控制职责SBO 执行、就地联锁、AGC/AVC 执行端、指令回执与回读
协议104、61850（MMS/GOOSE/SV）、Modbus、OPC UA、DL/T 476

容量与保留估算：

边缘原始存储 ≈ 点数 × 采样频率 × 单点字节 × 保留秒数

例：5,000 点、1 次/s、16 B/点、保留 7 天，原始约 48.4 GB；按 5:1 压缩约 9.7 GB，再加 30% 余量。实际按死区后的采样率、压缩率、索引与副本修正。历史保留空间不能当补数缓存：断网缓存按 §5.4 单独估算，否则一断网就把历史库写满。

1.6 云端 SCADA（云化监控平台）

定位：部署在云平台或区域集控中心，面向多站、多租户做集中监视、历史存储、告警聚合、远程运维与开放接口。"云 SCADA"不是标准术语，厂商口径不一，常见叫法还有云集控、集中监控平台、VPP 聚合平台；有的只做监视分析、不承担实时控制，严格说是"云侧监控平台"而不是完整 SCADA。若集控中心承担生产控制，它应按生产控制区（或安全接入区）建设，不能因为叫"云"就放进管理信息区。

维度典型做法
部署位置管理信息区（III/IV）、区域集控中心、云平台
数据来源边缘网关/前置经隔离装置或安全接入区上行
主要职责跨站监视、告警聚合与派单、长期历史、报表对账、远程运维、开放 API
数据保留月到年，按时序库/对象存储分层
扩展方式水平扩容，按点数、流量、租户计费
断网行为云侧不可用不影响站内自治；恢复后补数
典型时延秒级到分钟级，受广域网与隔离装置影响

2. 点表：SCADA 的合同

2.1 对象模型

点表不是一张 Excel，而是"站—间隔—设备—测点"的对象模型。推荐至少四层：

区域/聚合商
  └─ 场站（储能站、微网、充电站、分布式光伏）
       └─ 间隔/设备（1# 储能单元、PCS、BMS、关口表）

对象模型的价值在于：当设备增容、改名或更换通信地址时，只改一层映射，不用修改上层优化模型和报表公式。

2.4 命名与点号

  • 稳定：点 ID 一旦投运不改；设备改名只改显示名；
  • 唯一：跨站、跨协议不重复；不把 IP 或寄存器地址当点 ID；
  • 可读：人能看懂对象路径，机器能解析；
  • 不复用：退役点保留并标记 retired，不复用给新设备；
  • 可版本化：点表有版本号、生效时间、变更记录与回滚方案。

2.5 变比、量纲与死区

工程值换算：

工程值 = 原始值 × 变比 + 偏移

三个常见坑：

  1. CT/PT 变比重复：设备已经按一次值输出，网关又乘了一次变比；
  2. 单位混用：kW 与 W、kWh 与 MWh、百分比与小数混在一张表里；
  3. 死区过大：为了省带宽把死区设成量程的 5%，小功率变化全被吃掉，考核时"没有数据"。

死区至少分三种：采集死区（设备上报）、归档死区（历史库存储）、告警死区（阈值判断）。三者目的不同，不能共用一个值。

2.6 质量码

统一质量含义常见来源位处理建议
Good有效无异常正常使用
Invalid无效IV、故障、超量程不参与优化与考核
Questionable可疑抖动、通信质量差、替代值标记并人工复核
Substituted人工替代手动置数、调试记录操作人、原因、时限
Test测试调试/检修不进入结算与考核
Blocked闭锁联锁、检修保留原值并说明
Overflow溢出量程溢出、计数器翻转检查变比与量程

质量码必须端到端保留。很多系统在网关处把质量码丢掉，到了 EMS 只剩一个数；优化器无法区分"0 MW"和"通信中断"，会把断线当成真实零功率。

2.7 双点遥信与中间态

双点遥信有四种状态：00 中间态、01 分、10 合、11 故障。把双点压成布尔，会同时丢掉"中间态"和"故障态"：

  • 开关操作过程中的中间态是正常的，不应立即告警；
  • 11 通常表示辅助触点故障或接线错误，应告警；
  • 双点取反要在点表里配置，不要在显示层临时取反。

2.8 点表核对清单

  • [ ] 每个点有唯一 ID、对象路径、协议地址和量纲；
  • [ ] 变比、偏移、CT/PT 只乘一次，抽点与现场表计核对；
  • [ ] 双点遥信、取反、抖动抑制已配置；
  • [ ] 质量码从设备到实时库全链路保留；
  • [ ] 遥测死区、归档死区、告警死区分别设置；
  • [ ] 遥控/遥调有权限、互锁、超时、回执与回读；
  • [ ] 点表版本、生效时间、变更人、回滚方案齐全；

3.2 IEC 60870-5-104

定位：IEC 60870-5-101 的 TCP/IP 传输映射，国内调度与站端远动最常用的协议之一。默认 TCP 端口 2404。

报文结构：APCI（启动/停止/测试/确认）+ ASDU。ASDU 里最关键的四件事：

  • 类型标识：遥测、遥信、遥控、遥调、总召、对时等；
  • 传送原因：周期、突发、总召、命令确认、激活终止等；
  • 公共地址：站地址；
  • 信息对象地址（IOA）：点号，3 字节。

常用类型标识（只列最常见）：

类型含义
M_SP_NA_1 / M_SP_TB_1单点遥信 / 带时标单点遥信
M_DP_NA_1 / M_DP_TB_1双点遥信 / 带时标双点遥信
M_ME_NA_1 / M_ME_NB_1 / M_ME_NC_1归一化/标度化/浮点遥测
M_ME_TD_1 / M_ME_TE_1 / M_ME_TF_1带时标遥测

C_SE_NA_1 / C_SE_NB_1 / C_SE_NC_1归一化/标度化/浮点遥调

链路参数：标准给出 k/w 与 t0–t3 的缺省值（k=12、w=8、t0=30 s、t1=15 s、t2=10 s、t3=20 s），工程上按通道质量与设备能力调整，但必须两侧一致。k 是未确认 I 帧上限，w 是收到多少帧后必须确认；t1 是发送/测试超时，t2 是无数据时的确认超时，t3 是空闲测试周期。

工程要点：

  • 启动后先总召，再按组召/周期上送；总召期间的数据要防止重复入库；
  • 遥控优先用选择-执行，直接执行只用于明确允许的场景；
  • 命令要有超时、回执、激活终止与回读确认；
  • CP56Time2a 是本地时间且带夏令时标志位，跨时区/跨系统要统一换算；
  • 104 本身不提供加密与强身份认证，公网或跨区必须叠加 TLS/VPN/IEC 62351 或安全接入区；
  • 双通道运行时，前置要去重、判活、防止双通道同时下发。

3.3 IEC 61850

定位：变电站自动化与 DER 通信的对象模型标准，国内等同采用为 DL/T 860 系列。它不是"寄存器表"，而是"有语义的模型"。

三套通信映射：

  • MMS：客户端/服务器，用于监视、控制、报告、定值；
  • GOOSE：发布/订阅，快速报文，用于跳闸、联锁、状态互锁；
  • SV：采样值，用于电流/电压采样。

模型层次：IED/Server → Logical Device → Logical Node → Data Object → Data Attribute。工程上通过 SCL 文件（ICD/CID/SCD）交换模型，再绑定通信参数。

控制模型：直接控制、选择-执行（SBO）、增强型选择-执行等；控制对象有 Oper、SBOw、Cancel 等结构，必须按模型而不是按寄存器地址操作。

工程要点：

  • ICD/CID/SCD 版本必须与现场装置一致，改模型要重新联调；
  • GOOSE 依赖 VLAN 优先级与订阅关系，交换机配置错误会导致"信号发了但没人收"；
  • GOOSE/SV 的测试模式要显式标记，检修测试不能误动；
  • 61850 的时间戳通常是 UTC，显示层再转本地时区；
  • DER 场景可参考 IEC 61850-90-7 的对象模型，但别把"模型支持"当成"设备已实现"。

3.4 Modbus

定位：设备级寄存器通信，简单、便宜、生态广。RTU 走串口，TCP 常用 502 端口。

常用功能码：

功能码用途
01 / 02读线圈 / 读离散输入
03 / 04读保持寄存器 / 读输入寄存器
05 / 06写单线圈 / 写单寄存器
15 / 16写多线圈 / 写多寄存器

局限：

  • 没有标准时标、质量码、事件顺序；
  • 没有内建身份认证与加密；
  • 寄存器语义靠厂商手册，字节序/字序可能不同；
  • 轮询模式，点数多时延线性上升；
  • 写寄存器没有"选择-执行"语义，安全联锁要在网关/控制器做。

结论：Modbus 适合"设备 → 网关"的最后一段，不适合"站 → 调度"的广域链路，更不应把 502 端口暴露到公网。

3.5 MQTT

定位：发布/订阅消息协议，适合云边遥测、聚合商平台、海量分布式资源接入。常用 1883（明文）/8883（TLS）。

关键机制：

  • Broker：消息中转，主题（topic）分层；
  • QoS 0/1/2：最多一次/至少一次/恰好一次（ broker 与客户端之间，不是端到端业务确认）；
  • Retained：保留最后一条消息，适合状态量；
  • LWT：遗嘱消息，客户端掉线时由 broker 发布；
  • Session：持久会话与离线消息。

工程要点：

  • QoS 2 不等于"控制可靠"：端到端要有指令 ID、应用层 ACK、幂等与回读；
  • 主题设计要能按站/设备/点分层，ACL 要限制到最小范围；
  • 载荷要带 schema 版本、时标、质量码、设备 ID；
  • 离线队列要有上限与过期策略，避免恢复后"补发一堆过期指令"；
  • Broker 要做认证、TLS、审计与限流；匿名 Broker 等于公开的控制面板。

3.6 OPC UA、DL/T 476 与 CIM

  • OPC UA（IEC 62541）：带信息模型、订阅、证书与加密的工业互联协议，适合工厂、楼宇、园区设备集成；比 Modbus 重，但语义和安全更完整。
  • DL/T 476：国内电力系统实时数据通信应用层协议，主要用于调度主站之间；具体版本与互操作细则以现行标准和两侧系统为准。
  • CIM（IEC 61970/61968）：电网模型交换标准，用于模型拼接、图模维护，不是实时遥测协议。
  • IEC 62351：电力系统通信安全系列标准，给 104、61850 等协议提供 TLS、端到端安全与证书体系；"加个密码"不等于满足 62351。

3.7 协议网关的五个坑

  1. 点表漂移：网关配置改了，SCADA 点表没改，数据错位；
  2. 时标翻译：源协议无时标，网关用"收到时间"代替"事件时间"；
  3. 质量丢失：源协议有质量位，网关映射时丢掉；
  4. 控制语义错位：源协议是"写寄存器"，目标协议是"选择-执行"，直接映射会绕过互锁；
  5. 网关单点：所有协议、所有站共用一个网关，网关一挂全盲。

4. 采集频率、时延与时间同步

4.1 采样、上报与存储

三个周期要分开：

  • 采样周期：设备内部采样，毫秒到秒；
  • 上报周期：通信上送，秒到分钟；
  • 存储周期：历史库落盘，秒到分钟，或按死区压缩。

"采集频率 1 s"不等于"历史库 1 s 一个点"，也不等于"EMS 1 s 更新一次"。合同里必须写清是哪一个周期。

4.2 时延预算

下表是工程示例（D 级），用于说明分解方法，不是标准限值：

环节示例目标说明
设备采样到出口≤ 200 ms采样、滤波、打包
网关处理≤ 200 ms协议转换、点表映射
通信传输≤ 200 ms专网/专线；公网另计
前置处理≤ 100 ms解帧、去重、入库
实时库到应用≤ 1 s计算点、告警、推送
控制下发到回读≤ 5 s含鉴权、互锁、执行、回读

端到端时延要按测量点定义：从设备采样时刻到实时库可读，还是从指令发出到收到执行回执。两者不能混为一个"系统时延"。

4.3 时延指标怎么写进合同

  • 写 P50 / P95 / P99，不写"平均时延"；
  • 写测量点、测量方法、负载条件、统计窗口；
  • 写超时判定与补数/重传规则；
  • 写控制链路的回执时限与失败处理；
  • 写验收时的最大并发点数和背景流量。

只写"平均小于 1 秒"的合同，在告警风暴或大批量总召时会失效。

4.4 时钟同步

方式典型精度适用注意
北斗/GPS + 1PPS微秒级站端主时钟、SOE天线、馈线、防雷、守时
PTP (IEEE 1588)亚微秒到微秒61850、采样值、站控交换机需支持透明时钟
IRIG-B微秒级电力系统传统对时编码/解码、通道延时
NTP毫秒级服务器、通用设备无 GPS 时漂移大，难保 1 ms SOE
手动对时不可控仅调试不能用于生产

四条纪律：

  1. 存储统一 UTC，显示转本地；跨时区系统不要存本地时间；
  2. CP56Time2a 是本地时间，61850 时间戳通常是 UTC，转换要显式；
  3. 时钟跳变要检测：发现大步长回跳，标记数据质量并记录，不用错误时标回填；
  4. 对时质量要入点表：主时钟失锁、偏差超限、天线故障都要告警。

4.5 数据质量指标

完整率 = 有效采样点数 / 应采样点数 × 100%
正确率 = 与参考源一致的点数 / 抽检点数 × 100%
及时率 = 在时限内到达的点数 / 应到达点数 × 100%
可用率 = MTBF / (MTBF + MTTR) × 100%
可用率年停机时间（约）
99.9%8.76 小时
99.99%52.6 分钟
99.999%5.26 分钟

"数据可用率 99.9%"听起来很高，但一年仍有近 9 小时；对按 15 分钟结算的考核，足以丢掉几十个时段。指标要和业务后果一起看。

4.6 常见时标错误

  • 用服务器收到时间代替设备事件时间，SOE 顺序失真；
  • 服务器本地时间与设备时间不一致，跨时区/夏令时错一小时；
  • NTP 只对服务器不对设备，设备时标漂移；
  • 时钟回跳后继续写入，历史曲线出现"负时间"；
  • 总召数据不带原时标，全部盖成入库时间；
  • 测试环境与生产环境共用时钟源，测试数据污染生产。

5. 实时库、历史库与数据治理

5.1 实时库

实时库保存"当前值 + 时标 + 质量码 + 人工置数标志 + 闭锁标志"。它服务的是秒级监视、告警、控制联锁和计算点，不是长期存储。

设计要点：

  • 按扫描类组织点表，避免所有点同一周期；
  • 计算点要有依赖关系与计算顺序，避免循环依赖；
  • 人工置数、强制、闭锁要显式标记并审计；
  • 实时库重启后能从历史库/设备快速恢复，不把"0"当初始值。

5.2 历史库

历史库保存时间序列，服务于报表、优化、考核、结算对账和审计。选型关注：

维度要问的问题
写入吞吐峰值多少点/秒，总召/补数时会不会丢
压缩方式死区、旋转门、差值压缩，是否可还原
保留期原始/分钟/小时/日报各留多久
查询性能单站一年曲线、跨站聚合的响应
补数能力断网恢复后能否按原时标补入
审计谁改了点表、谁置了数、谁导出了数据
容灾双机/副本/备份，RPO/RTO 是多少

5.3 压缩与死区

历史库常用死区/旋转门压缩。压缩会丢细节，因此：

  • 结算、考核、事故分析用的点，保留原始采样或可审计的压缩参数；
  • 趋势监视用的点，可以用较大死区；
  • 压缩参数变更要版本化，否则同一份报表前后不可比；
  • 不要拿压缩后的曲线反推电量，再拿去和关口表对账。

5.4 补数与断点续传

边缘网关/RTU 应具备本地缓存与断点续传：

缓存容量 ≈ 点数 × 每秒采样次数 × 单条字节数 × 断网时长

示例（D 级）：5,000 点、5 s 扫描、单条 32 B、断网 15 min：

5,000 × 0.2 × 32 × 900 ≈ 28.8 MB

补数规则要写清：

  • 补数数据的时标用原采样时标，不用补传时间；
  • 重复数据按"设备+点+时标"去重；
  • 迟到数据有水位线（watermark），超过窗口不再入实时库，只入历史；
  • 补数不能覆盖人工置数/检修标记，冲突要告警。

5.5 数据血缘

每个进入报表/结算/考核的数字，应能回答：

  1. 来自哪个点、哪台设备、哪个协议地址；
  2. 经过哪些计算点、公式版本是什么；
  3. 时标是设备时标还是入库时标；
  4. 有没有人工置数、补数、压缩；
  5. 谁在什么时候改过点表或参数。

没有数据血缘，出现争议时只能"信系统"，无法自证。

5.6 数据治理清单

  • [ ] 点表、计算点、报表公式均有版本与责任人；
  • [ ] 实时库与历史库的时标、质量码语义一致；
  • [ ] 压缩参数变更留痕，结算点保留原始数据；
  • [ ] 补数、去重、迟到数据处理规则已文档化；
  • [ ] 数据导出有审批与审计；
  • [ ] 历史库容量与保留期按业务后果测算，不按磁盘剩余空间拍脑袋。

6. 告警与运行监视

6.1 告警分级

级别示例响应目标（示例）通知方式
P1 紧急保护动作、火灾、母线失压、通信全断立即声光 + 短信/电话
P2 重要单体过压、PCS 故障、SOC 越限5–15 min声光 + 消息
P3 一般风扇故障、通信抖动、温差偏大1 h消息/工单
P4 提示维护提醒、证书到期、磁盘将满当日看板/日报

分级不是按"严重"两个字拍脑袋，而是按后果 × 概率 × 可探测性定，并与运维SLA、备件、值班安排对齐。

6.2 告警风暴与抑制

ISA 18.2 给了一个常用设计参考：一名操作员在 10 分钟内处理约 10 条告警。超过这个量级，告警就从"提醒"变成"噪声"。

常用抑制手段：

  • 抖动抑制：短时反复动作合并为一条；
  • 因果抑制：上级故障时抑制下属派生告警；
  • 首出（first-out）：保留第一个原因，后续标为衍生；
  • 检修模式：设备检修期间屏蔽已知告警，但要有到期时间；
  • 搁置（shelving）：人工临时搁置，必须记录原因与到期时间；
  • 分层聚合：站级/设备级/点级分级展示，默认只看站级。

6.3 告警生命周期

检测 → 播报 → 确认 → 派单 → 处理 → 恢复 → 关闭 → 复盘

每一环要有时间戳、责任人、处理记录。只"报"不"闭环"的告警系统，最后一定被静音。

6.4 事件与告警的区别

  • 事件（Event/SOE）：发生了什么，按时间顺序记录，不一定需要人处理；
  • 告警（Alarm）：需要人关注或处理的事件，有级别、确认、闭环。

把 SOE 全部当告警，会淹没操作员；把告警只当事件记录，会漏掉处理。

6.5 HMI 降噪

  • 默认首页只放"当前最需要处理的 5 件事"，不是所有点的瀑布流；
  • 按站/设备/告警级别分组，支持一键钻取；
  • 曲线默认叠加参考线（额定、阈值、计划值），不要只画一条裸线；
  • 移动端只保留告警、关键曲线和确认操作，不做全量组态；
  • 深色/浅色主题下都要保证告警颜色可辨，不能只靠红绿区分。

7. 冗余与可靠性

7.1 冗余层级

层级冗余方式切换目标（示例）常见缺口
设备双机、双电源、双网口秒级共用一个电源/交换机
网络双交换机、双上行、环网秒级双网走同一管沟
前置 FEP主备/双活秒级共享同一采集端口
服务器主备/集群分钟级共享存储单点
历史库副本/备份分钟级备份未演练
时钟双主钟、北斗+GPS微秒级双钟同源
广域通道双通道、不同运营商秒到分钟双通道同路径

7.2 主备、双活与仲裁

  • 主备：备机平时不写，切换时接管；逻辑简单，但备机可能"冷"；
  • 双活：两台都工作，需要仲裁/一致性协议；搞不好会脑裂；
  • 仲裁：双活必须有第三方仲裁或共享锁，否则网络分区时两边都以为自己是主。

没有仲裁的双活，比单机更危险。

7.3 冗余不等于可靠

冗余只能对付独立故障，对付不了共因故障：

  • 双机接同一台交换机；
  • 双通道走同一根光缆；
  • 双时钟共用同一根天线；
  • 双系统跑同一版本、同一配置错误；
  • 双人复核用同一个账号；
  • 备份盘和主机放在同一个机柜。

做冗余设计时，先列共因，再谈切换。

7.4 切换演练

至少覆盖：

  • 杀掉主 FEP 进程/主服务器；
  • 断开主用网络，观察切换与恢复；
  • 拔掉主时钟天线，观察守时与告警；
  • 填满历史库磁盘，观察写入降级与告警；
  • 停掉 MQTT Broker，观察边缘缓存与补数；
  • 模拟数据库主备切换，核对数据不丢不重；
  • 双通道同时中断 15 min，核对补数与对账。

演练要有记录、有结论、有整改项，不能只看"切换成功"一个灯。

7.5 可用性指标

可用率、MTBF、MTTR 的定义要与业务对齐：

  • 计划检修算不算停机；
  • 单点失效但未影响业务算不算；
  • 数据丢失但系统仍在线算不算；
  • 切换时间从"故障发生"还是"发现故障"开始算。

指标口径不写清，99.99% 可以有很多种解释。

8. 电力监控安全防护与等保

8.1 现行规章

《电力监控系统安全防护规定》（国家发展改革委2024年第27号令），2024年11月25日公布，2025年1月1日施行，同时废止2014年第14号令。这是当前电力监控安全防护的顶层规章，不是"草案"，也不是"即将施行"。

要点：

  • 适用范围：电力监控系统运营者，以及相关的规划设计、研究开发、产品制造、施工建设、安装调试单位；
  • 系统范围：明确包括新能源发电监控、分布式电源监控、储能电站监控、虚拟电厂监控、配电自动化、电力现货市场交易等功能的系统，以及支撑它们的通信设施、数据网络与网管系统；
  • 结构原则：坚持"安全分区、网络专用、横向隔离、纵向认证"；
  • 分区：生产控制区（安全 I / II）、管理信息区（安全 III / IV），并设置安全接入区；
  • 边界：禁止任何穿越生产控制区与管理信息区、安全接入区之间边界的通用网络服务；
  • 全生命周期：投运前安全加固，运行中漏洞整改，供应链不得选用存在已知缺陷且未补救的产品和服务；
  • 监测：建设基于内置探针等的网络安全监测手段，与调度数据网相连的系统要将告警同步送至相应调度机构。

8.2 分区与边界

区域典型系统允许不允许
生产控制区 I/IISCADA、AGC/AVC、保护、站控实时监控、控制、保护公网服务、办公、邮件、通用远程桌面
安全接入区外部资源接入网关、代理、认证代理转发、端到端认证、受控数据交换直接控制、通用网络服务、绕过隔离
管理信息区 III/IVVPP 云平台、交易、结算、看板预测、优化、申报、分析实时控制、保护定值、直接写生产库

安全接入区不是"隔离区"的替代品。它解决的是外部资源（分布式光伏、储能、充电桩、第三方聚合商）如何受控接入，不是让公网流量直接进生产控制区。

8.3 VPP 云边安全架构

场景部署位置允许的数据流控制路径注意
VPP 只做监测/预测/交易管理信息区生产数据经隔离上行；交易数据经 API不控制设备不能回写生产实时库
VPP 需要下发功率指令生产控制区或安全接入区计划/指令经受控通道指令网关 → 站控 → 设备需鉴权、限幅、互锁、回执
第三方聚合商接入安全接入区代理转发、端到端认证仅限授权资源与指令类型最小权限、审计、可熔断
户用光伏/储能安全接入区/边缘遥测、状态、计量受控的启停/功率限制不能直连公网 Broker 控制
充电桩 V2G安全接入区/边缘状态、功率、计量受控的充放电指令车端/桩端双重校验

一句话：公网可以"看"，生产控制必须"过边界"。任何"手机 App 直接控制储能"的方案，都要先回答它走的是哪条安全链路。

8.4 等保与关基

  • 网络安全等级保护 2.0：GB/T 22239-2019 等系列标准，电力监控系统同样要落实等级保护制度；
  • 关键信息基础设施安全保护：《关键信息基础设施安全保护条例》（国务院令第745号）与相关要求；
  • GB/T 36572-2018《电力监控系统网络安全防护导则》：现行国家标准，给出技术防护框架；
  • 国能安全〔2015〕36号《电力监控系统安全防护总体方案》等：现行技术支撑文件；后续版本状态以国家能源局正式发布为准，不能把"正在修订"写成"已发布"；
  • IEC 62351 系列：电力系统通信安全标准，用于 104/61850 等协议的加密与身份认证。

等保测评不是"买设备"，而是"制度 + 技术 + 运维 + 审计"一起过。只做管理信息区、不做生产控制区的测评，等于没做。

8.5 常见违规

  • Modbus 502、104 端口直接暴露公网；
  • MQTT Broker 匿名可写，主题用 # 通配；
  • SCADA 服务器开远程桌面，运维从办公网直连；
  • 生产控制区与管理信息区共用一台交换机/VLAN；
  • 测试系统、厂商远程维护通道直接接入生产；
  • 默认口令、共享账号、长期不换证书；
  • 只做边界防火墙，不做纵向认证与入侵监测；
  • 日志只留 7 天，出事查不到；
  • 备份文件放在同一台主机；
  • 把"安全接入区"当成"公网直连缓冲区"。

8.6 上线前安全清单

  • [ ] 系统定级、备案、测评范围覆盖生产控制区与安全接入区；
  • [ ] 分区边界、隔离装置、纵向加密均已部署并策略核对；
  • [ ] 无通用网络服务穿越边界（RDP、SMB、HTTP 代理等）；
  • [ ] 安全接入区完成代理转发、端到端认证、最小权限；
  • [ ] 默认口令、共享账号、测试账号已清理；
  • [ ] 证书、密钥、VPN/APN 配置有归属人与到期提醒；
  • [ ] 网络安全监测探针/日志接入，告警能送到调度机构；
  • [ ] 供应链安全要求写入合同（漏洞响应、补丁、后门声明）；

9.3 SCADA 不是结算表

维度SCADA 遥测结算计量
目的监视、控制、优化贸易结算、考核
精度满足监视/控制按计量装置准确度等级
时标设备/网关时标计量装置时标
校验一般不做贸易校验检定、封印、比对
数据完整性允许补数/压缩需可审计、可追溯
用途不能直接作为结算依据结算依据

结论：SCADA 的电度/功率数据可以用来做运行分析、偏差预警和对账参考，但不能替代关口表。结算必须用专用计量装置与计量主站数据；两者出现差异时，按计量口径为准，并查明 CT/PT、时标、线损、未注册负荷等原因。

9.4 对账

  1. 对齐时标：统一 UTC/本地时区，确认计量周期（15 min/1 h）；
  2. 对齐单位与变比：kW/kWh、一次/二次值、CT/PT；
  3. 对齐边界：关口表位置、并网点、内部负荷；
  4. 对齐口径：是否含线损、厂用电、辅助服务；
  5. 设差异阈值：按电量比例/绝对量设告警；
  6. 留差异说明：通信中断、补数、人工置数、计量故障都要有记录。
